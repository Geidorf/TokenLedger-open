## 一、现状与根因

目标区域是 `draw_lockscreen_summary_card` 末尾的节奏图（`wallpaper.rs:2350-2388`），它是**当前锁屏唯一实际渲染的图表**——入口 `draw_lockscreen_wallpaper_image_with_stats:3296-3322` 只调用了这一张卡片。

### 1.1 为什么"像折线不像曲线"——三个叠加原因

**原因一：垂直量程只有 22 个逻辑像素。**

```
card_height = px(350.0)              // :3313
y2          = y1 + card_height
绘图带      = y1 + px(304.0)  ..  y2 - px(24.0)  =  y1 + px(326.0)   // :2368,2370
```

可用高度 **22 × sf**，宽度约 **330 × sf**（`x1+pad` 到 `x2-pad`，card_width 390 减去两侧 pad 30）。宽高比约 15:1。在这样一条窄带里，任何曲率都被压扁成近似水平线，肉眼看到的只有折点。**这是最主要的原因，只改插值算法不改版面不会有可见改善。**

**原因二：只有 12 个采样点，且点与点之间是直线段。**

```rust
let compact_values = smooth_series(&bucket_hourly_values(&stats.hourly_trend, 2), 1);  // :2359
let spark_points = series_points(...);                                                  // :2365
for segment in spark_points.windows(2) { draw_line(...) }                               // :2374-2387
```

`bucket_hourly_values(_, 2)` 把 24 小时合并成 12 个两小时桶（`:845-857`），`series_points`（`:859-881`）**不做任何插值**，只是把 12 个点算成屏幕坐标。于是 330px 宽度被 11 条直线段瓜分，每段约 30px。这就是字面意义上的折线图。

对比：同文件里 `draw_lockscreen_main_trend`（`:2393`，当前是 `#[allow(dead_code)]`）用的是 `smooth_curve_points`（`:896-939`），每小时 12 个子采样、Catmull-Rom 插值，输出约 288 个点——那份实现是对的，只是从来没被启用。

**原因三：预平滑掩盖了峰值但没有增加曲率。**

`smooth_series(_, 1)` 是一次 `[0.25, 0.5, 0.25]` 卷积（`:833-843`），它把真实小时值改写了（一个 09:00 的尖峰会被抹平并渗到 08:00 和 10:00），但因为随后仍是直线连接，视觉上并没有变圆滑——**付出了数据保真度的代价，却没换来平滑度**。对一个账本产品来说这是不划算的交易。

### 1.2 为什么没有昨日曲线

数据其实早就有。`WallStats` 同时持有两条 24 元素序列（`:594-595`）：

```rust
pub hourly_trend: Vec<i64>,
pub yesterday_hourly_trend: Vec<i64>,
```

`fetch_stats` 分别用两条 SQL 填充（`:651-679`）。`draw_lockscreen_main_trend:2523-2539` 已经在用 `yesterday_hourly_trend` 画绿色点线参考。**锁屏卡片的节奏图只是没去读它**——不是数据缺失，是一处遗漏。

### 1.3 其余同区域缺陷

- **今日曲线没有当前时刻截断。** `hourly_trend` 里未来小时是 0，所以曲线从当前时刻起一路掉到底再平着走到 24:00，看起来像"今天用量归零了"。`smooth_curve_points` 的 `cutoff_hours` 参数就是为解决这个问题设计的，锁屏卡片没用上。
- **纵轴用裸最大值而非规整刻度。** `:2360-2364` 用 `compact_values.max()`，加入昨日后两条线必须共享同一个 `nice_axis_max`，否则对比无意义。
- **没有任何 x 轴参照。** 没有时刻刻度，用户无法判断峰在几点。
- **空数据未处理。** 今日与昨日全为 0 时会画出两条贴底的平线，暗示"有数据且都是 0"，而实际是"没有数据"。

## 二、方案

### 2.1 视觉语言（已确认）

- **昨日**：半透明填充面积 + 细虚线上边界。作为背景参照层，先绘制。
- **今日**：实线曲线在上层，末端画当前时刻点。
- 两条线共享同一纵轴刻度，构成"今天相对昨天同一时刻高还是低"的直读对比。

选择填充面积而非点线的理由：锁屏图幅小、观看距离远，面积的整体轮廓在余光扫视下比离散点更容易识别；同时面积在下层不会与今日实线争夺注意力。这也与 Android D2「节奏」摆件档统一（见 `android-ambient-modes-v1.md` §D2），两个平台的同一张图应该长得一样。

### 2.2 版面调整（前置且必要）

| 项 | 现状 | 调整后 | 说明 |
|---|---|---|---|
| `card_height`（`:3313`） | `px(350.0)` | `px(436.0)` | 唯一需要改的卡片外形参数 |
| 小节标题 y | `y1 + px(286.0)` | 不变 | 同一行右侧新增图例 |
| 绘图带 | `y1+304 .. y1+326`（22） | `y1+312 .. y1+404`（**92**） | 高度 ×4.2，宽高比从 15:1 降到 3.6:1 |
| x 轴刻度文字 | 无 | `y1+408 .. y1+422` | `00 / 06 / 12 / 18 / 24` |
| 卡片下内边距 | 24 | 14 | 收紧以补偿增高 |

垂直空间校验（`:3311-3317`，`y1 = max((height - card_height) / 2, px(96))`）：

- 1920×1080，`sf = 1.0`：`card_height = 436`，`y1 = 322`，`y2 = 758 < 1080` ✓
- 3840×2160，`sf = 2.0`：`card_height = 872`，`y1 = 644`，`y2 = 1516 < 2160` ✓
- 2560×1080 超宽，`sf = 1.0`（受 height 约束）：`y1 = 322` ✓
- 1366×768，`sf ≈ 0.711`：`card_height ≈ 310`，`y1 = 229`，`y2 = 539 < 768` ✓

卡片仍完全落在右侧安全区，不侵入 Windows 拥有的中上时钟区与左下登录区（`:3308-3310` 的既定约束）。

### 2.3 曲线插值：改用保形单调三次插值

**不要直接复用 `smooth_curve_points` 的均匀 Catmull-Rom。** 该实现（`:896-939`）在相邻值落差大时会过冲——`:932` 那句 `.max(0.0)` 就是过冲到负数的证据。对 token 小时序列（典型形态是长时间接近 0、几个小时陡峭尖峰）过冲意味着**曲线会在真实数据之外凭空造出峰和谷**。账本产品不能这样画。

改用 **Fritsch–Carlson 保形单调三次 Hermite 插值**：

```
给定 24 个小时样本 y[0..23]，等距 h = 1：
  1. 割线斜率      d[i] = y[i+1] - y[i]                    i = 0..22
  2. 初始切线      m[0] = d[0]；m[23] = d[22]
                   m[i] = (d[i-1] + d[i]) / 2               i = 1..22
  3. 保形修正      若 d[i] == 0，则 m[i] = m[i+1] = 0
                   否则令 a = m[i]/d[i]，b = m[i+1]/d[i]
                       若 a < 0 或 b < 0，置对应 m 为 0
                       若 a² + b² > 9，取 t = 3/√(a²+b²)，
                                       m[i] = t·a·d[i]，m[i+1] = t·b·d[i]
  4. 求值          在区间 [i, i+1] 上，s = x - i
                   H(s) = y[i]·h00(s) + m[i]·h10(s) + y[i+1]·h01(s) + m[i+1]·h11(s)
                   （标准三次 Hermite 基函数）
```

这套算法给出三条硬保证，每一条都可以写成断言：

1. **不过冲**：`min(y[i], y[i+1]) ≤ H(s) ≤ max(y[i], y[i+1])`，因此永远非负，`.max(0.0)` 兜底可以删掉。
2. **不造假峰谷**：数据在某段单调，曲线在该段就单调；数据平坦，曲线就平坦。
3. **过点**：`H(i) == y[i]`，每个整点的高度就是该小时的真实值。

有了保证 3，**预平滑 `smooth_series` 应当从锁屏节奏图中移除**。曲线的圆滑度由插值提供，数值保真度由过点性质提供，两者不再互相牺牲。

子采样密度：每小时 **16** 个子采样（现有 `smooth_curve_points` 是 12）。24 × 16 = 384 个点，在 2× 渲染下每点间距约 1.7px，配合下采样足够连续。

### 2.4 昨日面积填充：不要用 `draw_polygon`

现有 `draw_polygon`（`:282-330`）是逐像素射线法点在多边形内测试，复杂度 `O(bbox_w × bbox_h × n)`。以 384 个曲线点、2× 渲染下 660×184 的包围盒计算，约 **4400 万次** 内外判定，只为填一块面积。4K 下再翻四倍。锁屏壁纸在扫描后事件驱动重绘（T5.2a），这个开销不可接受。

改用**按列竖向 span 填充**。面积图是函数图像，每个 x 只有一个 y，不需要通用多边形算法：

```
对绘图带内每一列 x：
  由曲线点线性求出该列的 y_curve（曲线点已按 x 单调递增，可顺序游标推进）
  从 ceil(y_curve) 到 baseline 逐像素 blend 填充色
```

复杂度 `O(w × h_col)`，即恰好等于被填充的像素数，无冗余。同时天然不会溢出绘图带。

### 2.5 绘制顺序与样式

```
1. 网格            3 条水平虚线（0 / 50% / 100% 刻度），复用 draw_dashed_line
                   4 条竖向刻度线（06 / 12 / 18），alpha ≈ 36
2. 昨日面积        span 填充，Rgba([ACCENT_NEUTRAL.., 30])（compact；full 用 27，T10.195 从 42 / 38 下调）
3. 昨日轮廓        沿曲线上边界的细虚线，Rgba([ACCENT_AXIS.., 170])，宽 1.0×sf，
                   虚线节奏复用 draw_dashed_line 的 5/7 参数（T10.195：AXIS_ACCENT_ALPHA，不与面积共用中性色的 143）
4. 今日辉光        沿曲线连段，Rgba([ACCENT_PRIMARY.., 60])，宽 3.5×sf
5. 今日主线        ACCENT_PRIMARY，宽 1.8×sf
6. 当前时刻点      外圈 r=5×sf alpha 60，内圈 r=3.5×sf 实心
7. x 轴刻度文字    "00" "06" "12" "18" "24"，11×sf，Rgba([174,196,224,150])
8. 图例            与小节标题同一行右对齐：
                   ── 今天    ┈┈ 昨天
                   实线段 + 虚线段各 22×sf 宽，文字 10.5×sf
```

昨日画满 0..24（它是完整的一天）；今日截断在 `cutoff = now.hour() + now.minute()/60.0`，与 `draw_lockscreen_main_trend:2519-2520` 的既有做法一致。

### 2.6 纵轴刻度

```rust
let axis_max = nice_axis_max(&[today[..], yesterday[..]].concat());
```

两条曲线必须共享该值。刻度线画在 0 / 50% / 100% 三档，只在 100% 档左侧标一次数值（`format_axis_token`），避免小卡片里堆文字。

### 2.7 空数据与边界

| 情况 | 处理 |
|---|---|
| 今日与昨日 24 小时全为 0 | 不画任何曲线；绘图带居中显示"今日暂无记录"，保留网格 |
| 仅昨日有数据 | 画昨日面积；今日只在 x=cutoff 处画当前点，图例中"今天"置灰 |
| 仅今日有数据（首日使用） | 不画昨日层；图例省略"昨天"，不显示空的虚线 |
| `cutoff < 1.0`（00:00–00:59） | 曲线退化为单点，仍画当前时刻点（`smooth_curve_points` 现有行为已正确） |
| 跨午夜期间重绘 | 沿用 T5.2b 的时区结论：`fetch_stats` 的小时桶与 `Local::now()` 必须处于同一时区语义，本次不改动该逻辑，但必须有回归用例覆盖 23:59→00:01 的过渡 |

## 三、实施建议

### 3.1 复用而非重写

`draw_lockscreen_main_trend`（`:2393-2590`）已经包含了本方案 70% 的逻辑：昨日参考层、截断的今日曲线、共享 `nice_axis_max`、辉光双描边、当前时刻点、坐标网格。它今天是死代码（审计 §D1）。

正确做法是把它重构为一个可复用的私有函数，而不是在 `draw_lockscreen_summary_card` 里再写一份：

```rust
struct RhythmChartStyle {
    show_axis_labels: bool,
    show_legend: bool,
    yesterday_fill: bool,      // true = 面积填充；false = 点线（保留主趋势图旧观感）
    line_width: f32,
    label_font: f32,
}

fn draw_hourly_rhythm_chart(
    img: &mut RgbaImage, font: &FontRef,
    x1: i32, y1: i32, x2: i32, y2: i32,
    today: &[i64], yesterday: &[i64],
    cutoff_hours: f32, style: &RhythmChartStyle, sf: f32,
)
```

`draw_lockscreen_summary_card` 用紧凑 style 调它；`draw_lockscreen_main_trend` 改为用完整 style 调它并保留 `#[allow(dead_code)]`（或在 TASKS 里登记删除条件）。这样两处不会再漂移。
