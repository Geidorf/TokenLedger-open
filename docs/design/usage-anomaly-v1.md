# 用量异常检测（v1）

状态：实施中（2026-10-24 起）。适用平台：桌面端（概览 › 消费洞察 › 用量异常、系统通知）。来源：用户要求识别 Token 或费用突增、缓存命中率骤降、某 Agent 或模型异常放量、单个会话异常昂贵、网关错误率突增，在消费洞察里展示，可选系统通知。

## 不做的事

- **不外推**：只看已经发生的用量，不预测「今天会超」「额度会用完」。进行中的小时或当天按已用量判断，已用量只会变大，所以判定不会被将来推翻。
- **不进云端**：只读本机账本；设置与提醒去重状态只存在本机应用数据目录（`usage_anomaly_settings.json`、`usage_anomaly_alert_state.json`），不改同步格式，也不改 `StatsData`。云端范围不显示这张卡片。
- **不重复预算与额度提醒**：超出预算由「预算提醒」负责，额度窗口剩余由「额度提醒」负责；这里只看用量相对平时是否异常。
- **不做学习模型**：规则只用中位数、倍数、百分点和下限，界面原样写出口径。

## 数据

- 用量：与本机概览同一份合并账本（网关记录优先于扫描到的同一请求，含所有设备），读最近 21 个本地日历日（最近 7 天 + 此前 14 天）。有效 Token = 输入 + 输出，缓存不并入；费用为看板同一逐行预估，含未核价记录的时段费用记为不可得，不当 0。
- 会话：只算有真实会话 ID 的记录，按（Agent，会话 ID）聚合。
- 网关错误：本机网关的诊断记录（每次上游尝试一行，成功或失败；失败的尝试通常没有 Token，不进计费账本）。诊断记录按 16 MB 轮转、保留一份旧文件，历史不足时只用绝对门槛。没有网关时该项显示「本机没有这类数据」。

## 规则

| 规则 | 最近的桶 | 基线 | 触发 |
| --- | --- | --- | --- |
| Token 突增（小时） | 最近 24 小时每小时 | 此前 14 天的活跃小时（至少 12 个） | ≥ 中位数 4 倍，且 ≥ 50 万 |
| Token 突增（天） | 最近 7 天每天 | 此前 14 天的活跃日（至少 5 天） | ≥ 中位数 2.5 倍，且 ≥ 200 万 |
| 费用突增 | 同上，按预估费用 | 同上，只取费用可得的桶 | 小时 ≥ $2、天 ≥ $5 |
| 缓存命中率骤降 | 最近 7 天每天（提示词 ≥ 100 万） | 此前 14 天的日命中率（当天提示词 ≥ 10 万，至少 5 天） | 比中位数低 20 个百分点以上 |
| Agent / 模型放量 | 每个 Agent、模型最近 7 天每天 | 它自己此前 14 天的活跃日（至少 3 天） | ≥ 中位数 3 倍，且 ≥ 200 万 |
| 会话异常昂贵 | 最近 7 天活跃的会话 | 21 天内全部会话（至少 8 个） | 费用 ≥ 中位数 5 倍且 ≥ $3；费用不可得时按有效 Token，≥ 5 倍且 ≥ 300 万 |
| 网关错误率突增 | 最近 24 小时每小时（≥ 20 次尝试） | 此前 7 天的总失败率（≥ 50 次才算数，否则按 0） | 失败率 ≥ 20%，且比基线高 15 个百分点以上 |

命中率 = 缓存读 ÷（输入 + 缓存读），与请求明细的命中率同一口径。当天有任何记录分不清缓存读写（来源只给了合计）时，这一天不算命中率，也不进基线；它的 Token 与费用照常计入其他规则。基线不够时该规则显示「历史不足，暂不评估」，不报异常。每条发现带稳定 ID（规则 + 桶 + 对象），最多 24 条；Agent、模型放量各最多 6 条，会话最多 3 条；按最近一次用量的日期从新到旧，再按偏离程度排序。

## 界面

- 位置：概览「消费洞察」分组的第一张卡片，只在本机范围出现。标题旁的说明列出全部规则。
- 每张卡片写：规则名（放量写对象名）、时间（今天 15:00 / 昨天 / 10-21，进行中的标注）、数值、与平时的比较（倍数或百分点）。小时、天和 Agent / 模型放量可点开当天明细，放量带上该 Agent 或模型筛选；会话与网关错误不可点。
- 没有发现时写明比较窗口；有规则没跑时在卡片底部列出原因。
- 刷新：本机统计更新、窗口重新可见、可见时每 5 分钟。

## 提醒

- 开关在卡片标题右侧「异常时系统通知」，默认关闭；与额度、预算提醒走同一个系统通知通道。开启时把当时已在卡片上的发现记为已发，不补发一串旧通知。
- 只提醒新近的发现：小时与会话是最近 3 小时内的用量，天是今天。每条发现只提醒一次（记录保留 8 天、最多 256 条），全局每小时最多 3 条，被限流的下次检查再送。
- 检查时机：每次刷新托盘提示时（扫描写入新记录、手动刷新、跨日），开启时后台每 5 分钟也检查一次；两次计算至少间隔 5 分钟。
- 通知只写规则、时间与倍数或百分比，例如「今天 15:00 的有效 Token 是平时的 8.0 倍」，不写金额、路径或会话 ID；含 `/ \ @ : $` 等字符或过长的模型名退回「某个模型」。

## 命令

`get_usage_anomalies`（发现列表与各规则的评估状态）、`get_usage_anomaly_settings`、`set_usage_anomaly_settings`。只授予主窗口。
