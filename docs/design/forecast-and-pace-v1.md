## 0. 一页结论

| | 周期末预测 | 额度消耗速度（pace） |
|---|---|---|
| 回答 | 照目前的日均，本月 / 本周 / 自定义区间结束时大约用多少、花多少 | 照目前的速度，这个额度窗口重置前会不会用完、何时用完 |
| 数据 | Stats v2 `comparison.current.series` 日桶；云端费用只信 `dailyCosts` | Quota v1 百分比窗口的 `used`、`windowMinutes`、`resetsAt`、`observedAt`、新鲜度 |
| 方法 | 已完成日的算术平均 × 剩余天数，加已完成合计；粗略范围按日波动、相邻两天的相关程度与最近 7 天日均放宽，未经校准，不标百分比 | 窗口开始至观测时刻的平均速度外推到重置；放慢一半 / 加快一半的敏感度区间 |
| 进行中的部分 | 今天不参与速率，只作“今天最终值不低于已记录量”的下限 | 观测区间 [窗口起点, observedAt] 已完整发生；刚重置时不外推 |
| 不给数字的情况 | 完整日 <7（周 <3）、活跃日 <2、剩余天数超过计算日均所用天数的 4 倍、未知费用、时区或序列对不上、月末同期截短的日子 | 非百分比、缺 windowMinutes 或 resetsAt、reset 精度粗于窗口 5%、来源能力为 experimental、时间线矛盾、历史数据、刚重置 |
| 出现在 | 趋势卡（本月 / 本周 / 多日自定义） | 额度面板每个百分比窗口下方 |
| 绝不出现在 | 同步、分享海报、HTML 简报、CSV、壁纸与锁屏、托盘 tooltip、Android 桌面小组件 | 同左 |

## 1. 范围与术语

- **完整日**：来源时区中已经结束的公历日。截止日（“今天”）只有在已结束的自定义区间里才算完整。
- **进行中的今天**：截止日当天，已记录量只是部分值。
- **典型日**：基线完整日的算术平均。基线是本期最近的至多 31 个完整日。
- **剩余天数 m**：进行中的今天加上今天之后到期末的天数。
- **窗口实例**：额度窗口 `providerId + scope + windowId` 加上当期 `resetsAt`。重置后是新实例。
- 有效 Token 固定为输入 + 输出；缓存读写不进入预测。界面“全部 Token”显示偏好不改变预测口径，预测行需写明“有效 Token”。

不在本版范围：预算与超支预测（D3 暂缓）、年度与“总计”范围的预测、今日的日内预测、突增或模型变化通知、订阅拆分与回本（D1，见 T10.154）。

## 2. 周期末预测

### 2.1 输入与时间边界（`forecastInputFromStats`）

只使用 Stats v2 已有字段，不新增契约字段：

1. 范围只支持 `month`、`week` 与多日 `custom`；`today`、`year`、`all` 返回 `unsupported`。单日自定义区间是小时桶，同样不支持。
2. “今天”取 `meta.generatedAt` 按 `meta.timezone` 换算的日期，**不取** `comparison.window.currentEnd`。原因：月末几天本机 Rust（`aligned_day = min(今天, 上月天数)`）与云端 SQL（`least(...)`）都把本期同期窗口截到上月的天数，`currentEnd` 与 `current.series` 停在对齐日。触发日为非闰年 3/29–3/31、5/31、7/31、10/31、12/31，闰年 3/30、3/31 与 5/31、7/31、10/31、12/31。`meta.timezone`、`meta.query.timezone`、`comparison.window.timezone` 任一冲突即整体不可用；缺少生成时刻时不猜，返回 `time-context-unavailable`。
3. 周期边界：本月 = 今天所在公历月；本周 = 今天所在的周一至周日（DESIGN §3）；自定义 = `meta.query.start/end`，截止日取末日与今天中较早的一个。
4. `comparison.current.series` 必须恰好是周期首日到截止日的稠密日桶（桶键 `YYYY-MM-DD`）。缺日、多日、乱序、首日不等于期首都判为 `series-misaligned`，不猜补 0。未升级到 T10.88 日期桶迁移的旧云端周 / 月序列（`D01` 形式的内部索引）因此自然失败。序列停在今天之前、且对比截止点正是最后一个桶（月末截短的形状）时返回 `unavailable/comparison-clipped`，界面不显示；绝不把截短的日子当成今天。根治需要后端不再截短本期序列，属契约变更（§10 第 6 条）。
5. 自定义区间以期末日为截止日时，今天晚于末日即区间已经结束，返回 `complete`，不再预测。
6. 本机作用域：日序列的 `cost` 是逐行记录值或按价格表的估算，直接使用。
7. 云端作用域：日序列的 `cost` 在 RPC 里是 `sum(coalesce(cost_usd, 0))`，会把未知费用合成 0，**不得使用**。费用只取 `dailyCosts`：`recorded-estimate` 取金额；`unavailable` 为未知；`dailyCosts` 只列有效 Token > 0 的活跃日，因此缺行的日子只有在当天 `requests = 0` 且 `tokens = 0`（没有任何记录）时才是真实的 $0，否则为未知。`dailyCosts` 缺失、`coverage.state = partial`、或覆盖与周期 / 截止日 / 时区不一致时，费用预测整体不可得。
8. 云端调用必须明确给出布尔值 `sourceIncomplete`（本机仍有待上传记录时为 true），类型上是必填项；绕过类型检查漏传时按不完整处理。来源不完整时整体不预测，避免把少算的已记录量外推成偏低的预测。本机作用域可以省略。

### 2.2 公式（`forecastPeriod`）

设基线完整日取值为 x₁…xₙ（n ≤ 31），本期全部完整日合计为 C，进行中今天的已记录量为 P（未知时不设下限，也不把未知当 0 记入已记录），剩余天数为 m。

```text
x̄      = 基线平均（典型日）
s      = 基线样本标准差（分母 n − 1）
s_eff  = max(s, 0.5 × x̄)                        日波动下限（经验值）
r      = 基线相邻两天的相关系数，按小样本偏差校正为 (n·r̂ + 1)/(n − 3)，截到 [0, 0.8]；n < 5 时为 0
f      = √((1 + r)/(1 − r))                      相关放宽倍数，最多 3
t      = Student t 的 0.9 分位，自由度 n − 1       宽度刻度（名义 80%，未校准）
x̄₇     = 最近 7 个完整日的平均（n > 7 时；否则取 x̄）
lo     = min(x̄, x̄₇)，hi = max(x̄, x̄₇)

第 k 天结束时（k = 1 为今天），三条线逐日累加：
  中心   = C + Σ 每天的 x̄      （今天取 max(P, x̄)）
  下中心 = C + Σ 每天的 lo     （今天取 max(P, lo)；基线里没有的日子类型记 0）
  上中心 = C + Σ 每天的 hi     （今天取 max(P, hi)）
  半宽   = t × s_eff × f × √(k + k² / n)
  下限   = max(C + P, 下中心 − 半宽)，并对 k 取运行最大值（累计量只增不减）
  上限   = 上中心 + 半宽

周期预测 = 第 m 天的中心；粗略范围 = 第 m 天的 [下限, 上限]。
```

- √(k + k²/n) 是“未来 k 天之和”的标准预测误差：k 来自未来每天自身的波动，k²/n 来自日均本身的估计误差。它假设各天互不相关、日均不变。
- 相关放宽：开发者用量常随项目阶段成片高低，相邻两天正相关时，和的方差约放大 (1 + r)/(1 − r) 倍。负相关不收窄范围。
- 近期包络：用量在期中变化时，按最近 7 天日均外推是第二种同样线性的说法；范围同时覆盖两者，点预测仍只用整体日均。
- 基线里没有的日子类型：本周预测在周四至周六时基线全是工作日，周末用量无从外推，下限按周末不用计算，上限仍按日均。月与自定义至少 7 个完整日，基线总含两类日子。
- 三条线逐日累加，保证浮点运算下也有 下限 ≤ 中心 ≤ 上限，且都不低于已记录量。
- Token 结果取整；金额保留原始精度，由文案层按量级取整显示。
- 结果另附累计轨迹（今天到期末每一天的中心、下限、上限），供累计图画预测线与色带；另附 `peakShare`、`peakInfluence`、`recentDaily`、`recentShift`、`autocorrelation`、`weekdayMixRisk`、`unseenDayType` 供附注。

示例（单测锁定）：9 月 1–14 日每天 100 Token、今天已记录 30。n = 14，s = 0 → s_eff = 50，r = 0，x̄₇ = x̄，t = 1.3502，m = 16；预测 = 1400 + 16 × 100 = 3000，范围 2605–3395。若今天已记录 250，今天按 250 计，预测变为 3150，典型日不变。

### 2.3 资格与诚实规则

| 规则 | 取值 | 结果 |
|---|---|---|
| 月末同期截短 | 序列停在今天之前，且对比截止点正是最后一个桶 | 整体 `unavailable/comparison-clipped`，界面不显示 |
| 最少完整日 | 月、自定义 7 天；周 3 天 | 否则整体 `insufficient`，文案说明还差几天、哪天起给出预测 |
| 最少活跃日（基线中 >0 的天数） | 2 天，按 Token 与费用分别判断 | 否则该口径 `insufficient` |
| 外推距离 | 剩余天数 ≤ 4 × 基线天数 | 否则整体 `insufficient`（长自定义区间早期） |
| 最早可预测日 `availableFrom` | 同时满足完整日与外推距离两道门槛的最早“今天” | ok 时为截止日；insufficient 时为之后的日期；周期内等不到为 null |
| 基线长度 | 最近至多 31 个完整日 | 长自定义区间不被早期习惯拖住 |
| 已完成日有未知值 | 任一天未知 | 该口径 `unavailable`，给出未知天数；Token 口径不受费用影响 |
| 今天费用未知 | — | 费用口径 `partial`：今天不设下限，文案注明 |
| 周期已结束 | 剩余 0 天 | `complete`，界面不显示 |
| 附注：单日高峰 | 去掉基线中最高的一天后日均下降 ≥ 25%（`peakInfluence`；3 天时约为峰值 ≥ 1.5 倍日均，31 天时 ≥ 8.5 倍） | 附注占比与影响；基线被截断时写明“最近 N 个完整日合计” |
| 附注：近期变化 | 基线 ≥ 14 天，最近 7 天日均 ≥ 1.5 倍或 ≤ 1/1.5 倍于再往前 7 天 | 附注方向与幅度；两段都恰好含每个星期几一次 |
| 附注：工作日与周末 | 周预测一律附注；月与自定义在基线与剩余天数的周末占比相差 ≥ 0.1，且两类日均相差 ≥ 1.5 倍、其中一类为 0 或基线缺一类时附注 | `weekdayMixRisk` |
| 基线里没有的日子类型 | 剩余天数里有、基线里没有（周四至周六时的周末） | `unseenDayType`；下限按这些天不用计算，详情写明 |

每个结果都带 `kind: 'forecast'` 品牌与 `method` 描述（`linear-mean`、`nominalLevel`、`calibrated: false`、波动下限、相关放宽上限、近期天数、最少活跃日、基线上限、外推倍数），界面与导出层可据此识别并拒绝。`calibrated: false` 表示界面不得把 `nominalLevel` 显示成百分比、“把握”或“置信”。

### 2.4 为什么是这个方法

- **用平均数而不是中位数**：要预测的是总量。日用量右偏（周末、尖峰），中位数 × 天数会系统性低估总量；平均数是总量的无偏估计。尖峰的影响不隐藏，而是通过范围变宽与单日高峰附注（`peakInfluence`）披露。
- **不用“单日分位带”**（例如 P25–P75 × 剩余天数）：单日分位描述的是一天，不是 m 天之和。9 天 $5、1 天 $50 时 P25 = P75 = $5，区间宽度为 0，而平均数外推的点预测反而落在区间之外；每天都相同时也会给出零宽度区间。
- **不用自助法（bootstrap）**：需要固定随机种子才能确定性；样本少时无法产生观测范围以外的值，区间系统性偏窄；也难以向用户解释。
- **t 分位 + 日波动下限**：样本少时样本标准差偏低且不稳，t 分位负责自由度，下限负责“几天恰好很像”的情况。0.5 是经验值，没有用真实账本标定；来由是工作日 $10、周末 $2 这种最规律的用法，仅周内起伏的变异系数就约 0.47。
- **月至少 7 个完整日**：任意连续 7 天恰好各含一次周一至周日，工作日与周末的比例才被样本覆盖。
- **周只要 3 天**：一周最多只有 6 个完整日；周四起给出预测，并固定附注“未区分工作日与周末”。首版界面可以只接本月，周预测保持可用但不强推。
- **不标百分比，只写“粗略范围”**：t × s × √(k + k²/n) 只有在各天互不相关、日均不变时才有名义 80% 的含义。开发者用量常见的重尾、成片高低与期中上升都违反这两个前提，任何单一百分比都会误导。因此 `method.calibrated = false`，文案只写“粗略范围”并写明前提，界面不得显示百分比、“置信”或“把握”。
- **不整体换成 95% 刻度**：0.95 分位在月初（第 8 天）的中位范围宽度已超过真实月总（重尾模型为 1.07–1.39 倍），成片用量仍只覆盖 74%、持续上升只覆盖 28%。宽度刻度保留 0.9 分位，成片与期中变化靠相关放宽与近期包络补偿，而不是整体加宽。

## 3. 额度消耗速度（pace）

### 3.1 资格（`computeQuotaPace`）

依次判断，前一条不满足即返回：

1. 窗口状态必须带值（`ok`/`stale`），数值通过 `validateQuotaWindowValues`，且为 `percent`；绝对余额、Credits、unlimited 返回 `unsupported/not-percent`。
2. 来源能力必须给出：`computeQuotaPace(window, now, { providerCapability })` 的第三个参数必填，取窗口所属 envelope 的 `capability`。只有 `stable` 与 `plan-dependent` 计算速度；`experimental`（Codex JSONL 兜底、Claude CodexBar 桥接与内置 CLI PTY、Antigravity）与未知能力返回 `unsupported/provider-experimental`。依据：Antigravity 的 `windowMinutes` 由桶名推断，Claude PTY 的 reset 由相对文本换算，窗口起点都可能不准。
3. 时间字段通过 `validateQuotaWindowTimeline`；必须有 `windowMinutes`（否则 `window-length-unknown`）与 `resetsAt`（否则 `reset-unknown`）。公司 OpenAPI 窗口没有 reset，自然不预测。
4. reset 精度默认不信任：来源声明 `resetPrecisionSeconds` 时用声明值；否则看 `resetsAt` 与 `observedAt`、`fetchedAt` 之差是否恰为 86,400、3,600 或 60 秒的整数倍，取最粗的一种作为精度（都不是时为 0）。精度超过窗口时长 5% 返回 `reset-imprecise`：每周窗口只写“Resets in 4 days”会被拦下，5 小时窗口只写“3h”也会被拦下；“2h 30m”精度为 60 秒，照常计算。精确来源恰好落在整小时上的概率约 1/3,600，误判的代价只是这一次不显示速度。结果带 `resetPrecisionSeconds`。
5. 新鲜度与额度面板同源（`readQuotaWindow`）：来源标 `stale`、`now ≥ observedAt + staleAfterSeconds`、或 `resetsAt ≤ now` 都返回 `stale`，不从历史快照外推。
6. 时间线一致：窗口起点 = `resetsAt − windowMinutes`；观测必须落在 [起点 − 容差, resetsAt) 内（容差为 5 分钟与窗口 1% 中的较大者），否则 `timeline-inconsistent`。
7. 已用 ≥ 100%：直接 `critical` 且 `exhausted`，不需要外推。
8. 最短已过时长：窗口 10%；多日窗口另需至少 24 小时（覆盖一次作息周期）。5 小时窗口即 30 分钟，每周窗口即 24 小时。不足时 `insufficient/too-early`；已过时长为 0 时绝不外推。

### 3.2 公式

```text
已过 e  = observedAt − 窗口起点            （只用观测时刻，已用比例对应的是它）
速度 r  = used / e
剩余 R  = resetsAt − observedAt
重置时用量（照此速度） D = used + r × R = used × 窗口时长 / e     （未封顶，展示封顶 100）
敏感度区间              = used + r × R × [0.5, 1.5]             （封顶 100）
用完时刻                = observedAt + (100 − used) / r          （D ≥ 100 时给出）
用完区间                = 加快一半 / 放慢一半两种速度下的用完时刻；放慢一半晚于重置时写“可撑到重置”（只在 critical 时给出）
```

区间不是概率区间：单次观测没有波动信息可估，因此只给透明的敏感度范围，并在文案中照实描述。区间只缩放剩余时间，随窗口推进自然收窄。

### 3.3 状态与 D4 对齐

D4 的两条线描述的是**当前剩余**（<20% 告急、<50% 偏紧），继续由 `quotaLevel` 驱动额度条颜色。速度描述的是**重置时的结果**，对齐方式是：

| 状态 | 条件 | 含义 |
|---|---|---|
| `critical` | D ≥ 100（含已用完） | 照此速度会在重置前用完 |
| `tight` | 100 − D < 20 | 照此速度重置前会跌进 D4 告急区 |
| `ok` | 其余 | 重置时仍剩 20% 以上 |
| `insufficient` | 刚重置 | 不预测 |
| `stale` | 契约意义上的历史数据 | 不预测 |
| `unsupported` | 不满足 §3.1 的 1–6 条 | 不预测 |

当前已在告急区（剩余 <20%）的窗口，D 必然 > 80，因此速度至少是 `tight`，不会出现“额度条红色、速度写够用”的矛盾。反过来不把“重置时剩余 <50%”判为偏紧：正常用满订阅的用户重置时本来就剩得不多，那样会长期误报。结果同时带 `currentLevel`，界面可同时呈现两者。

示例（共享 fixture `complete-v1.json`，now = 2026-07-15 08:30 +08:00）：Codex 每周窗口已过 96.5/168 小时、已用 64% → D ≈ 111%，照此速度约 54.3 小时后（北京时间周五 14:47）用完，早于周六 08:00 重置 → `critical`；此时剩余 36%，额度条按 D4 为偏紧色。Codex 5 小时窗口已过 70%、已用 38% → D ≈ 54% → `ok`。

### 3.4 已知局限：reset 精度

契约没有 reset 精度字段。Claude 内置 PTY 从“Resets in 4 days”一类相对文本换算 `resetsAt`，精度可能只有一天；每周窗口的已过比例因此可能偏差多达约 14 个百分点：窗口过半时速度会被乘以约 0.78–1.40，窗口越早偏差越大。复核按解析器的输出形状复现过：真实已过 49 小时、已用 30% 或 40% 的每周窗口会被算成 ok 或 tight，而真实应为 critical。处理：

- 逻辑层默认按时间戳推断精度（§3.1 第 4 条），不再缺省当作精确；来源声明的 `resetPrecisionSeconds` 优先。Claude 内置 PTY 的 envelope 能力本就是 `experimental`，第 2 条也会拦下；推断是第二道保护，也覆盖将来可能出现的其它相对时间来源。
- 建议契约只增不改地加入可选字段 `resetsAtPrecisionSeconds`（精确来源省略；相对“N 天”为 86400，“Xh Ym”为 60），由 Rust 生产者填写、TS/Kotlin 读取后作为 `resetPrecisionSeconds` 传入。契约由协调员单写。
- 在字段落地前，界面对速度一律写“约”，通知不因速度单独触发（§7 的速度预警默认关闭）。

## 4. 对 T10.87 撤下“月末预估”的逐条回应

T10.37 曾在趋势卡摘要显示“日均 ≈XX · 月末预估 ≈$YY”，T10.87 在多维对抗评审后于提交 `f9234b96` 删除了渲染，函数 `calculateBurnRateAndProjection`（`src/utils/contracts/insights.ts`）留作无人调用的代码。T10.87 日志没有单列删除理由；下表依据它记录的首轮阻断问题（时间语义漂移、未知成本被伪装成已知值）与被删函数的实际行为逐条对应。

| 旧实现的问题 | 证据 | 本方案的处理 |
|---|---|---|
| 用宿主时钟与宿主时区取年月日 | `nowDate.getFullYear()/getMonth()/getDate()`，默认 `new Date()` | “今天”来自 `meta.generatedAt` 按来源时区换算，公历算术全部按 UTC；月末同期截短的日子不预测；单测在 Kiritimati、洛杉矶与 UTC 宿主下通过，并覆盖 UTC 表示的截止点跨月 |
| 进行中的今天按完整一天计 | `daysElapsedInMonth = getDate()`，月初凌晨按 1 天算日均 | 速率只用完整日；今天只作下限；月初不足 7 个完整日不预测 |
| 范围与期末错配 | today 按 1 天、week 固定除以 7（周一也是）、year 用年初至今、custom 用区间总天数（进行中也一样）、all 固定 30 天，再把日均乘以“本月总天数”，而不是已发生量加剩余天数 | 每个范围只预测到自己的期末；today / year / all 不支持 |
| 未知费用按已知 | 直接用 `summary.totalCost ÷ 天数` | 本机用逐行估算的日序列；云端只信 `dailyCosts`；完整日有未知 → 不可得；今天未知 → partial |
| 假精度 | 单点“月末预估 ≈$YY”，无方法、无区间、无样本门槛 | 粗略范围与方法说明常驻，不标未经校准的百分比；最少完整日、活跃日与外推距离门槛；金额按量级取整 |
| 与其它洞察口径不一致 | 日均含进行中的今天，而突增基线与星期节奏只用完整桶 | 与 `insightRules` 同一截止点，速率同样只用完整桶 |
| 名称混淆 | 外推值叫“月末预估”，与“预估费用”同用「预估」 | 按 T10.154 术语表，「预估」只指按价格表估算的费用，外推值一律叫「预测」；单测锁定预测文案不出现「预估」 |

## 5. 标签与中文文案

文案由逻辑层一次给出（`describePeriodForecast`、`describeQuotaPace`），保证“预测”标签、数值、范围、方法同时出现。标签是可见文字，读屏时读作“预测：……”，不能只靠样式或颜色；两个函数都直接给出读屏整句 `ariaLabel`，接入点不必自己拼接。

术语遵守 T10.154 术语表（`docs/design/cost-naming-subscription-v1.md` §1）：「预估」只指按价格表估算的费用，外推结果只叫「预测」，二者不得互换；预测的对象写作「预估费用」或短形「费用」（如“费用预测不可得”），来源无法证明时写「不可得」。预测文案里说明计算过程时用“计算”“外推”“计入预测”，不用“估算”；唯一例外是说明被预测的量本身的 D1 短注“按价格表估算，非账单”。

**DESIGN 新增 §5.5 额度消耗速度（T10.153，D2 / D4）**

> `src/utils/quotaPace.ts` 只对可信的百分比窗口计算“照此速度”：窗口起点 = `resetsAt − windowMinutes`，平均速度 = 观测时已用比例 ÷ 已过时长，外推到重置得到重置时用量与用完时刻；另给剩余时间放慢一半 / 加快一半的敏感度区间。调用方必须给出窗口所属 envelope 的 `capability`，experimental 来源不预测。reset 精度默认不信任：来源未声明时按 `resetsAt` 与观测、抓取时刻之差是否恰为整天、整小时、整分钟推断，超过窗口时长 5% 不预测（Claude CLI“Resets in 4 days”即被拦下）。新鲜度与额度面板同源（`readQuotaWindow`），历史快照、缺 `windowMinutes` 或 `resetsAt`、观测不在窗口内、刚重置（窗口 10%，多日窗口另需 24 小时）一律不预测；已用完直接告急。状态：会在重置前用完为 critical，重置前会跌破 D4 告急线（剩余 <20%）为 tight，其余 ok；额度条仍按当前剩余着色。速度不从 Stats 或费用推导额度，上游桥接的 pace 字段继续丢弃。规格见 `design/forecast-and-pace-v1.md`。

**DESIGN 新增 §4.13 周期末预测（T10.153，D2）**

> `src/utils/forecast.ts` 只为本月、本周与多日自定义区间预测期末总量：只用 `comparison.current.series` 中已完成的日桶，点预测 = 已完成合计 + 典型日（完整日算术平均）× 剩余天数（含今天）。范围是未经校准的粗略范围：宽度按 t 分位 × max(样本标准差, 0.5 × 日均) × √(m + m²/n)，再按相邻两天的相关程度放宽，并同时覆盖按最近 7 天日均外推的结果；界面不标覆盖百分比。进行中的今天不参与速率，只作下限，预测永不低于已记录量。“今天”取 `meta.generatedAt` 在来源时区的日期；月末几天后端把本期同期序列截到上月天数，这几天不预测。公历算术与宿主时区无关。门槛：月与自定义至少 7 个完整日、周至少 3 个，至少 2 个活跃日，剩余天数不超过基线天数 4 倍。云端费用只信 `dailyCosts`（日序列把未知费用合成了 0），已完成日有未知费用时费用预测不可得。结果带 `kind: 'forecast'`，只在看板呈现。规格见 `design/forecast-and-pace-v1.md`。

**REQUIREMENTS 新增 GLB-11 预测类指标（D2）**

> 预测类指标（周期末预测、额度消耗速度）只用已完成的时间段线性外推，界面单独标“预测”，数值与计算方法、范围同时可见；未经真实数据校准的范围不标覆盖百分比；外推结果只叫“预测”，不叫“预估”（“预估”只指按价格表估算的费用）；样本不足、来源未知或时间线不可信时说明原因而不给数字，未知值不按 0 参与计算。预测不进入云同步、分享海报、HTML 简报、CSV 导出、壁纸与锁屏。预测触发的系统通知必须由用户显式开启并限频。

**REQUIREMENTS 新增 REQ-COMP-04 周期末预测（P1）**

> 本月、本周与多日自定义区间的趋势卡显示期末有效 Token 与预估费用的预测：按已完成日的日均外推，给出粗略范围与方法说明（写明假设之后的用量与已完成的日子相近，不标覆盖百分比），今天只作为不低于已记录量的下限。月与自定义不足 7 个完整日、周不足 3 个时显示还差几天、哪天起给出预测；已完成日有未知费用或云端未提供逐日费用时，费用预测显示不可得而 Token 预测照常。月末几天后端截短本期同期序列时不显示预测。今日、今年、总计不提供预测。
