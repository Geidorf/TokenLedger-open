## 1. 原则与每个表面回答的问题

### 1.1 原则

1. **一个问题，一处答案。** 同一事实在一页内只有一个主呈现，其他位置只引用。例如结论句引用 KPI 的数，不另算一遍。
2. **先结论，后图表。** 每页第一块是确定性规则生成的可读结论，不调用生成式 AI。
3. **有事才提醒。** 提醒只在触发时占位；无事时用一行说明检查了什么、有哪些无法评估。
4. **诚实降级。** 未知不显示为 0（GLB-01）；无法评估写“无法评估”，不写“正常”；样本不足不下结论。
5. **下钻不改写上下文。** 任何下钻都不修改全局时间范围与筛选，返回时恢复原页面、滚动与焦点（REQ-DRILL-03、REQ-DETAIL-01 第 4 条）。
6. **预测有标签、有边界（D2）。**
   - 预测只出现在 T10.153 §6 允许的位置，一律带“预测”标签、方法与区间，不进同步、海报、导出。
   - 结论句只陈述事实，不含预测值。
   - 回本倍数只属于计费周期，不进结论句。
7. **四端同口径。** 有效 Token、记录数、预估费用、额度阈值与 Android、小组件、云端一致。
8. **视觉服从 T10.150。** 不新增令牌以外的颜色、圆角、阴影或动效。

### 1.2 每个表面回答的问题

| 表面 | 回答 | 不回答 |
|---|---|---|
| 总览首屏 | 这期用了多少、花了多少、比上期同期如何；额度够不够、何时重置；有没有要处理的事 | 为什么变了（变化归因 N4 不在范围） |
| 趋势 | 这期是怎么走过来的，与上期同进度相比如何 | 使用习惯（去行为分析） |
| 提醒与异常 | 现在有什么值得我处理 | 常态数据 |
| 工具排行 / 模型排行 | Token 与预估费用花在了谁身上，谁的单位费用高 | 质量好坏（DESIGN 禁止推断任务质量） |
| 订阅回本 | 各订阅在当前计费周期里的 API 等值与回本倍数 | 所选范围内的回本（不存在这个量） |
| 活跃日历 | 使用是否连续，这期在全年里处于什么位置 | 单日细节（去单日复盘） |
| 行为分析 | 我是怎么用 AI 的：什么时候用、用多久、哪些会话最重、（开启后）哪些项目最重 | 与上期对比（由总览负责） |
| 明细 | 逐条核对 | 汇总 |
| 专属看板 | 单个工具或模型的全貌 | 跨实体对比 |

### 1.3 五秒答案与验收

首屏不滚动即可回答三件事：

1. 用了多少、花了多少、较上期如何：结论句 A 段 + KPI 1、2。
2. 额度够不够、何时重置：结论句 B 段 + 额度与速度条。
3. 有没有待处理的事：结论句 C 段 +「查看提醒」按钮。

**验收**：1280×860 与 1200×800 两种窗口、浅色与深色主题、本机与云端各一组夹具。页面滚动为 0 时，结论句（不超过 2 行）、4 张 KPI 卡与额度与速度条完整位于视口内。用几何断言（三者 `getBoundingClientRect().bottom ≤ innerHeight`）加夹具截图验收；登记了订阅（KPI 多一行副行）的夹具也要满足。

## 2. 总览（M1）

### 2.1 顺序与模块

自上而下：

1. **页头**：标题由“Token 使用看板”改为“总览”，右侧保留「调整显示」「刷新扫描」与完成时间。删除页脚重复的“最近一次刷新…”一行，新鲜度只在页头出现一次。
2. **现有横幅**（统计失败恢复、云端同步状态等）位置与文案不变。
3. **结论句**（属于 `kpi` 模块，位于 KPI 行之上，§2.3）。
4. **KPI 行**：4 张卡（§2.4）。
5. **额度与速度条**（`quota` 模块，§2.5）；完整额度列表在条内展开。
6. **趋势**（§2.6）。
7. **提醒与异常**（`alerts`，§4）。
8. **工具排行 → 模型排行**，云端“全部设备”时再加**设备排行**（`distribution`，§3）。
9. **订阅回本**（`subscription`，只在登记订阅后渲染，§2.7）。
10. **活跃日历**（`calendar`，§4.7）。

**与审计 §5.1 的差异**：审计把「提醒与异常」放在构成之后，本方案提前到趋势之后、排行之前。两张全宽排行约 900px，放在后面会让“要不要做点什么”落到第三屏。它是高度可变的内容，放在趋势之后而不放进首屏，首屏布局就不会随提醒条数跳动；结论句 C 段与「查看提醒」负责把它带进五秒答案。

**偏好迁移**分两步，每步都能单独发布。存储键仍是 `tokenledger:dashboard-display-preferences:v1`：

- **第一步（IA-3）**：默认顺序中 `quota` 移到 `trend` 之前。已存顺序与旧默认顺序完全相同时改用新默认顺序，否则保留用户顺序。新增可选字段 `quotaDetailsExpanded`（默认 false）；旧版应用读到后忽略该字段。
- **第二步（IA-6）**：载荷 `version` 升为 2。
  - `insights` 在原位置拆成 `alerts`、`calendar`（提醒在前）。已隐藏的 `insights` 只让 `calendar` 隐藏：提醒是新的轻量模块，不继承“隐藏洞察”的意图。
  - 同时新增 `calendarCollapsed` 与 `rankingMetric`（§3.3）。
  - 归一化规则由“缺失的已知 ID 追加到末尾”改为“插到默认顺序中它前一个模块之后”。这样以后新增 `subscription` 这类模块不需要再迁移。
  - 旧版应用读到 version 2 时按现有逻辑回到默认值；这种降级行为写入发布说明。
- 仍然满足 GLB-08：至少一个模块、一个当前额度来源可见；新来源默认追加；不渲染内容的 `subscription` 不算“可见模块”。

**Token 口径开关**（有效 / 含缓存）从顶栏移入「调整显示」，沿用现有持久化，只改变控件位置。行为分析页只用有效口径，不提供这个开关。

### 2.3 结论句

由纯函数 `buildOverviewConclusion(input)` 生成（新文件 `src/utils/overviewConclusion.ts`），组件只负责渲染。

- **输入**：`stats`、`rangeSpec`、`scope`、`tokenMode`；额度高亮列表（`quota` 模块隐藏或没有来源时为 `null`）；提醒评估结果（§4）；可选的费用拆分（T10.154 B3）；`now`；是否为缓存快照及快照时间；云端待上传条数（可选）。
- **输出**：分段数组 `[{ id, text, tone }]`、拼接后的文本，以及被预算裁掉的段 ID 列表，供测试断言。

**A 段 · 用量**：`{范围名}有效 Token {T}，{变化}，预估费用 ≈{C}{费用子句}{，工具子句}`

- **范围名**用 §0.1 的统一名称。自定义区间写日期，如“9/1–9/15”。
- **变化**取自 `comparison.delta.tokens`：
  - 没有 `comparison`、范围是今年或全部时，省略变化子句。
  - 云端基线缺失时写“上期基线缺失，不计算变化”。
  - `direction = new` 时写“上期同期为 0”。
  - |百分比| < 0.5 时写“与上期同期持平”。
  - 其余写“较{上期名}同期 +18%”：|百分比| ≥ 10 取整，否则保留 1 位小数；正负号总是显示，负号用 U+2212（−）。
  - 上期名：今日对昨日，本周对上周，本月对上月；近 N 天与自定义写“前一等长区间”，悬停说明里给出 `previousStart–previousEnd`。
- **预估费用**取 `summary.totalCost`，用 `formatEstimatedUsd(…, 'summary')` 格式化。非有限数时写“预估费用不可得”。
- **费用子句**（IP-A）：登记订阅且所选范围内 API 等值 > 0 时，追加“（其中 API 等值 ≈$Y）”。只写这一份，完整的三份拆分在 KPI 2 里。回本倍数不进结论句：它按计费周期计算，与所选范围不是同一个时间段（T10.154 §2.6）。
- **工具子句**：只有一个工具时写“全部来自 X”。两个及以上工具、且第一名份额 ≥ 50% 时写“主要来自 X（61%）”。份额优先按费用占比计算；有工具费用不可得时改按有效 Token 计算，并写成“Token 主要来自 X（61%）”。其余情况省略。

**B 段 · 额度**（仅 `quota` 模块可见且至少有一个可读百分比窗口时出现）：

- 取额度条同一列表的第一项（§2.5），保证句子和条带说的是同一个窗口。
- 最紧窗口剩余 < 50% 时写“最紧的 {来源} {窗口}额度剩 {r}%（偏紧/告急），{重置时间} 重置”。全部 ≥ 50% 时写“额度充足（最低 {来源} {窗口} {r}%）”。
- 该窗口是历史读数时追加“（观测于 HH:mm）”。
- **重置时间**：同日写“今天 17:40”，次日写“明天 09:00”，7 日内写“周六 10:00”，更远写“10/1 00:00”，一律按 `meta.timezone` 显示。
- 消耗速度属于预测，不进 B 段，由额度条与提醒 R5 表达。

**C 段 · 提醒**（仅 `alerts` 模块可见时出现）：

- 有未忽略、未稍后的提醒时，写“有 N 条提醒”；其中有“需处理”级别时写“有 N 条提醒（1 条需处理）”。
- 没有提醒、且所有适用规则都已评估时，写“未发现需要处理的事项”。
- 有规则无法评估时整段省略，不宣称“一切正常”。

**前缀**：显示缓存快照时加“（缓存快照 · 截至 HH:mm）”；云端有本机待上传记录时加“（云端 · 本机 N 条待上传）”。

**长度预算**：约 100 个显示单位（CJK 计 1，ASCII 计 0.5），对应 1200 宽、15px 字号约两行。超出时依次裁掉：工具份额数字 → 整个工具子句 → 费用子句 → 重置时间 → “未发现需要处理的事项”。用量与变化、任何“告急”内容都不裁。

**呈现**：用 `<p>` 渲染，各段为 `span`。偏紧、告急、需处理用 T10.150 的状态令牌着色，并同时保留文字，颜色不单独承载语义。句子不设 `aria-live`，避免每次刷新重复朗读。「查看提醒」是 44px 的独立按钮，点击后滚动到提醒标题并移动焦点。刷新时就地替换文本，不做打字机或淡入效果。

**导出**：结论句只在看板显示。若将来复用到简报或海报，按 T10.153 §6 剔除一切预测内容，并遵守“隐藏费用”偏好。

### 2.4 KPI

| 卡 | 主值 | 同期变化 | 副行 |
|---|---|---|---|
| K1 有效 Token | `summaryEffectiveTokens(summary)` | `comparison.delta.tokens` | 输入 X · 输出 Y |
| K2 预估费用 ⓘ | `summary.totalCost` | `comparison.delta.cost` | 按 T10.154 §4.3 的状态表 |
| K3 活跃 | 见下 | 见下 | 连续天数，见下 |
| K4 缓存复用率 | `calculateCacheEfficiency(summary).cacheRatioPercent` | 两期都可证明拆分时，取两期复用率之差，单位“百分点” | 缓存节省 ≈$Y |

**K1 在含缓存口径下**：标签改为“总 Token（含缓存）”，主值为输入 + 输出 + 缓存合计。变化标签前加“有效”，仍显示有效 Token 的变化，不另造一个含缓存的变化指标。副行改为“有效 X · 缓存 Y”。

**K2 预估费用**：

- 标签旁的 ⓘ 帮助弹层与副行都完全按 T10.154 §4.2、§4.3：
  - 未登记订阅时，副行是短注“按价格表估算，非账单”。
  - 登记后，副行是“API 等值 · 预估支出 · 其余”三份拆分（为 0 的份省略）。
  - 第二副行“{订阅} · 本计费周期回本 N 倍”（1–2 个订阅时）。
- 单位费用不放在 KPI，由排行（§3.3）与趋势提示提供。
- 有待核价模型时，帮助弹层追加“其中 ≈$x 来自待核价模型”，并提供「去核价」入口（依赖 IA-6 的价格状态）。

**K3 活跃**：

| 范围 | 主值 | 变化 |
|---|---|---|
| 今日、自定义单日（小时桶） | 活跃时段 x/y 小时：`comparison.current.series` 中 tokens > 0 的桶数 / 已开始的桶数 | 与 `previous.series` 同样计数之差，如“+1 小时” |
| 本周、本月、近 N 天、自定义多日（日桶） | 活跃天数 x/y 天 | 与上期同进度之差，如“+1 天” |
| 今年 | 活跃天数 x/y 天：`heatmap` 中今年 tokens > 0 的天数 / 今年已过天数 | 无 |
| 全部 | 今年活跃 N 天 | 无 |

- **连续天数**：从 `heatmap` 取今天往回连续的活跃日。今天尚无用量时从昨天起算，并写“（截至昨日）”。连续段一直延伸到 `heatmap` 最早覆盖的那天时写“≥ N 天”：本机预设在 IA-7 修复前只覆盖本期，所以此时只能给下界。
- 范围不含今天的自定义区间改写“区间内最长连续 N 天”，从 `comparison.current.series` 计算。

**K4 缓存**：

- 拆分可证明时，主值为复用率。副行为“缓存节省 ≈$12.40”（T10.154 术语：毛节省，未扣缓存写入溢价）。读、写量与“订阅覆盖部分的缓存节省同样是 API 等值”的说明放入这张卡的帮助弹层。没有 `cacheSavedUsd` 时副行写“缓存节省不可得”。
- 只有缓存合计时：标题“缓存”，主值为合计量，副行保留原文“当前数据仅提供缓存合计”，不显示变化。原 `CacheFlowPanel` 中“为什么无法计算”的解释并入这张卡的帮助弹层。

**什么时候不显示变化**：

| 情形 | K1 / K2 | K3 | K4 |
|---|---|---|---|
| 今年、全部 | K1 变化位写“无自动基线”，K2 留空 | 无 | 无 |
| 云端基线缺失 | 中性“基线缺失” | 同左 | 同左 |
| 缺少 `comparison` | 隐藏 | 隐藏 | 隐藏 |
| `direction = new` | “新增” | 按计数差 | 上期拆分不可证明时隐藏 |
| 云端上期缓存拆分未经实测验证 | — | — | 默认隐藏，验证后开启（§6.6） |

- **变化标签样式**：中性色，箭头加正负号，不用红绿表达好坏；用量增加本身不是坏事。
- **记录数**连同其变化移到趋势卡的摘要行（§2.6），继续满足 REQ-COMP-01 验收第 2 条。
- **不换行**：数值永不换行。数值与变化标签放不下同一行时，标签移到副行上方，沿用 `metricValueSizeClass` 的字号阈值。副行允许换行，不截断（T10.154 §4.3）。

### 2.5 额度与速度条（D2、D4）

**选哪几个窗口**：

- 候选取自 `collectQuotaHighlights`，只看可见来源，排序规则保持“剩余升序，同值时重置早者优先”。
- 去掉 `resetsAt ≤ now` 的窗口：那是已结束窗口的读数，完整列表中仍显示为“历史”。
- 容器宽 ≥ 720px 时显示前 3 个，480–719px 显示前 2 个，< 480px 显示 1 个并附“+N”。用容器查询判断宽度，不用视口宽度。

**每一格**：

1. 第一行：左侧“{来源} · {窗口}”，右侧“{r}%”，使用等宽数字。
2. 第二行：4px 细条（`tl-grow-x`，只在挂载时播放）加状态词“充足 / 偏紧 / 告急”。颜色沿用 DESIGN §5.4 的语义色，文字始终保留。
3. 第三行：“{重置时间} 重置”；没有可信重置时间时写“重置时间未知”，不虚构倒计时。
4. 第四行，速度行（IA-14 起）：取 `describeQuotaPace(computeQuotaPace(window, now), now)`。
   - 只在状态为 `critical`（照此速度会提前用完）或 `tight`（重置时约剩不到 20%）时显示，前置“预测”标签，文字原样使用 `text`。
   - `ok` 与 `insufficient` 只出现在展开后的完整列表里（T10.153 §10 第 3 条），不占用条带。
   - 方法与区间放在悬停或聚焦提示中。
   - 速度行不复用等级词，语气色按 T10.153 的 `tone`。
5. 历史读数加“历史 · 观测于 14:20”标签，不显示速度行。

绝对余额、不限额、待授权或出错的窗口不进入条带，只在展开入口里计数。

- 条带里的各格是纯文本，不可点击，避免出现“点了没反应”的假入口。

## 3. 模型排行（M2）与工具排行（M3）

### 3.1 结构

三类排行（工具、模型、设备）共用新组件 `RankingList`。行数据由纯函数 `buildToolRanking`、`buildModelRanking`、`buildDeviceRanking` 生成（新文件 `src/utils/rankings.ts`），模型部分复用 `modelCostDistribution` 与 `modelCacheBreakdown`。

```text
排行（模型，1280 宽，Token 档；费用档下主值列换成预估费用，次要值列换成有效 Token）
+--------------------------------------------------------------------------------------------+
| 模型排行 · 23 个模型                                        排序口径 [Token|费用|单位费用] |
| #   模型                                            有效 Token  占比   预估费用  复用      |
| 1   o claude-sonnet-4.5       ####################  5.1M        41%    ≈$9.38    72%    ▾  |
|     展开：输入 3.2M · 输出 1.9M · 缓存读 8.3M · 缓存写 0.4M · ≈$1.84/百万 Token · 每条 10K |
| 2   o gpt-5-codex             #############         3.2M        26%    ≈$6.40    64%    ▸  |
| 3   o kimi-k2 待核价          #####                 1.2M        10%    ≈$0.72    —      ▸  |
| …                                                                                          |
|     其余 15 个模型                                  0.9M        7%     ≈$0.85           ▸  |
| 待核价 = 按工具兜底价暂估的模型；复用 — = 该模型缓存读写拆分不可得。            [规则说明] |
+--------------------------------------------------------------------------------------------+
```

行数据字段：`{ id, label, badge?, effectiveTokens, totalTokens, cost, requests, cacheRead, cacheWrite, cachedCombined, reusePercent, unitCost }`。其中 `badge` 取“≈ 估算”“待核价”或“订阅”；未知值一律为 `null`，不写 0。

### 3.2 列与响应式

每行高 44px，列依次为：名次、身份色点 + 名称（最多两行，完整名称放入提示与可访问名称）、徽标、单色数据条、主值、占比、次要值、复用率（仅模型）、展开按钮。

按容器宽度裁列：

| 容器宽度 | 显示 |
|---|---|
| ≥ 900px | 全部列 |
| 820–899px | 去掉复用率 |
| 720–819px | 再去掉次要值 |
| < 720px | 再去掉数据条；保留名次、名称、主值、占比、展开 |

长模型 ID 用两行截断加完整提示，取代 `BarPanel` 的“截到 16 字 + 旋转 28°”。

### 3.3 排序口径

分段控件“排序口径”提供 Token、费用、单位费用三档：`tl-seg`，按钮带 `aria-pressed`，外层 `role="group"`、`aria-label="排序口径"`。T10.154 §4.5 把 M3 的“Token / 金额”写作“Token / 费用”，本方案三档同样改名。

| 档 | 排序 | 主值 / 次要值 | 规则 |
|---|---|---|---|
| Token | 有效 Token 降序（含缓存口径下为总量） | Token / 预估费用 | 标签随口径开关；占比 = Token 占比 |
| 费用 | 预估费用降序，不可得的行排最后并写“不可得” | 预估费用 / 有效 Token | 占比 = 费用占比，分母为 `summary.totalCost`（同 `modelCostDistribution`）。已知行费用合计比汇总少 $0.01 以上时，才加脚注“另有 ≈$x 无法归属到具体模型”（T10.154 §4.5） |
| 单位费用 | 单位费用降序 | 单位费用 / 有效 Token（本档不显示占比） | 有效 Token < `UNIT_COST_MIN_TOKENS`（10,000）的行排到末尾，归入“用量过小，不参与排序（N 个）”；单位费用为 `null` 的行再排其后，写“不可得”，不静默消失 |

- 选择按列表分别记住，存入偏好 v2 的 `rankingMetric`：`{ tool, model }`，设备只有 Token 与费用两档。
- **单位费用**按 T10.154 的定义计算（分子含缓存读写费用，分母只含输入 + 输出），格式化用 `formatUnitCost`。有效 Token 与预估费用都已知、且有效 Token > 0 时才计算，否则为 `null`。
- **订阅相关标签（IP-A）**：工具行完全按 T10.154 §4.5——
  - 订阅覆盖的工具写“API 等值 ≈$x”，带“订阅”标签（悬停说明所属订阅与本计费周期回本倍数）。
  - 按量工具写“预估支出 ≈$x”。
  - 未设置的工具只写“≈$x”。
  - 订阅在所选范围中途开始或结束时写“≈$x（其中 API 等值 ≈$y）”。
  - 模型行不打订阅标签。

### 3.4 默认行数、展开与下钻

- **默认行数**：显示前 8 行，其余合成一行“其余 N 个 · 合计 X（Y%）”。点击后原位展开全部，按钮带 `aria-expanded`。可见行与合计行之和等于总量，这是数据等价测试的断言之一。工具一般不足 8 个，不会出现合计行。
- **每行两个并列按钮**，不互相嵌套：
  - **主按钮**覆盖名称到数值区域，点击打开专属看板（沿用现有 `onOpenEntity`）。可访问名称如“claude-sonnet-4.5，有效 Token 5.1M，占 41%，打开专属看板”。
  - **展开按钮**为 44×44，可访问名称如“展开 claude-sonnet-4.5 构成”。
- **展开内容**：
  - 标题行“{名称} · 预估费用 ≈$x · 记录 N 条”。
  - 构成条：输入 / 输出 / 缓存读 / 缓存写，拆分不可证明时为“缓存合计”，并配同内容的文字列表。
  - 复用率、单位费用、每条记录平均有效 Token。
  - 工具行另显示 `ToolStat.models` 的前 3 个模型。
  - 订阅工具在 D1 生效后显示所属订阅（回本倍数只在订阅回本卡与悬停说明里出现）。
- **徽标**：`ESTIMATED_TOOLS`（antigravity、trae）的工具行显示“≈ 估算”。按工具兜底价暂估的模型显示“待核价”（数据来自 IA-6 的价格状态；IA-6 之前不显示）。

### 3.5 移除的组件，以及数据如何保持等价

| 移除 | 原来回答的问题 | 现在由谁回答 |

| `CostEfficiencyQuadrantPanel`（T10.154 称“模型用量与费用分布”） | 谁规模大、谁单价高 | 模型排行 · 单位费用档（不再按均值切象限下判断）；该面板的 T10.154 文案随之作废 |

- 每个被移除图表里的数，都能在排行的某一档或展开内容中找到。

- 重排动画：只有用户切换档位时做 ≤ 240ms 的 FLIP，刷新引起的重排立即完成，减少动态时不做动画。

### 3.7 设备排行（云端）

只在云端“全部设备”查询时出现，沿用现有显示条件。只有 Token 与费用两档；列为设备名、主值、占比、记录数，满足 REQ-DETAIL-01 第 7 条。

## 4. 提醒与异常（M4），以及节奏与日历的去向（M6）

### 4.1 规则目录

规则集中在无 React 依赖的纯模块 `src/utils/alertRules.ts`：`evaluateAlerts(input)` 返回 `{ alerts, checked }`。

- `checked` 逐条记录规则状态：`evaluated`（已评估）、`not-applicable`（本范围不适用或模块隐藏）、`unevaluable`（数据不足或字段缺失），后两种附原因。
- 每条提醒的结构：`{ key, rule, severity, title, detail, forecast, actions, scope }`。

| 规则 | 触发条件 | 严重度 | 文案示例 | 动作 | 身份键 | 适用 |
|---|---|---|---|---|---|---|
| R1 用量突增 | `detectSpikes` 在本期已完成的桶上判定：至少 5 个已完成桶，阈值 = 中位数 + max(3×1.4826×MAD, 1.5×中位数)；今年不评估 | 留意 | 9/22 用量突增 5.6M，为已完成日中位数的 2.7 倍 | 日桶：「当日明细」（可访问名称“查看 9/22 明细”）；小时桶不给链接（DESIGN §4.8） | `spike:{scope}:{bucket}` | 两端 |
| R2 新模型 / 待核价 | 本期有用量的模型，价格状态为 auto-discovered 或 fallback（即 T10.154 所说的“待核价”） | 占本期预估费用或有效 Token ≥ 5% 时为留意，否则为信息；首次出现时间在本期内时加“新” | kimi-k2 按工具兜底价暂估（占预估费用 8%），建议核价 | 去核价（设置 › 价格） | `price:{model}:{status}` | 本机；云端没有价格状态来源，记为无法评估 |
| R3 缓存复用骤降 | 两期拆分都可证明；两期的“输入 + 缓存读”都 ≥ 100 万；复用率下降 ≥ 15 个百分点，且相对下降 ≥ 25% | 留意 | 缓存复用率 41%，较上期同期 −22 个百分点 | 查看模型排行（切到 Token 档并展开第一行） | `cache-drop:{scope}:{currentStart}` | 本机先行；云端上期拆分验证后开启 |
| R4 额度告急 | 某个可见来源的百分比窗口，新鲜读数剩余 < 20% | 需处理 | Codex 5 小时额度剩 12%（告急），今天 17:40 重置 | 查看额度（展开完整列表） | `quota:{provider}:{window}:{resetsAt}` | 两端（额度是本机读数） |
| R5 额度可能提前用完 | `computeQuotaPace` 状态为 `critical`（资格条件见 T10.153 §3.1） | 留意，标“预测” | Claude 每周额度：照此速度约 1 天后用完，早于重置（预测） | 查看额度 | `pace:{provider}:{window}:{resetsAt}` | 同 R4 |
| R6 周期末预测偏高 | 仅本月范围，`forecastFromStats` 的费用预测状态为 `ok`，且区间下限 > 上个完整月预估费用 × 1.2 | 信息，标“预测” | 月末预测 ≈$195（区间 $180–$210），高于上月预估费用 ≈$142.00 | 查看趋势（切到累计走势） | `month-forecast:{yyyy-mm}` | 本机（需另查一次上月）；云端待 IA-8a |

- **不设“偏紧”提醒**：偏紧（< 50%）已在首屏的额度条上显示，再提醒只会重复。提醒只覆盖告急（R4）和预测会提前用完（R5）。
- **历史读数**：R4 降为“信息”，写“Codex 5 小时额度上次读数 12%（观测于 14:20），可能已变化”；R5 不评估（T10.153 对 stale 不给速度）。
- **R1 的样本门槛与文案**完全沿用 `insightRules.ts` 与 DESIGN §4.8：缺少稳定基线时记为无法评估，未命中也只算“已评估”，不写“速率平稳”。趋势卡原有的 1.8 倍规则删除。
- **R5、R6 的文字**分别取自 `describeQuotaPace`、`describePeriodForecast`；数值格式按 T10.153 §5.1（预测金额 ≥ $10 取整、点预测带 ≈），不套用预估费用两位小数的汇总格式。
- **价格状态**来自新增的本机只读命令 `get_model_price_status`（§7.3）。名称到价格键的匹配只在 Rust 里做（`matching_model_price` / `model_discovery_key`），前端不复制这套逻辑。若 T10.154 B2 的 `get_cost_breakdown_local` 已按模型返回待核价状态，就直接复用，不再新增命令。
- **提醒跟随可见性**：额度来源被隐藏、或 `quota` 模块被隐藏时，R4、R5 不产生提醒，记为不适用。

### 4.3 忽略与稍后

- **忽略**：按身份键长期隐藏这一条。额度类的键包含 `resetsAt`，到下个窗口会自然重新出现，所以按钮提示写“本周期不再提醒”；其他规则写“不再提醒此项”。
- **稍后**：隐藏 24 小时。
- **存储**：本机 `tokenledger:alerts-state:v1`，格式 `{ version: 1, entries: { "{scope}:{key}": { state, until?, at } } }`。
  - 清理 60 天前的条目，最多保留 200 条，超出时先删最旧的。
  - 读写都包在 try/catch 里；存储失败时只在本次会话内生效。
- **已忽略 N ▾** 列出被忽略和稍后的条目，每条可以恢复。操作结果用一次 `aria-live="polite"` 播报，如“已忽略 1 条提醒，可在已忽略中恢复”。
- 忽略只影响显示：结论句的计数不含已忽略项，数据与规则判定不变。

### 4.4 空态、加载与无法评估

- **空态**：只占一行，写“无待处理事项 · 已检查 N 项规则（K 项本期无法评估）”。N 为已评估与无法评估之和，不适用的不计入。
- **规则说明**：弹出层逐条列出规则的状态与原因，例如“已完成的桶不足 5 个”“云端没有价格状态来源”“还需 3 个完整日才预测”（取自 T10.153 的原因文案）。
- **加载**：一行静态骨架。统计本身失败时写“数据不可用，未评估”，不显示空态。

### 4.5 系统通知（IA-16，可选，后续）

系统通知完全按 T10.153 §7，本方案不另定规则。要点：

- 默认关闭。
- 只针对额度窗口：20% 档默认开；50% 与 5% 档、速度预警可选且默认关。
- 边沿触发，按窗口实例去重。
- 同一来源每 15 分钟最多一条，全局每小时最多 4 条。
- 静默发送；主窗口在前台且额度面板可见时不弹出。点击通知打开主窗口并定位到额度面板。

提醒模块与通知共用 R4、R5 的判断函数，但各自保存去重状态：在应用内忽略某条提醒，不影响通知的去重，反之亦然。

### 4.6 节奏的去向

- `UsageRhythmPanel` 的小时与星期节奏离开总览。本机场景由行为分析的热力主图、边际分布与星期维度取代（§5.6）。
- **云端**：在行为分析的云端降级页（§5.11）显示星期节奏，不像审计建议的那样在提醒里留一行摘要。提醒只放需要处理的事，节奏属于习惯信息。
- **星期模式的样本要求**：`buildRhythm` 新增参数 `minObservationsPerWeekday`，默认 1，维持现有行为，HTML 简报测试不受影响；行为页与云端降级页传 2。简报目前“按 5 个完整日聚合的日均消耗峰值在周五”的措辞实际是“单日最高”，是否同步收紧列为待定项（§9）。

### 4.7 活跃日历

- **常驻**：总览的最后一个模块，所有范围都显示。现在只在今年、全部与超过 31 天的自定义区间出现。
- **年份**：按 `meta.timezone` 取当年，不再用主机时钟（`YearHeatmap` 现在用本地时钟）。
- **当前范围**：日历上只做描边高亮，其余日期正常着色，与 Android T10.136 的全局热力图规则一致。
- **标题行**：“今年活跃 N 天 · 当前连续 N 天 · 最长 N 天”。复用 `shareSummary.ts` 中的 `activeIsoDays` / `longestStreak`，抽到共享工具模块中。
- **色阶**：按今年所有非零日的分位数分 5 档，单一色相，零值留空，附“少 → 多”图例。原因与 T10.111 改节奏面板相同：数量级色阶会让小值格比大值格更显眼。
- **交互**：
  - 点击或按 Enter 选中某天，进入单日复盘（§6.2）。
  - 键盘使用与行为热力相同的漫游焦点：整个网格只占一个 Tab 停靠点，方向键移动。现有的焦点环测试保留。
- **数据**：
  - 预设范围使用可信的年度 `heatmap`。本机预设目前只返回本期范围内的日期，与契约 §4“预设范围仍提供全年热力图”不一致；IA-7 修复 Rust 端，属于符合契约的修正，不改契约。
  - 本机自定义区间另发一次年度查询，只取 `heatmap`，使用独立的请求身份与缓存，不与主查询合并 summary、models 或 `dailyCosts`（与 Android T10.136 相同）。
  - 云端自定义在 IA-8a 之前只显示今年，并注明原因。
- **折叠**：可以收起，状态存入 `calendarCollapsed`；收起后只留标题行的统计。

### 5.3 范围与筛选

- **范围**：使用顶栏共享的 `RangeSpec`（§6.1）。行为页的主分段是“今日 / 近 3 天 / 近 7 天 / 近 30 天 / 更多▾”，满足 GLB-10。

  - “全部”受 731 天上限约束；`meta.rangeTruncated` 为 true 时注明“仅统计最近 731 天”。
- **工具筛选**：用 `FilterMultiSelect`，选项取同一本机范围的 Stats v2 `tools`，即 App 已持有的全局查询结果；该查询带工具筛选时，选项只列这些工具。
  - 筛选通过行为契约已接受的 `tools` 查询字段下发，不改契约。
  - 这是页内筛选，不写回全局查询。
- **项目筛选（IP-D）**：按 T10.155 §5.1、§6.1：
  - 多选，可搜索，含“未归属”（保留键 `@unattributed`）。
  - 通过顶层可选参数 `projects` 下发，不放进 `LocalStatsQuery`。
  - 收到项目维度关闭的事件时清空筛选。

### 5.4 结论条

由纯函数 `buildBehaviorConclusion(response, filters, now)` 生成，只读行为分析响应，不混用其他查询。最多两行，按下列顺序拼接：

1. **高峰时段**：在小时边际上找连续 4 小时的最大窗口（允许跨过午夜）。份额 ≥ 30% 时写“14–18 点最活跃（占 42%）”；否则写“使用时段较分散”。今日范围也适用。
2. **星期或单日**：
   - 每个星期几都至少有 2 个完整观测日时，写“周二最忙（日均 3.1M，基于 4 个周二）”。
   - 否则范围 ≥ 2 天时，写单日最高：“9/22（周二）用量最高 3.8M”。
   - 今日范围省略。
3. **最重的会话**：取 `sessions[0]`。有 T10.151 的会话字段时写“最重的会话 3.2M 有效 Token（Codex · ≈$4.10 · 2 小时 10 分）”，费用为会话预估费用，不可得时省略；没有这些字段时写“最重的会话 3.2M 有效 Token（Codex）”。
4. **项目**（仅项目维度 `ready`）：按 T10.155 §6.1 第 5 条，可引用占比最高的项目；未归属占比超过 20% 时必须同时说明，例如“TokenLedger 占 41%，另有 38% 来自不记录工作目录的工具”。
5. **活跃**：写“活跃 6/7 天”。范围截止到今天时追加“本区间内连续 5 天”，否则追加“区间内最长连续 N 天”。

**超长与前缀**：超出两行时依次裁掉第 4、2、1 项。有工具或项目筛选时加前缀，如“（仅 Codex）”“（项目：ledger）”。

**空态**：空区间沿用现有文案“该区间没有本机账本记录。”

### 5.5 KPI

行为页不显示同期变化，对比由总览负责。

| 卡 | 主值 | 副行 | 数据 |
|---|---|---|---|
| 有效 Token | `summary.tokens` | 记录 N 条 | 现有 |
| 预估费用 ⓘ | `summary.totalCost`（T10.151） | 按价格表估算，非账单 | `totalCost` 为 null 或 `costComplete` 为 false 时写“预估费用不可得”；字段缺失（旧后端）时同样写不可得，不写 $0 |
| 活跃天数 | `summary.activeDays` / 区间天数 | 本区间连续 N 天 | 现有 |
| 会话 | `summary.sessionCount` | 中位 X/会话（`summary.sessionMedianTokens`）；没有该字段时写“均 X/会话” | 均值 =（`summary.tokens` − `unknownSessionTokens`）÷ `sessionCount`；缺 `unknownSessionTokens` 时不显示副行，避免把无 ID 记录算进均值 |

缺少会话 ID 的记录数不放进 KPI，在会话表的说明行给出（§5.9）。

### 5.6 节奏主图：热力、边际与星期维度

**日期×小时**：

- 每行一个日期，标注星期，如“9/22 二”。每页 14 天，最近的一页在前，“较早 / 较近”翻页，沿用现有的 14 天分页。
- 24 列小时按查询时区划分。
- **边际**：上方为全区间每个小时的合计，标注“区间合计”；右侧为当页每一天的合计。
- **色阶**：按当前页的最大格线性分 5 档，与现有 `heatPeak` 口径一致；0 留空。未来时段不着色，也不能选中。
- **默认视图**：范围 ≤ 14 天时默认日期×小时，> 14 天时默认星期×小时。用户切换后按人记在本机，读写包在 try/catch 里。

**星期×小时**：

- 7 行（周一到周日）× 24 列。每格 = 该星期几、该小时的有效 Token 之和 ÷ 该星期几的完整观测日数。
- 观测跨度从区间开始与首条记录日期中较晚的一天算起。今天进行中的数据既不计入分子，也不计入分母。
- 提示：“周二 15:00 · 平均 0.4M · 基于 4 个周二”。
- 观测日少于 2 天的行用斜纹标“样本不足”，也不参与结论条的星期判断。

**键盘与读屏**：

- `role="grid"` 加漫游焦点，整个网格只有一个 Tab 停靠点。现在是 336 个按钮逐个可 Tab。
- 按键：
  - 方向键：移动。
  - Home / End：到行首、行尾。
  - Ctrl+Home / Ctrl+End：到第一格、最后一格。
  - PageUp / PageDown：翻到更早或更近的 14 天。
  - Enter / Space：选中。
  - Escape：清除选择。
- 每格的可访问名称，如“9/22 周二 15 点，有效 Token 1.2M，38 条记录”。

**44px 路径**：格子约 30×24px，小于 44px。选择行提供等价的“日期 / 时段”两个 44px 下拉框，与网格选择双向同步。时段下拉含“全天”。“查看该日明细”“清除”也都是 44px 按钮。

**选择的作用**：只高亮对应的行与列，并更新选择行的摘要：

- 选中时段：有效 Token、记录数。
- 选中整天：有效 Token、记录数、当日主要工具（来自 `toolDays`）。

选择不修改任何查询。“查看该日明细”走不改写上下文的下钻（§6.2）。

### 5.7 构成随时间

- 按日堆叠柱，日期与当页 14 天对齐，可在“工具 / 模型 / 项目”间切换。
  - 工具与模型各取前 6，其余合为“其他”。模型使用现有 `modelDays`；工具需要只增字段 `toolDays`，缺失时不显示该选项。
  - 项目按 T10.155 §6.1 第 3 条：前 8 个 + 其他 + 未归属，只在 `ready` 或 `indexing` 时出现。T10.155 的响应目前只有区间合计，没有按日数据；按日项目构成需要只增字段 `projectDays`（§7.3），这是对接缺口，未补之前不显示该选项。
- 图例开关状态在刷新后保留。点击柱子等同于在主图里选中那一天。
- 单日范围改为按小时显示模型构成（现有 `modelHours`），工具与项目选项隐藏。
- “模型时段分布”（模型 × 小时，跨日合计）折叠到“更多：模型 × 小时”。

### 5.8 项目排行

- 内容、状态矩阵与“未归属”规则完全按 T10.155 §6.1 第 2 条与 §6.3。
- **位置**：构成之后、会话表之前。
- **可见性**：项目维度关闭时，这里只显示一张一行高的入口卡：“按项目查看用量（默认关闭）。开启后只在这台电脑保存文件夹名，不上传。「了解并开启」”；不做成大块占位。项目名不做默认展开的大字标题（T10.155 §6.4）。
- **交互**：点击行即设置项目筛选，与筛选行的项目下拉双向同步。

| 有效 Token | `sessions[].tokens` | 现有 |
| 预估费用 | `sessions[].cost` | 会话预估费用；`null` 或缺失时写“不可得” |
| 记录 | `sessions[].requests` | 现有 |

- **排序**：后端返回按有效 Token 选出的前 100 个会话。表头可以改按费用、开始或时长排序，但只在这 100 个会话内排。`sessionsTruncated` 为 true 时注明“排序只在按有效 Token 选出的前 100 个会话内进行”。
- **分批显示**：先显示 20 行，“显示更多”每次追加 20 行。
- **行点击**：进入明细，覆盖条件为：日期 = 会话首末日，工具 = 会话所属工具，搜索 = 会话 ID（§6.2）。
  - 搜索是子串匹配，范围覆盖 tool、model、machine_id、session_id 四列（契约 §4.1 第 5 条），可能多匹配到少量其他行。chip 写“搜索：会话 ID”。精确会话筛选不在本方案范围内。
- **逐轮**：
  - 行尾“逐轮”按钮只在有 `sessions[].lastRecordId` 且该工具支持会话分析时出现。
  - 点击后在行为页直接打开 `SessionAnalysisDrawer`，传入 `{ id: lastRecordId, sessionId, tool }`。
  - 没有该字段时不显示这个按钮，用户经明细进入。
- **说明行**：
  - `summary.unknownSessionRecords > 0` 时写“另有 N 条记录缺少会话 ID，未计入会话数与排行”。
  - 有截断时写“共 N 个会话，显示有效 Token 前 100”。
- **会话规模**（可选，IA-11）：有只增字段 `sessionSizes` 时，表格上方显示一条“按会话统计”的规模分布细条。不从截断后的前 100 推算。

### 5.10 附录

- 现有的“账本记录大小分布”改名“单条记录规模（有效 Token，不含缓存上下文）”，默认折叠。
- 模型下拉默认选记录数最多的模型；T10.151 已把 `requestSizes` 改为按记录数排序。
- 注明“部分来源一条记录即一个会话，不能一律解释为单次请求”。

### 5.11 云端降级（IA-13）

云端不再只显示一张说明卡，改为三部分：

- **说明行**：“云端没有逐条行为明细，以下为全部设备的汇总节奏”，并附「切换到本机查看完整行为分析」。另加 T10.155 §6.3 要求的“项目维度仅在本机视图可用”。
- **显示**：
  - 星期节奏：用 Stats v2 `trends` 的日桶，仅本月与 ≥ 28 天的自定义范围（后者待 IA-8a），每个星期几至少 2 个观测日。今年是月桶，没有星期语义，不显示（DESIGN §4.8）。
  - 工具构成随时间：来自 `trends` 的各工具序列。
  - 突增：与 R1 同一套规则。
  - 活跃日历入口：跳到总览的日历。
- **隐藏**：小时热力、会话表、项目、记录规模。原因写在说明行里，不以样本冒充全量（GLB-10）。

### 5.12 刷新与动效

- 随 `stats-updated` 与页面恢复可见时刷新，同一查询刷新时保留旧数据、就地更新（T10.151 已实现）。查询变化时显示静态骨架，不显示上一查询的结果（GLB-10“范围切换后仅显示当前请求结果”）。

- ECharts 只在首次挂载时播放动画，后台刷新关闭更新动画；减少动态时全部关闭。

### 5.13 下钻

- 行为页里的任何选择都不改写全局范围。
- 现有的日期点击会调用 `changeRange('custom', 日期..日期)` 改写全局范围，改为 §6.2 的覆盖层。

## 6. 跨页规则

### 6.1 统一时间范围（M8）

```ts
type RangeSpec =
  | { kind: 'preset'; preset: 'today' | 'week' | 'month' | 'year' | 'all' }
  | { kind: 'relative'; days: 3 | 7 | 30 }          // 近 N 天，含今天
  | { kind: 'custom'; start: string; end: string };  // 本地日期闭区间，≤ 731 天
```

- **发送时的映射**：
  - `preset` 原样发送。
  - `relative` 在请求时按查询时区解析成 `range: 'custom'`，`start = 今天 − (N−1)`，`end = 今天`。在该时区跨过午夜、或页面恢复可见时重新解析，“近 7 天”会自动向前滚动。
  - `custom` 原样发送。
  - 这些映射不改 Stats v2，也不改行为契约，与 DESIGN §4.8“近 3/7/30 天通过自定义日期闭区间实现”一致。
- **名称**：一律经 `rangeDisplayName(spec)` 取得，词汇见 §0.1。同一年内写“9/1–9/15”，跨年写“2025/12/20–2026/1/5”。
- **两页共用一个状态、一个控件**，只是主分段不同：
  - 总览：“今日 / 本周 / 本月 / 今年 / 全部 / 更多▾”。
  - 行为分析：“今日 / 近 3 天 / 近 7 天 / 近 30 天 / 更多▾”。
  - “更多▾”（`aria-haspopup="menu"`）里放另一页的主分段项、现有 `CUSTOM_RANGE_PRESETS`（昨天、上周、上月、本季度、上季度，解析为 `custom`；原“最近 7 天 / 最近 30 天”改为滚动的“近 7 天 / 近 30 天”），以及“自定义…”（打开现有的非模态日期弹层，`aria-haspopup="dialog"`，沿用 731 天校验；弹层里的常用区间 chip 移入本菜单，弹层只保留起止日期与「应用」）。
  - 当前范围不在主分段里时，“更多”段显示为选中，文字换成该范围的名称，如“近 7 天 ▾”。任何时候都有一个段处于选中状态。
- **行为页**：页内时间栏退役，顶栏在行为页也显示范围控件（现在是隐藏的）。Token 口径开关不在任何一页的顶栏出现（§2.1）。
- **云端（IA-8a 之前）**：桌面云端还不支持 `custom`（契约 §4 的客户端开放范围差异）。
  - “更多▾”中的近 N 天、常用区间与自定义显示为不可用，并注明“桌面云端暂不支持自定义区间”。
  - 带着近 N 天或自定义范围切到云端时，近 3 天、近 7 天映射为本周，近 30 天与自定义映射为本月，并提示“云端暂不支持近 7 天，已显示本周”。切回本机时恢复原范围。
  - 这一行为替代 REQ-COMP-03 现行的“桌面端对云端 scope 的自定义区间直接给出可读错误”（建议文字见任务日志）；后端的 `reject_custom_range_for_cloud` 保留为兜底。
- **IA-8a**：在桌面接通云端 `custom`。v2 RPC 自迁移 `20260905162953` 起已支持，Android 已在用。
  - 与 T10.154 的 C0 是同一项工作，只登记一次。
  - 验收状态为 `external-pending`，直到在真实 Supabase 上验证为止。
  - 按计费周期计算的云端回本也依赖它。

### 6.2 下钻语义

**规则**：

- 下钻从不写全局查询 Q。目标页使用 Q' = Q ∘ 覆盖，即用覆盖字段替换 Q 中的同名字段，其余全局条件（设备、工具、模型、搜索）照常生效。
- 目标页显示覆盖 chip，如“单日复盘 · 9/22 · 来自总览”，旁边有“×”与「返回总览」。Escape 或返回键回到来源页，并恢复滚动位置与来源控件的焦点（用 `data-drill-id` 定位）。在目标页继续调整筛选只作用于覆盖层；离开目标页即丢弃覆盖层。
- 当前作用域表达不了覆盖条件时（例如 IA-8a 之前在云端按单日下钻），入口显示为不可用并说明原因，绝不退化成“把日期塞进搜索”——那正是 P0“日期下钻返回 0 条”的成因。
- **实现**：在 App 中新增 `detailsOverride` 与 `returnTo`；`useUsageDetails` 接受覆盖层，现在它只能用全局范围。
- **与 P0 修复的衔接（IP-F）**：P0 修复若采用“改写全局范围”的最小方案，IA-9 负责换成覆盖层；若 P0 修复已经实现了覆盖层，IA-9 只补返回与焦点恢复。

**入口**：

| 来源 | 触发 | 覆盖条件 | 目标 |
|---|---|---|---|
| 总览趋势的日点 | 点击或 Enter | 日期 = 该日（单日 `custom`） | 明细（单日复盘） |
| 提醒 R1（日桶） | 当日明细 | 日期 = 突增日 | 明细 |
| 活跃日历的日格 | 点击或 Enter | 日期 = 该日 | 明细 |
| 工具 / 模型排行的行 | 点击 | 实体 = 工具或模型（沿用现状） | 专属看板 |
| 行为页节奏主图 / 构成柱 | 查看该日明细 | 日期 = 该日；工具筛选随行为页 | 明细 |
| 会话表的行 | 点击 | 日期 = 会话首末日；工具 = 会话所属工具；搜索 = 会话 ID | 明细 |
| 会话表的“逐轮” | 点击 | recordId = `lastRecordId` | 逐轮抽屉（在行为页内打开） |

- 单日复盘继续使用规范的单日查询（契约 §8 T10.136 一节）。
- 项目筛选不带入明细：项目维度不进 Stats v2（T10.155 §6.4），chip 注明“项目筛选只作用于行为分析”。

### 6.3 动效（服从 T10.150）

- **只在挂载时播放一次**：卡片入场用 `tl-enter-up`，只在进入页面时播放。刷新、范围或作用域变化都不重放，因此组件的 key 不能随刷新改变。
- **后台刷新**：数值、条宽、重排都立即完成。只有用户主动改变查询或档位时，才允许 ≤ 240ms 的宽度过渡与 FLIP 重排。
- **数字**：同一查询刷新时不做滚动计数。
- **分段控件**：使用 `tl-seg` 与 `useSegmentedIndicator`。
- **新出现的提醒**：只有页面可见期间新增的提醒使用 `tl-pop-in`，首次加载不播放。
- **热力格与日历格**：没有逐格动画，选中高亮立即生效。
- **减少动态**时全部关闭。不使用 `@starting-style`、锚点定位或 View Transitions。

### 6.4 可访问性

- **触控目标**：所有可交互控件至少 44px，包括分段按钮、展开按钮、刷新、提醒操作、排行行按钮、下拉框与 ⓘ 帮助按钮。
- **不只靠颜色**：状态一律同时有文字，如充足 / 偏紧 / 告急、需处理 / 留意 / 信息、预测；变化同时有箭头与正负号。
- **网格**：行为热力与活跃日历都用漫游焦点加方向键，整个网格只占一个 Tab 停靠点（§5.6）。
- **播报**：刷新不播报。只对用户操作的结果用一次 `aria-live="polite"`，例如忽略提醒、切换档位后的排序结果。
- **焦点恢复**：下钻返回、弹层与抽屉关闭后都恢复焦点。
- **读屏读全称**：例如“预估费用不可得”“预测：照此速度约 1 天后用完”。
- **图表的文字等价**：趋势靠摘要行加现有的无障碍数据；排行本身就是列表；热力可用网格读取；构成柱配有同源的文字图例与数值提示。

**总览只换范围时保留旧画面（T10.181）**：上表「查询变化」一列对总览各块以本段为准。

- 总览看板在同一口径、同一设备下只换范围或自定义起止日期时，保留上一范围已显示的结论句、KPI、趋势与排行（含其范围标签）。
  - 页头标题同一行（标题右侧，按基线对齐）写一行 `role="status"` 的提示，写明正在加载的范围和当前仍显示的范围；窗口窄到放不下时折到标题下方（T10.200）。
  - 整页 `aria-busy`，刷新按钮显示「加载中…」。
  - 不插骨架、不闪错误、不重建图表实例；提醒在新数据到达后重新评估。
- 新范围加载失败时，照常显示错误并丢弃旧内容。持有期间切换 Token 口径不丢旧内容：口径不在查询里，旧内容按新口径重排后继续显示，排行、分布、KPI 与页脚同一口径（T10.200）。
- 换口径、设备或账户仍用骨架，不带入上一查询的数据；这些切换在同一次渲染里进入加载态，不出现错误面板，已在当前口径时再点一次不做任何事。查询身份（口径 + 设备 + 云端账户）由 `App` 传给 `DashboardTab`（T10.200）。行为页换范围时同样保留上一帧：页头写明正在加载哪一段、下方仍是哪一段，图表实例不卸载；换作用域（本机与云端）仍用骨架，且切换那一拍不再闪出上一作用域的「读取失败」（T10.201）。
- 状态行写作「正在加载「<新范围>」，下方暂为「<旧范围>」的数据」。
  - 范围名与顶栏范围控件同一写法：今日、本周、本月、今年、总计；自定义区间写起止日期，如「7月8日—7月14日」。
  - 新数据到达、加载失败或旧内容被丢弃时，这一行随之消失。
  - 等待期间再换范围，只改写“正在加载”的那一段，“下方暂为”仍是屏上那一段。
- 失败的恢复动作按种类给出，面板与横幅相同，第一个为主动作（T10.200）：
  - 本机读取失败 → 重试加载；本机扫描失败 → 重试扫描；
  - 云端范围受限 → 选择预设范围、临时查看本机；
  - 登录状态已过期（含未登录）→ 重新登录、临时查看本机；
  - 网络连接中断、云端服务暂不可用 → 重试加载、临时查看本机；
  - 云端版本不兼容、云端权限不足 → 去设置、临时查看本机；
  - 分类按 Rust 原文逐句（`classifyCloudFailure`），契约测试从 Rust 源码锁定原文（R-60）。
- 已知缺口（T10.200 之后，见 `docs/BACKLOG.md`）：
  - 窗口窄到一行放不下（实测 900×800 预设、1024×768 长自定义区间）时状态行折到标题下，下方内容仍下移约 6 px；
  - 换设备且没有快照时，加载期间顶栏设备下拉显示「全部设备」；
  - 钥匙串类失败暂归登录过期；Rust 把 401 与 403 合成一句，看板分不出权限不足。

**快照与过期**：统计失败后显示的上次可信数据，一律在页头与结论句前缀中写明时间。额度的历史读数另有自己的标签（§2.5）。查询变化期间屏上仍是上一范围的数据时，同样就近写明它属于哪一段（见上文状态行）。

### 6.6 本机与云端的差异

| 能力 | 本机 | 云端 |
|---|---|---|
| 同期对比 | 今日、本周、本月、近 N 天、自定义 | 今日、本周、本月；近 N 天与自定义待 IA-8a；上期为空时显示“基线缺失” |
| 缓存读写拆分 | 有 | v2 RPC 有，旧 RPC 只有合计 |
| 上期缓存拆分（K4 的变化、R3） | 有 | 迁移看起来会输出，但未经实测验证；默认不显示，验证后开启 |
| 费用的完整性 | 每条记录都有有限费用 | `summary.totalCost`、`tools[].cost` 把空费用按 0 相加，工具行无法显示“不可得”；`models[].cost` 可能缺失（T10.154 §2.1 已知局限，写进帮助） |
| 设备排行 | 无 | “全部设备”时有 |
| 价格状态（待核价、R2） | 有（新命令） | 无，R2 记为无法评估 |
| 额度条、R4、R5 | 本机额度读数，与作用域无关（沿用现状） | 同左 |
| 活跃日历 | 预设为全年（需 IA-7 修复）；自定义另发年度查询 | 预设为全年；自定义待 IA-8a |
