# 会话详情（v1）

状态：实施中（2026-10-24 起）。适用平台：桌面端（用量 › 会话 › 会话详情）。来源：用户要求点开一个会话看逐条时间线、累计费用、Context 构成变化、最贵的几条与同类会话对比，并能从请求明细、周报「最贵会话」、异常卡片跳转进来。

## 不做的事

- **不新增口径**：只读本机明细（`get_usage_details`，与「请求」子页同一份去重账本与逐行预估费用）和本机行为分析（`get_local_behavior_analysis`，与会话排行同一口径）。页面上的合计、累计与平均都是对这两份结果逐行求和或相除，不改 `StatsData`、契约与同步格式。
- **不进云端**：会话 ID 只在本机账本里有，云端只存小时汇总。详情始终读本机；从详情回到请求明细时一并切回「本机机器」范围。
- **不把记录数说成请求数**：本机明细的一行是一条账本记录，有的来源按会话或累计记账，一行不一定是一次模型请求。概要条显示「账本记录」；只有每行都带来源请求数（`requests`）时才另注「来源记下 N 次请求」。时间线、最贵列表都按「第 N 条」计。

## 入口与地址

- 地址 `#session/<工具>/<会话 ID>`，两段都做 URL 编码；工具未知时写 `-`，按会话 ID 匹配所有工具的记录。扫描器的占位值 `unknown_session` 不是会话，不生成入口。
- 其他页面调用 `openSessionDetail({ sessionId, tool })`（`src/features/sessionDetail/sessionDetailRoute.ts`）跳入：地址变化后切到「用量 › 会话」并显示详情。返回列表时地址回到 `#sessions`；切到别的页面时详情收起并去掉锚点，之后从导航回到「会话」看到的是列表。
- 已接入：会话排行的行（原先直接打开按会话筛选的请求明细，这个动作移到详情页的「在请求明细中查看」）、请求展开行的「会话详情」、概览「会话异常昂贵」卡片、本机周报/月报的「最贵会话」与网关请求日志详情中的会话入口。
- 报告入口保留原始工具键，不用工具展示名反查；请求日志入口使用与本机账本相同的 Agent 到工具映射。空白、缺失与占位会话不提供入口。两处都打开本机完整会话历史，入口旁明确说明范围可能超出当前报告或请求，不能把详情合计当作报告期或单次请求的合计。

## 数据

- 读取：明细按工具（有时）与会话 ID 搜索，范围「全部」，每页 100 条，最多 30 页；搜索是子串匹配，只保留会话 ID 完全相同（工具相同）的行。超出上限时只展示最新的 3000 条并注明；读满上限仍没有完全匹配的记录时说明「没能读完」，不说会话不存在。
- 时间线按时间正序。模型与上一条不同时标「切换」。命中率 = 缓存读 ÷（输入 + 缓存读），只在读写拆分可证明时给出，与请求展开行一致。累计费用只累加已知费用；有费用不可得的记录时概要条显示已知部分并注明条数。
- 耗时只有经网关的记录带；概要条给中位数与合计。
- Context 构成只有经网关且记下构成的记录带；按字节占比分摊这条记录的输入 + 缓存，作估算 Token 堆叠，与请求展开行同一算法。
- 同类会话：同一工具在截至本会话最后一条记录所在本地日期的 30 个日历日内的其他会话（本会话不计入），平均费用、有效 Token 与账本记录；行为分析对其他会话只统计窗口内的记录，所以本会话也只取窗口内的部分来比，较长的会话不会因多算窗口外的历史而显得更贵。行为分析只返回前若干会话时注明平均只覆盖这些会话；有会话费用不可得时平均费用不可得。会话跨多个工具时不做对比。

## 界面

沿用桌面视觉刷新：一张卡细线分格的概要条，其余为平面卡片。窄于 1100px 时图表与对比单列，概要条三列；窄于 640px 时两列。所有文案走 i18n（`sessionDetail.*`）。
