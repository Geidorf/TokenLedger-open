# 网关供应商健康度（v1）

状态：实施中（2026-10-24 起）。适用平台：桌面端主窗口（供应商页、路由页）。来源：用户要求自带网关能看出每个供应商、每个模型最近是否可用、快不快、错在哪。

## 不做的事

- **默认只做被动统计**：只读网关自己写的诊断记录（`usage-v1.jsonl`，轮转后连同 `.jsonl.1`），不为统计发任何上游请求。主动探活见下文，默认关闭。
- **不进挂件、不上云**：健康度只在主窗口用，命令 `gateway_provider_health` 只允许主窗口调用。
- **不改路由**：v1 只显示，不因健康度剔除或后移成员。成员冷却仍由路由组按失败即时处理（见 [路由决策解释链](routing-decision-trace-v1.md)）。

## 数据

窗口为最近 24 小时。每个已配置的供应商一条（没有流量的显示「无流量」），另含该供应商在记录里出现过的每个上游模型：

| 字段 | 说明 |
| --- | --- |
| `requests` / `ok` / `successRate` | 发到（或尝试发到）上游的次数、成功次数与成功率 |
| `p50Ms` / `p95Ms` | 成功请求的耗时分位（最近秩法）；流式请求算到最后一个事件 |
| `rateLimited` | 非额度原因的 429 次数 |
| `skipped` | 网关本地就拦下、没发到上游的次数（未设置 Key、协议不支持、凭据不可用），不计入成功率与耗时 |
| `codes` / `statuses` | 失败的原因码分布与 HTTP 状态码分布，按次数降序 |
| `buckets` | 24 个滚动小时桶（从 24 小时前起，最后一桶截至此刻，与统计窗口一致）：请求数、失败数、成功请求 P95 |
| `recentFailures` | 最近 5 次失败：时间、模型、状态码、原因码、错误前 160 字 |
| `cooling` | 该供应商此刻在路由组里冷却中的成员 |

原因码沿用解释链码表：上游回复（错误正文以「上游返回 <状态码>」开头）按状态码分 `rate_limited`、`quota_exhausted`、`auth_failed`、`upstream_failed`、`upstream_rejected`；连接失败与等待响应头超时为 `connect_failed`；本地拦下的为 `key_missing`、`protocol_unsupported`、`credential_unavailable`。网关停止时被中止的请求、Agent 中途断开或不再读取响应（错误以「客户端」开头）不计，它们与供应商无关。

## 状态判定

| 状态 | 条件 |
| --- | --- |
| 故障 `down` | 最近连续 3 次上游请求失败，或有成员已连续失败 3 次仍在冷却；或 24 小时内只有本地拦下的请求 |
| 降级 `degraded` | 最近一次上游请求失败，或有成员冷却中，或至少 5 次请求且成功率低于 90% |
| 健康 `healthy` | 有上游请求且不满足以上条件 |
| 无流量 `idle` | 24 小时内没有任何记录 |

`reasons` 给出判定依据：冷却中为 `cooling_down`，再加次数最多的上游失败原因码。

## 界面

- 供应商页：每行在 Key 状态前显示 24 小时趋势条（柱高为请求量，红色顶部为失败占比）与状态徽标（启用的供应商才显示），悬停说明近 24 小时次数、成功率、P95 与原因。详情抽屉底部「健康度」一节列出统计、错误分布、冷却成员、各模型对比与最近失败。
- 路由页：路由组卡片每个成员前有所属供应商的健康圆点，子组成员没有。
- 两页每 30 秒刷新一次，窗口隐藏时跳过；刷新失败时撤下徽标与统计，不把旧数据当成当前状态。

## 主动探活（可选，默认关）

- 开关与间隔存在网关目录的 `health-probe-v1.json`（`enabled` 默认 `false`，`intervalMins` 5–120，默认 15），由仅主窗口命令 `gateway_set_health_probe` 写入。
- 开启且模型接入总开关打开时，每到间隔对每个启用的供应商发一次 `GET …/models`：OpenAI 兼容供应商为「接口地址 + `/models`」，Anthropic 协议为 `…/v1/models`（带 `anthropic-version`）。两者都是官方公开文档的模型列表接口，不发对话、不消耗 token。只用用户已为该供应商存进钥匙串的 key；没设 key 的供应商不探。连接走与转发相同的地址校验。
- 「立即探活」（仅主窗口命令 `gateway_probe_providers`）只在用户点击时探一次，开关关着也可以用。
- 结果只在内存里保留每个供应商最近 12 次，不写用量记录，关闭开关即清空。状态码映射：2xx 正常，401/403 `auth_failed`，402 `quota_exhausted`，429 `rate_limited`，5xx `upstream_failed`，404/405/501 `probe_unsupported`（没有模型列表，不算失败），其余 `upstream_rejected`，连接失败或 20 秒超时（含解析地址与建连）`connect_failed`。一轮最多同时探 4 个供应商，两轮不重叠（定时一轮进行中点「立即探活」会等它结束）；探活读钥匙串用单独的名额，不占转发请求的名额。关闭开关时仍在进行的一轮不再写回结果；供应商的 key 被改动或删除、或这一轮因没有 key 被跳过时，丢掉它之前的探活结果。
- 并入状态：最新一次探活失败且比最近一次成功请求更新时，有请求的供应商至少降级、没有请求的判为故障，并把探活原因码加进 `reasons`；探活正常可让无流量的供应商显示为健康。
- 界面：供应商页列表上方一行「定时主动探活」开关、间隔与「立即探活」按钮；详情「健康度」一节显示最近一次探活结果。
