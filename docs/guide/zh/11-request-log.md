# 11. 请求日志

[← 常见问题](10-faq.md) · [目录](README.md)

在网关页点击「打开请求日志」，可以检查经过本机网关的请求。这里适合排查失败、限流、耗时和路由切换；普通工具日志的统计明细仍在[用量页面](03-usage.md)。

## 筛选与查找

时间范围可选最近 1 小时、24 小时、7 天或全部留存记录，再按客户端或 Agent、供应商、模型、状态和耗时筛选。状态包括成功、错误、发生重试、4xx、429 限流和 5xx；搜索框可查请求 ID、会话、模型和错误。

列表显示请求时间、客户端、目标与实际路由、状态、Token、预估费用、首 Token 时间、耗时和输出速度。不能计算的指标显示不可得，不补零。页面同时显示匹配条数、本机留存条数和最早留存时间；「全部」指当前仍保留的诊断记录。

## 展开一次请求

展开记录可以查看：

- **尝试顺序**：一次逻辑请求可能先失败再切换到另一成员；每次尝试分别列出结果和用量。
- **路由解释**：为什么选中该成员，其他成员为何被跳过、处于冷却或失败。
- **Token 与预估费用**：有效 Token 为输入加输出，缓存读写单列；费用根据本机价格表中适用的历史价格估算。
- **Context 构成**：系统提示、工具定义、对话历史、工具结果与附件的大小和计数；这是构成统计，不能据此还原原文。
- **请求标识与错误信息**：用于关联一次请求及其会话，核对上游错误。

零 Token 的失败请求和被网关跳过的尝试也可能出现在诊断里，不代表它们计入了有效用量。旧记录缺少 Context 或路由解释时，详情会保留缺失状态。

## 实时尾随与导出

开启「实时尾随」后，页面约每 2 秒刷新一次，窗口隐藏时暂停轮询。再次点击可停止尾随；「刷新」用于手动更新当前结果。

「导出 CSV」按当前筛选生成文件，便于离线分析。请求标识、模型、供应商和错误等元数据也可能暴露使用习惯，分享前应核对内容。

## 留存与隐私

请求日志只保存时间、状态、模型、用量、耗时和 Context 大小等元数据，不保存请求或回复正文，也不能用它恢复原始对话。

用量诊断日志在本机自动轮转，总量约 32 MB；路由决策日志单独轮转，因此旧请求的路由解释可能先过期。更早请求的用量仍保留在账本统计中，但逐请求诊断不保证长期留存。

当前页面没有手动清理日志按钮，自动轮转负责控制诊断文件大小。清空筛选只恢复列表条件，不会删除日志或账本。
