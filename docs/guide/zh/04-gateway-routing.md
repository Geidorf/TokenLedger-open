# 4. 网关与路由组

[← 用量页面](03-usage.md) · [目录](README.md) · 下一章：[预算提醒 →](05-budget.md)

模型网关是可选功能：TokenLedger 在本机 `127.0.0.1` 上起一个统一入口，各个 Agent 把请求发给它，由它转给你配置的供应商。好处是：

- 多个 Agent 共用一组供应商 key，key 只存一份；
- 每次请求都由网关记账，连日志里不写用量的工具也能统计；
- 可以把几个供应商的模型合成一个**路由组**，按规则选择，失败自动切到下一个。

不用网关也完全可以使用 TokenLedger 的统计功能。已经用其他工具管理 Agent 配置的话，保持关闭即可。

## 打开模型接入

**设置 › 模型接入 › 总开关**。打开后，顶栏才会出现 Agent、供应商、网关、路由四个页面。一般按「供应商 → Agent → 路由」的顺序设置。

关闭模型接入时，如果还有 Agent 指向本机网关，TokenLedger 会列出它们，并提供「恢复原配置并关闭」，避免关掉网关后 Agent 连不上。

## 供应商

![供应商](../images/providers.png)

供应商就是模型的来源，例如 OpenAI、DeepSeek、OpenRouter，或者兼容 OpenAI 接口的中转站与本机模型服务。

- 点「添加供应商」，选预置项或手动填写接口地址、协议（Responses 或 Chat）与模型列表，再填 API key。
- **API key 存在系统钥匙串里**（Windows 凭据管理器、macOS 钥匙串），只由网关读取，不写进设置文件，也不上传云端。
- 添加好的模型会以 `供应商/模型` 的形式出现在 Agent 与路由组的选择器里，例如 `deepseek/deepseek-chat`。
- 暂时不用的供应商可以停用，停用后保留配置但不参与转发。

### 健康度

已启用的供应商每行有一条 24 小时趋势条（柱高是请求量，红色顶部是失败占比）和一个状态徽标，鼠标指上去显示近 24 小时的次数、成功率、P95 耗时与原因：

| 状态 | 什么时候 |
| --- | --- |
| 故障 | 最近连续 3 次请求失败，或有成员连续失败 3 次仍在冷却 |
| 降级 | 最近一次请求失败，或有成员冷却中，或至少 5 次请求且成功率低于 90% |
| 健康 | 有请求且不属于上面两种 |
| 无流量 | 24 小时内没有经过网关的请求 |

点开供应商，详情底部的「健康度」一节列出成功率、P50 / P95 耗时、限流次数、错误原因与状态码分布、正在冷却的成员、各模型对比和最近 5 次失败（错误里的 key 片段会打码）。

健康度只统计网关自己记下的请求，**不会为了统计额外访问供应商**，也不上传云端；它只用来显示，不会自动把供应商移出路由组。网关自己拦下、没发出去的请求（例如还没填 key）单独计数，不算进成功率。页面每 30 秒刷新一次，窗口隐藏时暂停。

## Agent

![Agent](../images/agents.png)

列出本机能接入网关的 Agent（Codex、Claude Code、OpenCode、Gemini CLI、Kimi CLI 等），每行显示配置文件位置和当前状态。

- 在右侧「选择模型」里选一个模型或路由组。TokenLedger 会**先预览改动，确认后才写入**。
- 写入前会备份原文件，只改网关相关的键，其余内容和注释保持不变。写进 Agent 配置的只有网关地址和本地 token，没有供应商 key。
- 想撤销时点该 Agent 的恢复按钮，回到接入前的备份。
- 个别 Agent 的配置格式不公开或会被自己覆盖，这类只提供「手动配置」：复制网关地址与本地 token 后自己填进去。

## 网关

![网关](../images/gateway.png)

- **接入信息**：Base URL（默认 `http://127.0.0.1:3462/v1`）、本地 API 密钥（`tl-` 开头的本地 token）和可用模型，附 curl、Python、Node 示例，可以一键复制。网关同时提供 OpenAI Responses 与 OpenAI Chat 两种接口。
- **模型目录**：全部可用的模型与路由组 ID，路由组以 `group/` 开头。
- **最近请求**：时间、Agent、请求的模型、实际转发到哪里、状态码、Token 与耗时。「实际转发」一栏能看到路由组最终选了谁，以及是不是走了备选。

网关只监听本机地址，局域网里的其他电脑访问不到。端口被占用时，网关页会显示错误。

**不会重复计数**：同一次请求既可能出现在 Agent 自己的日志里，也会出现在网关账本里。TokenLedger 在本机按时间区间把两边合并，只算一次。

## 路由

![路由](../images/routing.png)

### 实时路由

页面顶部是实时路由舞台：左边是 Agent，中间是网关，右边是上游的 `供应商/模型`。请求经过时连线会流动；某个成员失败（例如返回 429 或 401），光点会在它那里弹回、标上状态码，再跑向下一个成员。舞台下方有一句话说明最近一次请求是怎么走的。

舞台只画真实记录，没有请求时显示空闲，网关没运行时显示原因，不会播放示意动画。系统开了「减少动态效果」时只保留点亮状态和文字说明。

如果本机还运行着另一个兼容的外部网关，舞台也会一起显示它的在途请求。

### 路由组

点「新建路由组」，给它起名（例如「编码主力」），它就会成为一个虚拟模型 `group/<名称>`，Agent 可以像选普通模型一样选它。

| 分配方式 | 行为 |
| --- | --- |
| 按顺序 | 总是先用第一个，失败才换下一个 |
| 轮流 | 新会话轮流分给各成员，失败换下一个 |
| 按权重 | 新会话按权重比例分给各成员，失败按权重从高到低换 |
| 固定一个 | 只用选定的成员，规则暂停 |

还可以：

- **加规则**：例如「请求带图片 → 先用某个支持视觉的模型」「输入超过 120,000 字符 → 先用某个长上下文模型」。规则命中时优先，命中的成员失败后仍按分配方式继续。
- **会话保持**：同一会话在一段时间内（例如 1 小时）固定用同一个成员，有利于命中供应商的缓存。
- **嵌套**：一个路由组可以把另一个路由组当成员；不允许成环。
- **冷却**：成员失败（例如被限流）后会暂时冷却，从 30 秒起、连续失败时逐次加长，最长 5 分钟；冷却期内跳过它，到期或成功响应后自动恢复。卡片上会标出正在冷却的成员。
- 右上角开关可以临时停用整个路由组。
- 每个成员前的小圆点是所属供应商的[健康度](#健康度)，子路由组成员没有圆点。

### 最近决策

右栏列出最近几次路由决策：选了谁、为什么（命中规则、会话保持、按顺序、按权重选中……），每个成员的结果（成功、失败已切换、上游拒绝、跳过、冷却中）。展开「为什么这样选」可以看每个成员没被选中的原因，排查「为什么总走备选」很方便。
