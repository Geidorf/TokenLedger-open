# TokenLedger · 产品需求与验收标准

> 产品行为以本文件为准；架构和字段实现见 `DESIGN.md` 与 `contracts/`。条目中的“现行…”“分期：…”只说明现行产品与目标的差距。任务状态与负责人由维护方的内部台账维护，不随本仓库发布（见 [`internal-collaboration-materials.md`](internal-collaboration-materials.md)）。
>
> 版本：v1.5 ｜ 2026-10-17（按代码核对修订）

## 1. 全局需求

### GLB-01 统计可信

- 主指标明确标注有效 Token（输入 + 输出）；缓存读/写、估算与供应商原始值不混用。
- 所有比较必须使用相同筛选、时区、Token 口径和桶定义。
- 缺失、旧 RPC、估算来源和 stale 数据需明确呈现，不用 0 掩盖未知。来源无法提供缓存写入时（目前是 Antigravity，本机 `cache_write_known = 0`），缓存写入显示为未知，不计为 0。
- 缓存节省类金额统一为「缓存净节省 = 缓存读取节省 − 缓存写入溢价」，按价格表估算、非账单，四端同一口径；读写拆分不可证明时不可得，不以读取节省（毛值）冒充；净值为负时照实显示（T10.162；T10.300f 收口桌面看板/缓存面板，消费校验后的缓存净节省，历史毛值仅保留字段兼容，Android 海报已改为缓存净节省（T10.184），分期见 `design/cache-savings-net-v1.md`）。
- 云端上一周期没有可验证记录时显示“基线缺失”并停止计算百分比，不得把缺失历史画成已知的零线；本机待上传记录数必须在云端看板可见。桌面云端视图与 Android 使用同一判定：上一周期记录数与有效 Token 均为 0 即视为未验证，不画上期线，不给百分比与方向色（T10.172；Android 由 T10.172 候选任务 C2 实施）。
- “数据已上传”与“云端汇总已刷新”是两个结果。后者失败时保留上传成功事实，同时用警告状态说明看板可能短暂不完整。

### GLB-02 跨端一致

- 桌面本地、桌面云端、Android 对相同范围/设备/工具/模型返回一致口径。
- 新契约对旧云端向后兼容；不支持的能力明确降级。
- 账本行的计数在所有端统一叫「记录数」（T10.156 §0.1），界面不再称“请求次数”或“N 次请求”；wire 字段仍叫 `requests` / `totalRequests`，不改名。部分来源一条记录就是一个会话；云端按小时聚合，云端明细的一行是一条「小时聚合记录」（用户决定，T10.172 Q7），不当作单次请求。会话逐轮分析里每轮的请求数计的是模型请求（`contracts/session-analysis-v1.md`），不在此列。T10.300f 收口桌面统计消费者叫法；网关尝试日志与会话逐轮保留真实请求语义，Android既有记录数消费者沿用同一契约。

### GLB-03 可访问与可恢复

- 关键操作支持键盘、读屏、48dp/44px 触控目标和 reduced motion。
- 加载、空数据、筛选无结果、离线、鉴权过期、服务失败分开呈现，并提供可执行的恢复动作。

### GLB-04 请求正确性

- 快速切换范围、设备、模型或工具时只允许最后一个请求写入界面。
- 退出登录后任何旧请求不得恢复会话或写回数据。

### GLB-05 视觉与主题一致性

- 桌面端以中性系统表面为主，品牌蓝只用于主操作、当前选择、数据线和键盘焦点，不把整块侧栏、页面背景或普通卡片同时染成强调色。
- 顶栏、正文、卡片、筛选控件和表格遵循统一间距与高度；1200×800 及以上窗口不出现肉眼可见的基线错位、重叠或无意义卡片套卡片。
- Light、Dark、Auto 使用同一份语义令牌与共享状态源。切换时 HTML、图表和原生窗口同步生效，不允许短暂混用两套颜色或通过卸载整张图表制造闪烁。
- 浮层、筛选弹窗和 dialog 必须使用不透明或足够高对比度的表面、边框和阴影；后方文字不得穿透到选项内容中。
- 动效只说明状态变化，常规内容刷新不逐卡重播入场动画；`prefers-reduced-motion` 下关闭非必要动画。
- 工具颜色绑定工具身份，也不作为唯一线索，必须同时显示工具名；深浅两色下图形对比度 ≥3:1，按图表实际绘制的透明度计算。桌面与 Android 共用一张「工具 → 图表槽位」表（用户决定，T10.173 V-Q6；槽位表见 `design/android-visual-refresh-v2.md` §3.8）：每个工具固定一个槽位，不随排名变化；同一产品的别名同槽，未登记的工具按名字哈希落槽；同一视图里两个工具撞槽时，排名靠后的顺延到下一个空槽（按排名确定、可复现）。槽位共 8 个：同一视图不超过 8 个工具时，不同工具不同色（root 决定 R-3）；超过 8 个时的处理由 T10.178 定。现行：桌面为 T10.161 的逐工具色表（每个工具一色、别名共色、未收录工具用中性色，见 DESIGN §4.4），改用槽位表由 T10.178 实施，同时复核 T10.161 的对比度与色差并改写相应测试；Android 给四个固定工具指定颜色，其余按名字哈希对 4 取模（`stableToolColorIndex`），第 5 个工具起必然撞色，改为槽位表随 T10.173 的视觉任务（A0，T10.177）实施。

### GLB-06 系统副作用须显式授权

- 新安装不得默认修改桌面、锁屏或动态壁纸，应用启动、扫描和云同步也不得间接触发壁纸写入。
- 旧配置缺少当前授权版本且仍启用壁纸时，自动化必须暂停并提示用户确认；确认保留后才恢复，拒绝后关闭全部壁纸目标。
- 授权状态必须跨 Rust 设置与 TypeScript UI 一致；仅修改开关而未确认授权不能绕过调度器。

### GLB-07 云端引导与故障恢复

- 云端入口依次说明连接配置、登录、Stats v2 能力和首次同步四个阶段；不得要求普通用户直接执行仓库 `schema.sql`。
- 云端读取失败时保留当前云端作用域和最后可信数据，区分离线、鉴权过期、旧契约与服务失败，并提供重试、重新登录和临时查看本地的独立动作。
- 临时查看本地是用户显式动作，不能由异常处理静默切换；密码在成功、失败、退出和界面卸载后均不得继续保留。

### GLB-08 本机显示偏好

桌面首页提供“调整显示”，可按稳定模块 ID 显示／隐藏和上下排序结论与核心指标、额度与速度、趋势、提醒与异常、工具与模型排行、订阅回本与活跃日历，额度来源也可独立显示与排序；有效／含缓存 Token 口径开关也在这里。偏好仅在本机持久化并支持恢复默认；隐藏不停止采集、读取或同步。至少保留一个模块及一个当前来源可见；新来源默认追加，新模块插到默认顺序中的位置，暂时消失的来源恢复后保留原偏好。控件支持键盘、44px 触控目标与焦点恢复。总览默认只在额度与速度条中显示最紧的至多 3 个百分比额度窗口（容器变窄时减为 2 个或 1 个），完整额度列表在其下方展开，展开状态本机记住。旧版已存的模块偏好（含多维行为模块与“消费洞察”模块）应安全迁移，独立行为分析不受首页模块显隐控制。

现行概览由卡片组成（统计条、额度要点、趋势、额度详情、用量拆分、预算、消费洞察、平均 Context 构成、时段规律、热力图、Agent 用量），可拖动或用键盘排序、隐藏、调宽（全宽、半宽、三分之一），可保存多套布局（内置「日常」「省钱」）并一键切换、另存、改名、删除，每套可恢复默认；布局只存本机，旧版模块偏好自动迁移；“调整显示”管理当前布局的卡片与额度来源，默认连续额度列表不变，Token 口径开关在顶栏；以上目标由信息架构 v2 的实施任务负责（方案 T10.156，`design/analytics-ia-v2.md`）。

### GLB-09 设置与桌面呈现（T10.115）

- 设置按用户任务展示单个分区，常用偏好优先；搜索可按壁纸、启动、额度等自然词定位。稳定哈希保留深链和前进后退，切换后标题与内容可见；离开账户分区清除密码，价格等非敏感编辑草稿保留。
- 保存方式就近说明：开关和扫描/壁纸间隔自动保存；账户、接口、价格与订阅仍需显式提交。保存失败必须回读实际值，已保存但系统应用失败独立提示并提供重试。
- 桌面壁纸只有一个总开关；macOS 呈现方式为动态桌面或静态图片，Windows 只有静态图片，不做动态桌面（用户决定 U-15）。关闭总开关保留方式偏好，但明确显示暂停，不把动态方式选中等同于运行。云端数据未就绪时说明原因，仍允许用户主动改用本机，不隐式降级来源。
- 动态桌面保留主显示器系统底图，以克制中性阅读层显示时间、有效 Token、输入/输出、缓存、预估费用、记录数（现行界面仍叫“请求”，随信息架构 v2 改名）和走势；没有持续装饰动画或调试计数器。数据身份、来源和历史状态必须真实，切换来源失败不能沿用另一来源数字。阅读层将改用与托盘挂件、桌面小组件同一套卡片，工具以显示名、配色 B 与份额呈现，不显示内部 ID；换皮前先在真 Mac 上按 `design/desktop-widgets-wallpaper-visual-v1.md` §3.3 清单验一次，窗口层级、桌面空间与全屏或外观检查不过则下线动态桌面、只留静态图片（用户决定 U-14，未实现，W6）。静态壁纸与锁屏只换配色 B、「有效 Token」「记录数」叫法与「较昨日同期」口径，不改版式（U-16，W7，T10.195 已实现）：昨日截到当前时刻，本机与云端两种来源同一口径；基期为 0 时写「新增」或「持平」；读取失败时与其他未知值一样显示「不可得」，不按 0 画。云端上期记录数与有效 Token 均为 0 时，壁纸目前也写「不可得」，改为与看板一致的「基线缺失」归 T10.210；活跃度热力图仍是旧的绿色色阶，改为与看板年度日历同一分档与配色也归 T10.210。
- 动态桌面仅覆盖主显示器，不抢焦点、不拦截桌面点击，位于系统背景之上及桌面图标之下；退出应用后消失。静态方式不得创建动态窗口，系统应用失败不得提示成功。
- 设置页壁纸分区常驻显示当前设置下的壁纸效果预览（缩略图，用户决定 U-103）：静态方式用与真实壁纸相同的渲染器和统计口径（有效 Token = 输入 + 输出，缓存单列），动态方式内嵌缩小的动态桌面；按屏幕比例显示并标注「预览，未应用到桌面」与分辨率，设置或数据变化时防抖刷新。生成预览不得修改系统壁纸、不得写壁纸文件、不得要求壁纸授权或触发系统授权弹窗；区域只有一张图和一行状态。
- 清理历史壁纸只删除应用自有历史图片，保留current图片和用户设置；不得删除macOS Dock数据库、重启Dock或重置其他桌面配置。

### GLB-10 独立本机行为分析（T10.149）

桌面导航提供独立「行为分析」视图，覆盖工具、会话、模型、日期与小时，以及用户开启后的项目维度（GLB-13）。页面与总览共用同一个时间范围控件与范围词汇：行为页主分段为今日、近 3 天、近 7 天、近 30 天，其余预设与自定义日期闭区间在“更多”中；“近 N 天”包含今天，按所选时区的日历日计算并随日期滚动。页首为确定性规则生成的结论条，其后是不带同期变化的核心指标、日期×小时热力（附小时与每日边际，可切换星期×小时）、构成随时间、会话表（开始、时长、工具、主模型、有效 Token、会话预估费用、记录数）与默认折叠的单条记录规模。所有图表与摘要使用相同筛选、时区和有效 Token 口径，范围切换后仅显示当前请求结果。工具与会话、日期×小时、模型分时与每日用量从本机完整账本聚合，不得由首页 `history` 的有限条数推断全量。显示账本实际覆盖、空数据与截断排行；缺少会话 ID 的记录不计为会话并注明条数，工具行同样注明，整源缺失时显示“会话未知”；“全部”最多分析最近 731 天并注明截断；会话排行提供预估费用、起止时间与主模型（仅本机）；行为数据随本机扫描或同步完成自动刷新（窗口重新可见时只在有更新或跨日时重算），同一查询刷新不清空当前结果。图表提供可识别的提示与图例，热力可用键盘操作并有 44px 的等价选择路径；页内选择与下钻不改写全局时间范围。云端不具备完整行为分析来源时明确说明，只显示由 Stats v2 完整聚合得到的星期节奏、工具构成与突增，不以样本冒充全量。数据契约见 `contracts/behavior-analysis-local-v1.md`。

T10.268 起（用户决定 U-89、U-90、U-95），侧栏把「总览看板」与「行为分析」合并为一个「用量」入口，页内子标签为概览、记录、行为分析（T10.274 起，用户决定 U-100：子标签由「会话」改名「行为分析」，侧栏「用量」下常驻展开同名三个二级入口，当前子页高亮、点击直达，窄栏只保留「用量」图标；旧锚点 `#behavior` 仍直达行为分析；T10.277 起，用户决定 U-101：子页只由侧栏二级入口切换，页内子标签删除，窄栏点「用量」图标弹出三项菜单，顶栏标题为「用量 · 子页」面包屑）：概览保留原总览的全部模块（含范围切换、Token 口径开关、调整显示、分享），页首补一行结论句与本期预估费用；行为分析子页即上述行为分析，范围与功能不变；记录逐行列出当前范围内的本机记录（时间、工具、模型、供应商、来源、输入、输出、缓存读、缓存写、预估费用），带汇总行与加载更多，复杂筛选与搜索仍在「活动明细」。主数字仍是有效 Token，缓存单列。本机网关记账存在时，看板按 Stats v2 §2.5 并入网关记录，与日志扫描重复的记录以网关为准，记录页标注来源与供应商；T10.273（U-96）起，云同步也按同一规则合并：桌面先去重，再上传小时聚合，因此云端看板与 Android 的数字包含网关记录且与本机同口径；上传内容仍只有小时聚合，不含会话、供应商、key 或请求内容。同一账号仍有旧版桌面上传的小时保持纯扫描口径。

2026-10-23 起（用户决定：用量分析全面对齐 magpie Usage 页，方案见 `docs/design/usage-analysis-magpie-v1.md`），「用量」子页改为概览、请求、会话、额度四项，取代上段的三项划分：原「记录」与一级入口「活动明细」合并为「请求」（保留活动明细的精确筛选、搜索、展开详情与整段会话分析，展开行补来源与供应商），侧栏不再有「活动明细」一级入口；原「行为分析」按 magpie 改名「会话」，范围与功能不变；完整订阅额度从概览移到「额度」，概览只留额度要点，点「查看全部额度」直达额度子页。旧锚点 `#records`、`#logs` 落到请求，`#behavior` 仍落到会话，新增 `#requests`、`#allowances`。四个子页共用一个顶栏，范围与设备控件都在页内工具行。magpie 的 Context（逐请求提示词构成）需要本机与云端都没有的数据，本期不设入口。

T10.306f（用户 2026-10-05 PC 体验专项授权）调整宽侧栏的呈现：用量成为分组标题，概览/记录/行为分析与模型接入页面采用同一图标、字号和选中规则，不再有重复父入口；窄栏菜单与页内无标签保持。三页提供统一可见页面标题，报表文字不低于11px。macOS 托盘弹窗所有入口优先锚定顶部菜单栏，无法取得图标位置时顶部兜底，不改变独立桌面常驻小组件的用户位置。

2026-10-23 起（用户决定：桌面视觉与导航整体对齐参考设计），侧栏取消：一级入口改为窗口顶栏中间的分段（Agent、供应商、网关、路由、用量；模型接入关闭时只剩「用量」），设置是顶栏右侧齿轮；用量的概览、请求、会话、额度四个子页由页头二级分段「用量子页」切换，当前项高亮并对读屏标明当前页，取代侧栏二级入口、窄栏菜单与「用量 · 子页」面包屑。窄窗口逐级收起顶栏标题、状态文字与快捷工具，两级分段始终可用；所有可点控件命中区不小于 44px（GLB-03）。上文关于侧栏与面包屑的描述以本段为准。

缺少会话 ID 的计数、731 天上限、会话费用与起止时间、主模型与刷新规则由 T10.151（后端与 hook）和 T10.164（界面）实现。现行页面仍用页内时间栏选择区间；共用范围控件、结论条、构成随时间、会话表、项目维度与云端降级页由信息架构 v2 的实施任务负责（方案 T10.156）。

### GLB-11 预测类指标（D2，T10.153）

预测类指标（周期末预测、额度消耗速度）只用已完成的时间段线性外推，界面单独标“预测”，数值与计算方法、范围同时可见；未经真实数据校准的范围不标覆盖百分比；外推结果只叫“预测”，不叫“预估”（“预估”只指按价格表估算的费用）；样本不足、来源未知或时间线不可信时说明原因而不给数字，未知值不按 0 参与计算。预测不进入云同步、分享海报、HTML 简报、CSV 导出、复制图片、壁纸、锁屏、动态桌面、托盘提示文字、Android Launcher 小组件与全屏摆件；桌面托盘挂件与桌面小组件首版也不放预测（以后只考虑最紧窗口的一行速度，见 `design/forecast-and-pace-v1.md` §6）。预测触发的系统通知必须由用户显式开启并限频。

分期：桌面趋势卡的周期末预测（REQ-COMP-04）与额度面板的消耗速度（REQ-QUOTA-06）先在桌面提供（T10.153 规则、T10.159 接入）；Android 在桌面稳定一个版本后再移植（用户决定，T10.172 Q5）。现行没有预测触发的系统通知（REQ-QUOTA-07）。

### GLB-12 费用口径与订阅回本（T10.154）

- 所有端的金额主标签统一为「预估费用」，短注「按价格表估算，非账单」；预估费用按模型价格表估算，工具日志自带费用时直接采用。不再使用预估成本、估算成本、预估总成本、预计成本、花费成本、花费金额等叫法。「预估」只指价格表估算，外推值一律标「预测」（GLB-11）。
- 用户可在桌面设置中登记订阅：名称、服务商、订阅费、币种、计费周期与计费日、起止日期、覆盖的工具，可选模型前缀与设备。登记后预估费用拆为「API 等值」（订阅覆盖）、「预估支出」（标为按量付费的工具）与「其余」（未设置付费方式）；每条记录只归一类，三者之和等于预估费用。未被订阅覆盖、也没有标为按量付费的工具不默认视为按量，归入「其余」（用户决定）。两个订阅在同一时段覆盖同一类记录时拒绝保存。设置文件里无法识别的订阅条目逐条丢弃，日志只记条数，不改写成默认值；汇率无法识别时人民币换算显示「不可得」，直到用户重新保存汇率（T10.188）。
- 回本倍数 = 一个计费周期内该订阅覆盖记录的 API 等值 ÷ 该周期订阅费。它只按计费周期计算，不随看板所选范围变化，出现时写明计费周期。进行中的周期用全额订阅费并显示已过天数，不做外推；订阅在周期中途开始或结束时按日历天折算订阅费，并写明折算天数。只陈述数字，不做「划算」一类评价。
- 人民币订阅费按用户设置的固定汇率（默认 1 美元 = 7.2 元）折成美元，经过换算的数字注明汇率；不联网获取实时汇率。
- 任一参与计算的金额缺失、非有限或为负时，对应的预估费用、API 等值、预估支出、其余与回本倍数显示「不可得」，不按 0 显示或参与合计；真实 0 照常显示。
- 未登记订阅时，各表面数值与改动前一致，只更换叫法并加短注。订阅设置经专用云端表在本人设备间同步（用户决定，方案 ②）：登录云端后默认同步，可在设置中用「同步订阅设置到我的设备」关闭（用户决定 S-Q1）；同步时只允许本人读写，按版本条件更新，删除留墓碑，旧客户端不受影响；未登录、同步已关闭或云端未部署时只保存在本机。关闭同步时询问是否同时删除云端副本，默认保留（用户决定 U-1）；「删除全部订阅设置」连同云端副本一起删除，写删除墓碑，其他设备随之删除（U-2）；登录云端后的第一次默认同步前提示一次，不拦截（U-3）。订阅设置不写入日志与 CSV 导出。Android 在接入订阅同步之前只统一叫法、显示预估费用，不显示拆分与回本；拆分与回本在桌面稳定一个版本后再移植，与预测类指标同一节奏（用户决定 S-Q2）。
- 「隐藏费用」偏好（原「成本隐身」「隐藏金额」）同时隐藏金额及由金额算出的占比与倍数。分享海报首期不展示回本倍数（用户决定）。额度页的订阅额度窗口与订阅费、回本倍数是两条事实链，不互相推算或合并展示。设置入口为「费用与订阅」分区（原「模型价格」更名，用户决定）。口径、文案与实施拆分见 `design/cost-naming-subscription-v1.md`。
- 分期：叫法与未知值统一（A 期）、桌面订阅登记与回本（B 期）、订阅同步与 Android 的拆分和回本依次实施，Android 的拆分与回本在桌面稳定一个版本后移植（用户决定 S-Q2）。现行界面没有订阅登记、回本与同步；订阅设置的本机模型、校验与读写命令已实现（T10.188，契约 `contracts/cost-profile-local-v1.md`），设置页登记随 B4。桌面与托盘的叫法和未知值已按 A 期统一（T10.186）；设置分区更名「费用与订阅」随 B 期，现仍叫「模型价格」；Android 仍有「成本」「金额」等旧叫法，随 A3 统一。
- CSV 导出的 `cost_usd` 是账本原值：账本没有存费用时留空，不写 0，也不表示免费（只用本机、未登录云同步的用户这一列大多为空）；看板读取时按价格表现算，所以两者可以不同（T10.154 D70，T10.186）。紧跟其后的 `estimated_cost_usd` 与总览「预估费用」同一口径（用户决定 U-11，T10.196）：账本存的费用非负且有限时与 `cost_usd` 相同，账本没有存费用时按看板同一价格表（含用户价格覆盖与自动发现的待核价项）和同一兜底规则逐行现算，缓存读写分开计价；价格表查不到任何价格时留空，账本存的金额为负或不是有限数时也留空，不写 0，也不改用价格表估算（R-64，T10.205）。这样的行在总览「预估费用」与明细合计里同样记为不可得；明细合计与总览共用同一逐行估价（T10.205）。同一批记录的 `estimated_cost_usd`（美元）之和等于本机总览对这些记录给出的预估费用（差别只在浮点求和顺序；总览「全部」只到当前时刻），由测试锁定。

### GLB-13 本机项目维度（T10.155、T10.165）

- 行为分析可按项目查看用量，但项目维度默认关闭；只有用户在设置「数据与帮助」中阅读“会读取 / 不会读取”说明并确认后，才开始读取工作目录（用户决定）。说明须逐一列出读取的日志字段与元数据文件，其中扫描器本身不打开的三类元数据文件是 Gemini CLI 的 `.project_root`、Kimi Code 与 Kimi Desktop 的 `state.json`、`session_index.jsonl` 与 `workspaces.json`，以及 DeepSeek GUI 的 `metadata.jsonl`（用户决定接受）。读取范围扩大时须提升授权版本，旧授权暂停采集，直到用户重新确认。
- 只保存一个文件夹名或固定分组，不保存完整路径、盘符、用户名或路径哈希（用户决定）；不提取、不保存对话内容，不读取分支、提交或远程地址。文件夹名取会话工作目录的末级名称；常见 worktree 目录与来源记录的仓库根取仓库所在的文件夹名，仓库自身的文件夹名即视为末级名称。git 探测按用户决定关闭，在仓库子文件夹或自建 worktree 里启动的会话按各自的文件夹名归属；开启 git 探测须另行决定并提升授权版本。主目录、存放主目录的上级文件夹（如 `C:\Users`、`/home`）以及与本机账户名同名的文件夹只记“主目录”；磁盘根目录、临时目录与工具托管目录只记固定分组。能识别的主目录写法及其上级不论由哪条规则得出，都不作项目名；能识别的写法包括：本机主目录的长名、短名与物理路径（主目录本身是符号链接或目录联接时），Windows 的 `HOME`、`HOMESHARE` 与 `HOMEDRIVE`+`HOMEPATH`，以及任何账户的常见主目录（含 UNC 共享上的 `Users\<名>`、主目录共享与 WSL 路径）；会话路径或来源仓库根途经的常见主目录，其账户名同样不作项目名。仍认不出的有两种：从别处指向主目录、且被工具按逻辑路径记录的链接；其他账户位于非常见位置的主目录（T10.165 P3 隐私修复轮）。
- Antigravity、腾讯 Marvis 等来源不记录工作目录，其会话照实显示为“未归属”，不按内容推断项目（用户决定）。
- 项目数据只在本机，不进入云同步、Supabase、Stats v2、Android、分享海报、HTML 简报与 CSV 导出，由回归测试锁定。
- 关闭后立即停止读取，并删除已保存的全部项目名；数据库日志中的残留在截断受阻时于下一次扫描清除。重新开启时从空索引重建。
- 无法归属的用量按原因（来源不记录、无法确定、尚未建立索引、缺少会话 ID）显示为“未归属”，不得并入任何项目，也不得显示为 0；项目占比的分母包含未归属。
- 首版提供「隐藏项目名」显示开关（用户决定）：开启后项目名与项目键都不渲染，包括可见文字、提示、读屏标签与持久化的筛选状态，项目改用不含名称的代称（如“项目 1”）；只改显示，不改索引与存储。
- 本机项目索引后端由 T10.165 实现（本机库 schema v13），行为分析的项目聚合由 T10.182 实现（行为契约 v1.2：项目排行、按原因分列的未归属、会话项目与可选项目筛选；未开启或授权版本过低时不返回任何项目内容，带筛选返回 `project_dimension_disabled`；本机索引读不出来时，不带筛选省略项目维度、照常返回其余字段，带筛选返回 `project_dimension_unavailable`）。现行源码已接入设置「数据与帮助」→「按项目统计」入口，用户阅读读取范围说明、打开「按项目统计本机用量」开关并确认「开启并建立索引」后，由 `useProjectDimension` 调用 `set_project_dimension`；行为分析的「了解并开启」只跳转到该设置卡片。PD-7 对应入口已接线，但真实平台上的开启、索引与「隐藏项目名」显示验收仍待完成（`design/project-dimension-v1.md` §9）。

### REQ-DETAIL-01 模型与设备筛选（P0）

用户可以通过筛选控件选择一个或多个模型、设备；可同时按工具与文本搜索缩小结果。筛选状态需要可见、可一键清除，并展示命中条数与筛选后总量。

验收：

1. 点击明细中的模型或设备标签会加入/切换对应筛选，不丢失当前范围。
2. 桌面本地模式在完整本地数据上筛选；云端模式不得只筛当前 200 条返回结果后冒充完整结果。
3. 无结果显示筛选条件和“清除筛选”，不是空白表。
4. URL/页面状态或明确的可恢复状态保留下钻上下文；关闭详情返回原筛选位置。
5. 模型、设备、工具的多选与文本搜索必须在本地/云端数据源层执行；趋势比较、明细、facet 和实体看板复用同一规范化查询，不允许客户端只过滤当前页。
6. 空数组表示“不限制该维度”；旧单值调用在兼容边界规范化为单元素数组，跨端不得产生不同空值语义。
7. 桌面云端“全部设备”看板展示设备排行，可在有效 Token 与预估费用间切换，至少包含主值、占比与记录数，并跟随范围、工具、模型和搜索条件。单设备查询、本地模式或旧云端缺失该能力时隐藏，不得从最近 200 条明细推算完整分布。（费用档与“记录数”叫法随信息架构 v2 实现；现行设备分布显示有效 Token、占比与请求数。）

### REQ-DETAIL-02 明细详情（P1）

单条记录可查看输入、输出、缓存读/写、预估费用（未知显示不可得；单条记录不足 1 美元保留 4 位小数，其余两位，T10.186）、时间、工具、模型、设备、会话 ID 与数据是否估算；敏感原始日志内容默认不展示。云端明细是按工具、模型、设备与小时聚合的记录，没有会话 ID；桌面云端视图与 Android 称之为“小时聚合记录”，不显示会话 ID，也不提供按会话过滤（用户决定，T10.172 Q7；Android 由 T10.175 实现，桌面现以“云端小时聚合”标注粒度）。

## 3. 同期趋势比较

### REQ-COMP-01 自动上一周期（P0）

- 今日：以本地时区小时桶，将今日截至当前时刻与昨天相同时刻比较。
- 本周：以周一为首日，将本周截至当前星期/时刻与上周等长窗口比较。
- 本月：按自然日位置，将本月至今与上月等长窗口比较；若上月天数更短，只比较双方共同存在的日序。
- 今年/全部：默认不伪造同比；核心指标的变化位显示“暂无自动基线”，后续另立年度比较需求。

验收：

1. 当前线与上一周期线使用稳定颜色、不同线型和直接图例；tooltip 同时显示两期与差值。
2. 总量、记录数与预估费用的绝对变化和百分比直接显示在核心指标卡上，同一问题只回答一次（趋势卡不再重复总量行）；日／小时均值只平均已经结束的桶，并与上一周期同样数量的桶比较（总览只有这一种日均）。基期为 0 时显示“新增”或“持平”，云端无法证明上期基线时显示“基线缺失”，任何情况下都不显示 0% 或 ∞；变化使用中性色、箭头与正负号，不以红绿表达好坏。
3. 设备、工具、模型、有效/含缓存口径变化后，两期使用完全相同的筛选。
4. 图表说明比较窗口，不把不完整今日与完整昨天、月初与完整上月直接误导比较。
5. 本周、本月与多日自定义区间都可以在逐日与累计走势之间切换；本机“全部”走势标明只显示最近 31 天，云端标明按全部历史逐日绘制。
6. 核心指标卡的主值与同期变化必须描述同一窗口；月末同期截短、两者窗口不同时，变化处写明对齐截止日（如“较上月同期（截至 3月28日）”）。

验收 2、5、6 与中性变化由 T10.159 在桌面实现。现行界面把记录数写作“请求次数”、把顶栏的“全部”写作“总计”，随信息架构 v2 改名；Android 的变化与基线说明按 T10.172 Q3 补齐。

### REQ-COMP-02 可读结论（P1）

总览首屏顶部用确定性规则生成一至两行结论句，依次说明本期有效 Token 与同期变化、预估费用与主要来源、最紧额度窗口的剩余与重置时间、待处理提醒数，例如“本周有效 Token 12.3M，较上周同期 +18%，预估费用 ≈$42.10，主要来自 Claude Code（61%）；最紧的 Claude 每周额度剩 23%（偏紧），周六 10:00 重置；有 1 条提醒。”行为分析页顶部的结论条按同样原则说明高峰时段、最忙的星期或单日、最重的会话与活跃天数。

验收：

1. 不调用生成式 AI，不夸大样本；无法评估的规则不写成“正常”，基线缺失时写明不计算变化。
2. 结论句不含预测值与回本倍数；若复用到导出，预测内容一律剔除。
3. 1280×860 与 1200×800 窗口下，结论句、四个核心指标与额度与速度条不滚动即完整可见。
4. 结论句随核心指标模块（`kpi`）一起显示或隐藏，不单独设开关（用户决定）。

现行总览已有用量与费用结论。T10.306k 在核心指标下、趋势前补充最多三个可读百分比窗口的额度速览，尊重核心指标、额度模块与来源显隐；历史值明确标注，点击可到完整额度列表。两种规定窗口尺寸已在匿名浏览器 fixture 验证首屏可见；完整信息架构 v2 的速度条、提醒汇总和整段结论验收仍由方案 T10.156 的实施任务负责。

### REQ-COMP-03 自定义日期区间复盘（P1）

- 总览与行为分析共用同一个范围状态与顶栏控件，只是主分段不同：总览为今日、本周、本月、今年、全部，行为分析为今日、近 3 天、近 7 天、近 30 天。分段最后是“更多”菜单，内含三类：一是另一页的主分段项，其中近 3 天、近 7 天、近 30 天含今天并随日期滚动；二是常用区间（昨天、上周、上月、本季度、上季度）；三是“自定义…”，由用户输入起止日期。自定义区间为本地日期闭区间，`start ≤ end`，最长 731 天，开始日期不晚于今天。
- 自定义区间对主看板、同期趋势、消耗明细、专属看板、战报与简报统一生效；同期对比取紧邻其前、等长的区间，并与预设范围一样按同一进度对齐（区间跨越“现在”时截到现在）；单日区间用小时桶，其余用日桶。
- 自定义区间是查询身份的一部分：`meta.query` 回显 `start/end`，缓存快照与明细游标不得混用不同区间的数据。
- 云端汇总在 RPC 支持前不得伪造结果。桌面（T10.185 起）与 Android（T10.113 起）在云端 scope 下都按 `start/end` 直接查询自定义区间与单日复盘，切换作用域时保留所选区间，不改用预设；开始日期晚于所选时区今天的区间在本地直接拒绝并说明原因。云端未部署日期迁移 `20260905162953`（缺少 v2 签名，或对 custom 报 HTTP 400、SQLSTATE 22023、`query-v2: invalid range custom`）时，桌面显示「云端范围受限」并说明可切到本机或选择预设，Android 显示“不支持自定义日期范围”；两端都不得显示「云端服务暂不可用」或 0，不得以预设或局部筛选冒充所选区间，旧 `_v1` 入口不承接 custom。预设范围保持可用。
- 桌面云端的单日与自定义区间复盘由 T10.185 实现（用户决定）：旧 RPC 回退时把单日与自定义区间视为不可表达；云端未部署日期迁移时显示「云端范围受限」。生产库已于 2026-09-25 经只读查询确认有该迁移（Supabase 迁移工具记录的版本号为 `20260905234547`，用户决定 U-10）。
- 自定义区间下的年度日历画区间里最后一个已查询日期所在的年（结束日期晚于今天或快照截止日时先截断）。区间外、快照截止日之后且响应中没有记录的日期显示为“未查询”（不可点击，读屏读“未查询”），不得画成 0，并在日历中说明只查询了哪一段；不为此追加年度查询（T10.161，桌面已实现）。

验收：

1. 顶栏“更多”按钮可用键盘打开菜单（`aria-haspopup="menu"`），其中“自定义…”打开日期弹层（`aria-haspopup="dialog"`）；Escape 关闭并把焦点还给触发按钮。当前范围不在主分段中时，范围名称显示在“更多”按钮上（如“近 7 天”“8/1–8/31”）；任何时候都有一个分段处于选中状态。
2. 起止倒置、超过 731 天或格式无效时给出明确错误且不发请求。
3. 同一区间来回切换命中同一缓存快照；不同区间不会互相冒充“最近可信数据”。

现行顶栏的第六段是“自定义”（`aria-haspopup="dialog"`），本机与云端 scope 都查询所选自定义区间（桌面云端自 T10.185 起；旧云端显示「云端范围受限」）；共用范围控件、“更多”菜单与近 N 天相对范围由信息架构 v2 的实施任务负责（方案 T10.156）。

### REQ-COMP-04 周期末预测（P1）

本月、本周与多日自定义区间的趋势卡显示期末有效 Token 与预估费用的预测：按已完成日的日均外推，给出粗略范围与方法说明（写明假设之后的用量与已完成的日子相近，不标覆盖百分比），今天只作为不低于已记录量的下限。月与自定义不足 7 个完整日、周不足 3 个时显示还差几天、哪天起给出预测；已完成日有未知费用或云端未提供逐日费用时，费用预测显示不可得而 Token 预测照常。月末几天后端截短本期同期序列、统计快照是缓存或云端来源不完整时，不显示预测数字，只说明原因。今日、今年、全部不提供预测。

验收：

1. 同一数据在不同宿主时区下结果一致。
2. 预测与范围下限不低于本期已记录量。
3. 数值出现时“预测”标签、范围与方法同时可见，Token 写作“有效 Token”。
4. 预测不出现在海报、简报、导出与同步数据中。
5. 月末同期截短的日子（例如 3 月 29–31 日）不显示预测数字，只说明原因。
6. 云端作用域只在明确知道本机没有待上传记录时预测；待上传记录数未知时按不完整处理，并写明原因。

分期：桌面先做（T10.153 规则、T10.159 接入）；Android 在桌面稳定一个版本后移植（用户决定，T10.172 Q5）；月末截短的后端根治另立任务。

### REQ-COMP-05 提醒与异常（P1）

总览在趋势之后提供「提醒与异常」，只在规则触发时列出可处理事项：用量突增（沿用突增侦测规则）、待核价模型、缓存复用率较上期骤降、额度告急（剩余 <20%）、照此速度会在重置前用完（预测）、周期末预测明显高于上月（预测）。规则由确定性纯函数实现，不调用生成式 AI；阈值先写成常量，以后再开放调整（用户决定）。

验收：

1. 每条显示严重度文字（需处理／留意／信息）、说明与可执行动作；预测类提醒必须标“预测”，并可查看方法与范围。
2. 用户可忽略或稍后 24 小时。忽略按提醒身份记住（额度类到下个窗口自动失效），可在“已忽略”中恢复；状态只存本机，不同步。
3. 无事时只占一行，写明已检查的规则数与本期无法评估的规则数；数据不足的规则记为无法评估，不写成正常。
4. 提醒跟随额度来源与模块的显隐；提醒与系统通知各自去重，通知规则以 REQ-QUOTA-07 为准。

现行看板没有「提醒与异常」模块，突增在「时段行为」组的突增侦测面板里；本条由信息架构 v2 的实施任务负责（方案 T10.156）。

## 4. 模型与工具专属看板

### REQ-DRILL-01 工具专属看板（P0）

从工具排行、趋势图、明细或筛选结果进入。展示当前/上一周期趋势、输入/输出/缓存构成、预估费用、记录数、均值、峰值、模型占比、设备占比、活跃日历和相关明细，以及该实体占总预估费用的比例与单位费用（每百万有效 Token 的预估费用）；占比只在与总览同一作用域、同一查询且两份统计生成时间相近时显示，否则整项隐藏，不用 0 或“不可得”掩盖不可比（T10.163，桌面已实现）。模型/工具/设备分布卡片可在“有效 Token”与“费用”两种对比口径间切换：条形、排序与首位数字随口径变化，每行同时给出占比、另一口径与记录数；最近明细每行在 Token 之外显示预估费用（T10.111）。现行界面把记录数写作“请求次数”或“N 次”，随信息架构 v2 改名。

### REQ-DRILL-02 模型专属看板（P0）

从模型排行、明细或工具看板进入。展示同等指标，并说明该模型由哪些工具与设备使用。模型 ID 必须完整可复制，别名与原始 ID 不混淆。

### REQ-DRILL-03 可组合上下文（P1）

专属看板继承范围、设备与 Token 口径；从工具看板点模型时形成“工具 + 模型”组合筛选。返回时恢复原页面、滚动与筛选。

### REQ-DRILL-04 模型费用分布报表（P1）

总览的模型排行提供“Token／费用／单位费用”三档。费用档中全部模型（当前范围的完整模型列表，不得复用 Token 排行截取的前 N 名）按预估费用降序排列，预估费用不可得的显示「不可得」并排在最后；默认显示前 8 行，其余模型合成「其余 N 个模型」合计行并写明合计与占比，可原地「展开全部（N）」；只有汇总总费用超出全部模型已知费用之和的部分才可称为「无法归属」。每行展示模型名、预估费用、费用占比、有效 Token 与复用率，并用与所选档一致的横向数据条表达相对量级；记录数与命中缓存（读缓存）量在展开区给出。展开单个模型，展示该模型的命中缓存消耗分布——未命中输入、输出、命中缓存读、缓存写的 Token 构成、该模型预估费用、记录数与复用率（读缓存 ÷（输入 + 读缓存））；点击行进入模型专属看板。桌面模型排行与 Android 模型专属看板使用同一统计口径；桌面以 USD、Android 以人民币呈现，隐藏费用偏好只作用于金额显示，不改变底层统计或下钻。2026-10-24 起 Android「用量 › 来源」页改为「用量拆分」，对齐桌面概览的用量拆分：维度 Agent／模型／设备／账号，指标 Token（标明有效或含缓存口径）／记录数／预估费用；合计与占比的分母是同一响应的汇总值（`summary`），行值不可得时写「不可得」并排在最后，不按已知行之和归一；Agent 与模型行点开专属看板，模型的命中缓存构成与复用率在模型专属看板查看。设备维度读云端设备分布，按设备筛选、只有一台设备或云端未返回时写明原因；账号来自桌面网关记下的供应商，云端没有这份数据，标为不可用，不从其他字段推断。旧云端缺失缓存读写拆分时诚实降级为“缓存合计”，不得把合计伪装成命中缓存。

现行「模型费用分布」面板已按完整模型列表、默认 8 行加「展开全部（N）」、不可得排最后与「无法归属」口径呈现（T10.158）；三档排行与行展开由信息架构 v2 的实施任务负责（方案 T10.156）。

## 5. 额度中心

### REQ-QUOTA-01 Provider 能力分级（P0）

每个 Provider 必须声明：数据来源、账户范围、刷新时间、已用/上限/剩余、重置时间、单位和置信状态。自动读取、手工配置、不支持三种状态不可混淆。

### REQ-QUOTA-02 官方接口与安全（P0）

- 支持接入官方公开的 API 组织用量/费用接口时，secret 只保存在系统安全存储或受控后端，前端和 APK 不接触 secret。用户自己的供应商 API key 发往该供应商自家域名读取余额或套餐用量是允许的；接口无公开文档的只能标实验性并默认关闭（ADR-018）。
- ChatGPT/Codex 或 Claude 消费者订阅没有官方公开额度 REST API 时，来源按稳定、受控本地观察、用户授权本地增强三档分级。所有消费者来源默认关闭并逐来源 opt-in；UI 必须说明来源、风险、权限和撤销效果。
- 用户授权本地增强可以参考成熟开源实现的来源规划并由 TokenLedger 内置，但不得直接调用消费者产品的未公开网络接口或读取第三方 Cookie/OAuth Token/钥匙串。若通过供应商本地代理或 CLI 读取，必须使用规范化绝对路径、固定参数、无工具权限、隔离工作目录、PTY、超时、输出大小和字段白名单，不经 shell、不回显 stderr/原始终端内容；只保留正规化额度窗口，账户资料与本地路径不进入 React、Android、日志、快照或云同步。关闭来源时清除额度 LKG。无法满足这些约束时显示不支持或手工配置，不把活动量推导成额度。
- 桌面消费者额度以 TokenLedger 内置、跨平台本地授权路径为主，外部桥接只能是用户另行安装且独立 opt-in 的失败兜底，不能成为 Windows 或其他平台的必需依赖。Antigravity 只允许同用户进程与 `127.0.0.1` 本地服务；允许为本地自签名证书使用隔离 client，但不得把证书放宽复用于互联网请求。TokenLedger 自行启动的 CLI 必须有界回收，不得终止用户原有进程。
- Provider 失败不阻塞主看板，使用上次成功快照并标注时间/错误。

### REQ-QUOTA-03 展示（P1）

桌面看板与可选壁纸/摆件按 Provider envelope 展示独立窗口。只有来源直接提供百分比，或同单位已用／上限可验证时才绘制进度；上限未知显示绝对用量和“上限未知”，Credits 与 unlimited 使用独立文案，不构造进度。

桌面采用连续来源／显示分组列表，移除最低额度摘要、圆环与图表切换，不读取旧视图偏好。来源身份位于左侧，百分比窗口固定两列，每项保留自己的周期标签、右对齐剩余百分比、细横条与可信重置时间；公司仍只展示日／月窗口。账户标签或明确显示前缀只在来源标题出现一次，未知名称保留原文并换行，不依据显示分组推断或合并真实账户。所有独立窗口保留确定性排序，余额与不限额在身份下方独立显示。辅助文字、来源标题、百分比为 12／14／18px；容器 ≤640px 指标排在身份下方，≤300px 指标改单列，窄面板不得截断名称、数值或操作。

历史和不可用标记始终可见，整组同状态显示一次，混合状态标在对应窗口。原因、原始观测／读取时间、scope 与来源收纳于原生详情；44×44px 行尾入口具备来源／分组语境的可访问名称，可用键盘展开，不删除完整数据。刷新入口保留加载／同步状态与禁用语义，窄容器允许显示为具有完整可访问名称的图标按钮。待处理来源保留具体原因和恢复动作，但默认折叠为一行摘要（来源数量与名称、去设置入口），用户展开后才显示逐来源说明与授权按钮；没有可信 reset 时不虚构倒计时。

中文界面不得把 `Primary`、`Secondary`、`5-hour`、`7-day`、`Credits` 或状态枚举等机器字段直接作为主文案。窗口有可信 `windowMinutes` 时优先解释为“5 小时额度”“每周额度”等周期语义；Credits 解释为额外用量余额/额度点。稳定 ID 无周期时只说明“主要/次要/附加额度窗口”，不得擅自推断周、月或滚动周期；未知 Provider、未知窗口和用户自定义预算名称保留原文，避免误翻译。窗口名前缀若只是当前 Provider 名或重复英文周期词可以省略；账户、模型或套餐等有区分度的前缀必须保留。桌面与 Android 的可见文本和读屏描述使用同一规则。

跨设备额度按用户与 `providerId + scope` 持久保存最后一个可用快照，不因年龄或其他设备上传时缺项而删除。冲突以来源 `observedAt` 最新者为准，相同来源时间才用服务端接收时间裁决；error、auth-required、unsupported 与较旧 LKG 不得覆盖较新的可用值。关闭某台设备同步、退出登录或撤销该设备 Provider 只停止本机读写；用户显式执行单 Provider 或全局删除时必须写入可阻止迟到写的 generation/epoch 墓碑。桌面允许没有本地 Provider 的只读同步，并把本地与云端快照按稳定键合并；云端旧数据始终可读并用真实时间显示 stale。

T10.308 恢复验收补充：超过 8 个云端活跃来源或历史坏快照不能作为合法展示值，但用户确认全局删除后必须有条件清空恢复路径。清空发送许可前先持久关闭本机同步，关闭失败不发送；确定删除失败、结果未知或崩溃重启均不自动恢复同步或重发删除，需用户显式开启。确认提前披露此代价，未知与确认成功分开反馈，切号不停止新账户；跨设备容量满时说明关闭本机不删除云端历史，不隐式挑选来源或删除数据。

桌面可见窗口对本次运行中已观察到的未来重置边界，在 reset 后约 5 秒补一次本地来源读取；后台定时器可能节流，恢复可见后补查。稳定 Provider／scope／window／reset 时间每边界仅尝试一次，合并在途自动请求，失败保留真实历史值，不循环重试。冷启动已过期的历史快照不制造补刷新循环；继续保留五分钟可见刷新和手工重试，不扩大来源授权或开启跨设备同步。

### REQ-QUOTA-04 多公司 OpenAPI 来源（P0）

桌面设置允许同时配置最多 5 组命名额度接口，主要使用场景为 2～3 组不同地址与对应 API key。每组生成不随名称、顺序或 key 变化的稳定 Provider ID，可独立启停、编辑与删除；接口地址只保存非 secret 元数据，API key 只进入当前电脑的系统安全存储。请求固定使用 `Authorization: Bearer`，禁止 URL 凭据、query key、跨源重定向和非本机明文 HTTP；连接/总时限、响应字节与并发数必须有界。删除本机配置必须同时删除对应系统凭据与 LKG，但不把撤权解释为云端删除。

公司接口只把官方文档或真实样本能证明的字段映射到额度契约。上游同时提供同单位 `used/limit` 时可计算百分比；字段缺失、非有限、负数、超限或响应结构未知时 fail closed，不猜金额单位、reset、模型停用窗口或余额语义。没有真实 API key 与脱敏响应对账时，fixture、编译和未鉴权 401 只能作为局部证据。

### REQ-QUOTA-05 公司额度跨设备呈现（P1）

每个已启用公司接口的可用 envelope 沿既有 owner-bound quota transport v2 独立同步；云端投影不得包含 API key、接口 URL、原始响应或账户标签。桌面额度仪表、Android 完整额度页与全屏摆件按未知/未来 Provider 规则展示用户命名来源；Android Launcher 小组件配置页从加密 quota LKG 动态枚举这些 Provider，可选择单一公司来源或跟随全部可用来源。小组件/摆件的窗口选择继续使用稳定键与角色规则，不为公司来源新增数组下标假设。

### REQ-QUOTA-06 额度消耗速度（P1）

额度面板为可信的百分比窗口显示“照此速度”的重置时用量或用完时刻，前置“预测”标签，方法与敏感度区间可在行内详情查看。非百分比窗口、实验性来源、缺少窗口时长或可信重置时间（重置时间只精确到天或小时而超过窗口 5% 的也算不可信）、历史数据、刚重置的窗口不预测；已用完的窗口不再重复说明。会在重置前用完的窗口用危险语气，重置前会跌破剩余 20% 的窗口用警示语气，文字本身必须完整表达结论；额度条仍按当前剩余 <20% 告急、<50% 偏紧着色（D4）。

分期：桌面额度面板先做（T10.153 规则、T10.159 接入）；Android 在桌面稳定一个版本后移植（用户决定，T10.172 Q5）。来源声明的重置精度字段 `resetsAtPrecisionSeconds` 要等额度契约只增扩展，现行按整天、整小时、整分钟推断。

### REQ-QUOTA-07 额度提醒通知（P2）

默认关闭；用户在设置中显式开启并授予系统权限后，额度窗口剩余跌破 20%（默认）以及可选的 50%、5% 时发送一次系统通知，“照此速度会提前用完”的预测提醒另设开关且默认关闭。同一窗口同一档每个重置周期只通知一次，同一来源 15 分钟内最多一条、每小时全局最多 4 条；只由新鲜观测触发，静默、遵守系统勿扰，内容不含账户、金额或路径，去重状态只存本机。现行状态（T10.287）：桌面已实现阈值告警，设置页「额度提醒」开关与 50%/20%/5% 档位多选，默认关闭；托盘常驻时后台 5 分钟节拍补一次本机读取；预测提醒未做；Android 不做通知。

范围（U-110）：首批只做桌面本机通知，阈值判断基于本机读取或已同步到本机的快照，不经云端推送；Android 通知另行立项。不做额度历史曲线。

### REQ-QUOTA-08 Claude 额度一键接入（P1）

用户开启「读取 Claude 额度」后，设置页可一键把 TokenLedger 写入 Claude Code 用户级 `settings.json` 的 `statusLine`（U-105）：

- 只改 `statusLine` 一项，其他键与原键顺序保持不变；文件不存在时只创建这一项。
- 写入前展示改动预览（命令中的用户目录做掩码），用户确认后写入；文件在预览后被外部改动时拒绝写入，要求重新预览。
- 每次写入前备份原文件，设置页提供「恢复原配置」；接入后文件又被外部改过时，恢复前需二次确认。
- 用户原有 status line 保留（U-106）：原命令改由 TokenLedger 在记录额度后执行，stdout 原样输出；原命令失败、超时或无输出时，Claude Code 只看到它自己的结果（空或失败），额度记录不受影响，stderr 不回显。
- 仍保留手动复制配置作为备选；未写入、已写入待首个快照、已收到快照三种状态在设置页明确可见。

### REQ-QUOTA-09 额度来源检测与统一状态卡（P1）

设置页「订阅额度」打开时只读检测 Codex、Claude Code、Antigravity 是否已安装（不启动进程、不读凭据），每个来源一张状态卡：「未安装 / 待开启 / 已连接 · N 分钟前 / 需在原应用登录 / 读取失败（保留旧值）」，下面列出该来源的窗口（周期、剩余百分比、重置时间）。未安装的来源开关置灰并给出安装说明。Claude 合并为一个开关（U-107），实验来源放入「高级」且默认关闭。每张卡只保留一句说明，权限与数据边界收进折叠面板；错误按 reason code 显示「一句话 + 一个动作」。凡是改动设置页界面的实现，都以设置页精简（T10.281）合入为前提。

### REQ-QUOTA-10 供应商官方余额（P2）

对 Moonshot、DeepSeek、OpenRouter、SiliconFlow，用用户已在「供应商」页保存的 API key（或在额度设置中单独填写的 key）读取官方余额接口；对用户自配的中转站，读取用户填写的同源余额地址（U-108）。余额以货币金额显示（人民币、美元等，按来源声明的币种），不画进度；多币种分别显示。每个来源默认关闭、逐个开启，key 只存系统钥匙串，只发往该供应商的允许列表域名或用户配置的同源地址。余额进入跨设备同步仍需第二层授权，且只同步金额与币种，不同步 key、URL 或原始响应；旧客户端看不到余额来源，不影响其他额度。

### REQ-QUOTA-11 实验性套餐用量（P2）

智谱 GLM、MiniMax、Kimi Code 的编码套餐用量（5 小时、每周等百分比窗口）作为实验性来源接入（U-109）：默认关闭；开启前弹出风险提示（接口无公开文档、可能随时失效、只使用用户自己的 API key、只发往供应商自家域名），用户确认后才读取；状态卡与额度面板标「实验性」，不做消耗速度预测。凭据只存系统钥匙串。读取失败时保留旧值并标明时间，不推算、不补零。不得改用订阅登录 OAuth 或网页会话（ADR-018）。

## 6. Android

### REQ-ANDROID-01 现代移动看板（P0）

使用 Material 3、edge-to-edge 与 TokenLedger 自有品牌令牌，不仿制 iOS 控件。移动看板需要在 390×844 内提供可扫描的高信息密度：时间范围、有效 Token/预估费用、趋势、记录数/缓存/平均值（Android 由 T10.207、T10.209 改名）、输入/输出/缓存/模型、构成、工具分布、额度和消耗日历热力图；通过图表、分组和渐进披露控制层级，避免卡片套卡片。今日页是摘要（T10.143），给出有效 Token、预估费用、二者的同期变化与比较基线说明，以及记录数、缓存复用率与活跃天数（用户决定，T10.172 Q3）；缓存净节省不进今日页，只进分享海报（用户决定，T10.162 Q5）。结论句与提醒在桌面信息架构 v2 定型后再移植（T10.172 Q3）；预测按 GLB-11 在桌面稳定一个版本后移植（T10.172 Q5）。趋势以平滑曲线呈现，不使用生硬折线连接采样点；消耗量曲线固定从 0 起算，当前期与上一期共用最大值，并在峰值上方保留 10%–15% 余量，禁止用非零截轴夸大普通波动。非紧凑图必须显示 0 与顶部刻度，便于解释曲线量级。趋势图与数据表共享同一指标和币种状态；当前期为空与上一期缺失必须分别表达，两期按同一窗口槽位对齐，长度不同时保留缺侧为“不可得”，不得用 `zip` 丢弃真实桶。云端费用趋势的日桶只取同一响应中覆盖完整、查询回显一致的 `dailyCosts`，费用不可得的日子画缺口并在表格与读数中标“不可得”，不按 0 绘制；今日的小时桶照旧（用户决定，T10.172 Q4；由 T10.172 候选任务 C5 实施）。趋势数据表使用时段、本期、上期三列精确数值，单位仅标一次，默认显示最近三行并可展开全部；不重复绘制主趋势已经表达的比例图。来源页的工具/模型排行、日历页的最近活跃日期与实体页的模型/设备组成复用同一行内数据条语言，按各自可见组最大值归一，同时保留排序、精确 Token、占比/记录数、日期或下钻语义。环形来源构成的绘制、点击命中与选中读数使用完整响应总量作为同一分母；被截断的来源只显示不可筛选的中性“未显示”余量，零值不生成弧或点击目标，全零显示诚实空态。数据条按实际行宽绘制，不使用固定像素宽度，也不能替代可读数值；窄屏或大字体下图表与排行必须重排而不是挤压文字；已有环形构成、热力图、趋势曲线和时间明细不得为了“多图表”重复编码或制造错误排名语义。2026-10-24 起 Android「用量」增加「会话」子页（对齐桌面「用量 › 会话」的云端可得部分）：读云端 `get_activity_rhythm_v1`（[activity-rhythm-cloud-v1](contracts/activity-rhythm-cloud-v1.md)），按当前范围与筛选显示有效 Token、记录数、活跃天数、24 小时分布、星期 × 时段热力与 Agent、模型排行；云端只有小时聚合，不显示会话列表与请求大小，页底写明并指向桌面。云端未部署该接口时如实说明，不报错、不显示 0。

数字格式与桌面一致（用户决定，T10.172 Q1；T10.207 实施，即 T10.172 C1，与 T10.154 A3 合并）：Token 紧凑写法 K 保留一位小数、M 与 B 保留两位，先按目标精度舍入再选单位，不出现 `1000K` 或 `1000.0K`；Launcher 小组件按 REQ-WIDGET-03 保留一位小数，是唯一例外；明细、数据表与读屏给出千分位精确值（现行 Android 只有趋势数据表是精确值，明细行四格与摆件、热力图等读屏仍用缩写，随 A5、A7）。金额按 T10.154 格式显示 `¥` 或 `$`、千分位、两位小数、不带 ≈，单条记录不足 1 个显示币种单位（人民币 ¥1、美元 $1）时保留 4 位小数（T10.207，R-76；桌面只显示美元，门槛即 $1）；大于 0 但舍入后为 0 时写“<¥0.01”，差值为负写“−¥1.23”，金额为负、缺失或非有限写“不可得”（与桌面黄金用例 `estimated-usd-format-v1` 一致）。变化率与桌面同一规则（`formatChangePercent`）：绝对值小于 10% 保留一位小数、不小于 10% 取整，始终带符号（负号用 U+2212），固定 `Locale.US`；变化小于 0.05% 写“持平”，上期为 0 时写“新增”或“持平”、不给百分比（Android 由 C2 实施）；小组件可一律取整（root 决定 R-11）。应用、摆件、小组件与海报共用同一个格式层。

工具/模型专属看板必须复用同一套 V2 顶栏、卡片、曲线、热力图、明细行和返回层级，不得跳回历史视觉壳层。小时明细必须同时正确读取云端 `YYYY-MM-DD HH:mm:ss` 桶和 RFC 3339 时间，列表显示真实小时与分钟，不得用字符串尾部的分钟/秒数冒充时间。

看板提供“有效 / 含缓存”展示口径切换并记忆选择：有效 Token = 输入 + 输出，含缓存 Token = 有效 Token + 缓存（与桌面“概览含缓存”同名；时间范围仍叫“全部”，用户决定，T10.172 Q8；Android 由 T10.207 实施）。主指标卡、复盘趋势卡与摆件预览卡本身是切换触点，卡头必须同时展示当前状态和下一步动作，并向 TalkBack 暴露 Switch 状态，不额外侵占一整行分段按钮。该选择只改变响应中已有汇总、来源和明细字段的呈现，不写入只接受 `effective` 的 Stats v2 查询契约；缓存尚无时间分桶时，趋势曲线和日历必须明确保持有效 Token 口径，不能从汇总值伪造分桶。

Android 的额度页、今日摘要和摆件统一按 Codex、Claude、Antigravity、其他来源的稳定优先级展示，不依赖云端数组顺序。完整额度页按 Provider 分组展示全部合法窗口，并以窗口实际观测时间重算新鲜度；过期 LKG 必须标记琥珀色“历史数据”并写出观测时间，进度条按档位色淡化，不整条改成琥珀（用户决定，T10.173 V-Q2；随 T10.173 的视觉任务（A4 额度）实施；现行进度条整条压成灰色半透明，数值与状态标签为琥珀），不得仅因 transport 成功就显示为实时。没有可展示窗口的 Provider 不占空位；今日摘要与紧凑摆件最多展示排序后的两个可绘制百分比 Provider，任一来源缺数据时由后续可用来源顺序补位。额度墙则每个 Provider 只展示一个代表窗口，来源数不得与窗口数混用；用户点击整屏可在环图与条形图间切换。墨水日报完整展示所有窗口时必须先按 Provider 分组，再在组内按代表窗口优先级排序，禁止不同软件交叉穿插。

### REQ-ANDROID-02 原生导航与筛选（P0）

底部导航或 NavigationRail 遵循窗口宽度；用量、路由、额度、我的是稳定一级目的地（重构方案 v2，用户 2026-10-23 确认；取代 T10.143 的今日/复盘/额度/展示），概览/趋势/来源/日历/请求在用量内切换。用量子页签选择是展示层的单一事实源；旧 `DashboardSection` 只保留兼容映射，不得用异步 section 回显覆盖用户刚完成的页签选择，快速连续切换最终必须停留在最后一次点击。范围使用原生分段控件；设备、模型、工具筛选的入口并入顶栏副标题（如「今日 · 全部设备 ⌄」），点按打开原生筛选面板，有筛选生效时副标题写出条件，顶栏保留分享入口（用户决定，T10.173 V-Q3；随 T10.173 的视觉任务实施。现行为顶栏下的一行查询摘要，行尾的筛选按钮打开含 FilterChip 的底部面板）。工具/模型行必须真正可进入专属看板，不保留空点击回调。

设置提供默认关闭的“强制横屏”。关闭时跟随系统方向，开启后用量、路由、额度与我的均锁定传感器横屏，并保留设置页内一键恢复；横屏使用 NavigationRail、紧凑摘要与宽屏设置网格，不得把竖屏布局机械拉伸。全屏摆件在横屏下必须按实际可用宽高重排主趋势、构成、日历与额度，不能只占左上区域或留下无意义的大块空白；同时要用更大的安全边距、卡间距和无卡片日签区保留有意图的呼吸空间，避免退化为塞满屏幕的常规仪表盘。多窗口或窗口宽度不足时仍以可用窗口尺寸为准，避免方向锁定造成主要操作不可达。窗口宽度按 600dp / 840dp 分三档（2026-10-24）：600dp 以下底部悬浮栏单栏；600–840dp（折叠屏内屏、平板竖屏）用 NavigationRail，内容单栏限宽 720dp 居中；840dp 及以上（平板横屏、手机横屏）且字号低于 150% 时拆双栏——用量的概览与来源、趋势与日历、请求与趋势并排，路由舞台与最近调用左右并排，额度卡两列，「我的」根页与待机屏子页并排。

用量·概览是全局日期范围的调整入口，使用 Material 3 日期范围选择器并支持日期输入；选择区间保留设备、工具、模型和搜索上下文。用量的趋势、来源和请求子页继承同一全局查询范围，只显示紧凑的当前范围摘要；日历呈现全局底图并高亮所选范围，不重复今日/周/月等范围按钮或维护另一套日期范围状态（T10.118a）。模型用量与费用合并为同一张排行卡，通过“Token / 费用”切换指标并重新排序；占比分母使用完整模型集合，前 8 项之后可展开全部，不用当前可见行冒充全量。工具选择向服务端发起规范化筛选，不能按总体比例推算该工具下的模型金额。

日历热力图使用响应时区和可信截止时间，呈现全局可信年度覆盖，概览所选区间只高亮，不裁剪可见或可点击日期（T10.136，用户确认）。预设查询复用全年 heatmap；自定义范围另取目标年度热力图并保留筛选与时区，不把辅助响应的汇总或金额并入主查询。未来或未经证明覆盖的日期不可点击；可信覆盖内空白日才表示已知零。按自然月绘制全局热力图，年视图按月、星期定位（小格不写日期）；月份整体可点击打开该月日期面板，面板内日期可定位、可信日期可进入当天复盘；月份读屏摘要说出合计、活跃天数、最高日，以及当前查询的日子与未查询（覆盖外）的日子（T10.209）；保留至少48dp的原生日期入口，不给细小日期格创建重叠触点。选择日期进入当天复盘，返回恢复原查询、页签和滚动位置。日历只保留一个热力图载体，不再铺重复摘要和每日不可得金额表；当天复盘使用该日查询的权威金额。保留的逐日预估费用呈现仍严格使用同一次响应的 `dailyCosts`，缺失、partial 或筛选不匹配一律不可得，禁止从汇总反推；隐藏费用覆盖数值、比例和无障碍语义。期末预测等预测类指标按 T10.172 Q5 在桌面稳定一个版本后移植（T10.172 候选任务 C7）；现行 Android 没有预测类指标。

### REQ-ANDROID-02a 信息架构：四分区（P0，重构方案 v2）

用户 2026-10-23 确认 APK 视觉与功能分区整体重构，移动端一级目的地固定为“用量 / 路由 / 额度 / 我的”，取代 T10.143 的方案 B（今日 / 复盘 / 额度 / 展示）。底部导航为悬浮胶囊，顶栏标题即分区名，范围由页内范围栏表达，不再进标题：

- **用量**承接原今日与复盘，用一条子页签在概览、趋势、来源、日历、请求之间切换。概览是当前全局查询的可扫描摘要与日期范围调整入口，主行动是一行「查看趋势 · 峰值 HH:mm ›」，主要来源行直接进入工具专属看板（用户决定，T10.173 V-Q4）；它只摘要趋势、构成、额度与日历，不复制完整子页。趋势、来源、全年日历、请求和工具/模型专属看板在同一返回链中切换。点击可信年度日历中的日期始终进入该日复盘，并保留进入前的日期范围、设备、工具、模型、搜索、页签与滚动位置；不得改写全局查询或另造一套筛选状态。
- **路由**展示网关路由：Agent 的请求经网关分到哪个账号、哪个在应答、哪个在限流，以及最近调用。数据源接入同步前只显示如实说明缺什么的占位，不画假流向、不编数字；动画场景随重构 R4 实施。路由页不依赖用量统计，统计加载中或失败时照常显示自身内容。
- **额度**按稳定 Provider 与既有新鲜度规则呈现，并只在呈现层分为“需关注 / 可用 / 历史”。“历史”默认折叠且必须保留真实 `observedAt`、原因和详情入口；不可把历史快照伪装为错误、实时数据或零值。
- **我的**承接原展示（全屏摆件、Launcher 小组件与周期分享），并逐步收拢同步、锁屏动态壁纸、待机/墨水屏与偏好入口（随重构 R5 实施）；各能力仍保持各自既有的配置、权限、系统入口和验收边界，不能因改名合并实例配置或改变分享数据。顶栏分享入口在用量与我的保留。

工具→模型→实体等下钻采用连续面包屑/返回链。加载中保留已进入的路径与上一层上下文，直到新数据可用后再替换内容；失败保留路径并给出恢复动作。设置只保留真实可写偏好、账号与设备能力；统计、缓存、口径与新鲜度解释以就近帮助/信息入口提供，不再作为设置主页面的常驻说明。

本批仅重组导航、页面职责、视觉层级、状态文案和**已有**数据投影。不得变更 Stats v2、Quota v1、有效 Token、缓存、预估费用、Provider 新鲜度/unknown 语义，不新增或修改 RPC、迁移、同步、扫描或云端数据。

### REQ-ANDROID-03 状态与离线（P0）

ViewModel 负责会话、latest-wins 请求、离线快照和鉴权过期。返回前台、跨午夜、时区变化可刷新；退出登录取消请求并清除会话代次。

额度页必须分别展示云端投影生成时间与各来源窗口的 `observedAt`，并可按稳定 Provider 身份展开完整观测、抓取/读取、可信重置与本机缓存时间；未知时间保持未知，不回显凭据或本机私密路径。来源观测超出 `staleAfterSeconds` 时标为“来源待刷新”，不得笼统写成“云端数据过期”；仅因各窗口年龄不同形成的新旧混合组显示“部分历史”并保留逐窗状态，显式 Provider 错误、授权状态与 Quota v1 数值准入优先。本机离线 LKG、云端投影新鲜度和来源观测新鲜度是三个独立状态。

额度加密缓存不设固定年龄 TTL；只要 owner、transport、结构与 epoch/revision 仍可信，即使离线多年也继续显示并按窗口时间标 stale。只有身份切换、显式删除/墓碑、结构损坏或单调版本倒退可以清除缓存，不能把“很旧”转换为“未同步”或 0%。

### REQ-ANDROID-04 无障碍与能耗（P1）

提供常规看板与全屏摆件。全屏摆件有一瞥、节奏、全息、额度墙、墨水日报五种信息编排（`AmbientMode`，按信息密度递增）：一瞥只看一个数字，节奏看 24 小时曲线与昨日对比，全息兼有曲线、热力与额度，额度墙只看剩余额度，墨水日报是等宽排版的全文本报纸式编排；每种编排在墨水屏上都有对应形态，墨水日报采用信息优先的布局与低刷新策略。手机竖屏与平板横屏的全息主信息都应落在可用画面的视觉中部，不得只占顶部并留下无意义的大块空白；长期驻留界面只保留当前数字、必要语义、同期变化、额度与刷新状态，不重复显示内部能力、同步协议、模式说明或显而易见的操作提示。横屏摆件包含按设备本地日期轮换的“今日一句”和 `Jeidorf` 签名字标；日签优先从无需密钥的公开句子服务按本地自然日获取一次并缓存，同日重复进入不得重复请求，网络、响应或隐私边界不满足时立即使用内置经典语句，跨午夜再刷新，不增加持续动画或高频网络请求。主题与摆件样式是两个独立偏好：摆件样式只改变信息编排，不得隐式切换深色、浅色或 E-ink 主题；各编排都继承用户当前主题。E-ink 主题负责黑白、高对比和无依赖颜色的线型/纹理；在没有既有用户偏好时，能从公开 Build、系统 feature 或显示刷新率组合信号识别出的墨水屏设备默认使用 E-ink 主题和墨水日报编排（其他设备默认全息），用户仍可分别修改。图表必须有文本摘要与 TalkBack 语义；热力图不能只靠颜色表达强度。

图表提供摘要/数据表替代、TalkBack 语义和至少 48dp 操作目标。摆件模式默认低功耗，尊重系统动画倍率、省电模式与热状态；非 E-ink 且系统允许动画、未进入省电或热限制时，整屏内容每分钟执行一次不超过 8dp 的低频像素位移并预留安全边距，用于降低静态驻留风险，不得用持续高帧动画替代。E-ink、关闭系统动画、省电或热限制下必须完全静止。低功耗不等于冻结数据：全屏摆件进入时立即拉取一次最新统计与额度，可见期间统计最多每 5 分钟自动刷新一次、额度最多每 15 分钟自动刷新一次，跨午夜、时区变化或从后台恢复时按新鲜度补刷新；请求保持 single-flight/latest-wins，失败继续显示合格 LKG，切到后台立即停止周期任务。全屏摆件可见期间必须保持屏幕常亮，以支持旧手机/平板作为长期桌面摆件，退出、切走或销毁该页面时立即恢复进入前的系统熄屏策略，不在后台持有唤醒锁。全屏摆件隐藏顶部 Android 状态栏并允许边缘滑动临时唤出，退出时恢复进入前的状态栏可见性；不重复显示编排名称作为模式标题，也不叠加返回或横屏切换按钮，方向只由设置页控制，系统 Back 可退出且不持久化临时进入状态。

T10.136 用户确认的呈现规则：全局日期热力图与当前统计范围分离，选一天仅高亮或进入当天复盘，不裁成单日底图。页面遵循非必要不增加实体；重复图表合并，精确表格按需展开，优先点击标题/数字切换而非新增一排同类按钮。隐藏费用同时覆盖比例图形与语义，模型币种跟随全局偏好。

### REQ-ANDROID-05 发布链路（P1）

仓库提供 Gradle Wrapper、release signing 接口、R8/资源压缩、lint/test/assembleRelease 门禁；生产构建缺 Supabase 配置应在 CI 失败，而不是向终端用户展示工程说明。

### REQ-ANDROID-06 查询身份与设备组成可信度（P0，T10.137）

### REQ-WIDGET-01 多组件家族（P0）

Android 桌面小组件提供“环形额度”“单行消耗”“组合卡”“额度条”四种每实例可选类型。实例类型是内容事实源，Launcher 尺寸只允许响应式重排或明确降级，不能在 4×2 下无视用户选择强制渲染组合卡，也不能把 2×2 组合卡标成组合却只显示额度。环形额度以 2×2 为主要形态；单行消耗以 4×1 为主要形态；组合卡以 4×2 为主要形态；额度条以 4×3 为主要形态，每个额度窗口一行写可用百分比与重置倒计时，可选在底部附一行最近一次路由（只读云端 routing-snapshot-v1 摘要）。

另有两个固定用途的表面，不参与上述类型选择：
- **实时路由小组件**：4×3 为主要形态，最小 4×2。它画 Agent → 网关 → 供应商/模型的一帧静态路由图，并列出最近 3 条调用。
  - 数据只读云端 routing-snapshot-v1。Glance 不能逐帧动画，所以是近实时静态帧：桌面在线且 10 分钟内有调用时约每 3 分钟读一次，空闲时约 10 分钟一次。桌面离线、未同步、需重新登录或访问令牌余量不足时停止近实时读取，回到 30 分钟的共用周期刷新；系统省电可能把间隔拉得更长。
  - 卡头写真实的读取年龄，不写「实时」。在途超过 90 秒的观察不再画成处理中；超过 10 分钟的调用不点亮。
- **快捷设置磁贴**：显示最紧额度窗口的「可用 N%」，口径同 REQ-WIDGET-02。最紧 = 可用最小的正常窗口，平手按额度条的截断优先级。没有正常窗口时退到「历史 N%」，再退到今日预估费用；都没有时写「暂无数据」。
  - 「今日」费用只在缓存写于本地今天零点之后时显示，跨天的旧数不冒充今日。
  - 点按打开应用。磁贴只读本地缓存，不联网、不存密钥。

验收：两者都读本地缓存或云端快照、不存凭据，有对应的截图金图和纯逻辑单测；真机上需走查添加入口、通知栏外观与 TalkBack。

### REQ-WIDGET-02 额度与时效语义（P0）

百分比圆环、数值、颜色阈值和 TalkBack 一律表达“可用额度”，不得拿上游已用比例配上无方向说明的百分比。所有表面（桌面额度面板、桌面挂件、Android 今日、额度页、摆件、小组件与读屏）显示同一个可用百分比：可用 = 100 − round(已用)，档位按显示的整数判定（用户决定，T10.172 Q2；Android 由 T10.207 实施，小组件读屏的档位词随 A9）。可用额度低于 20% 为告急、低于 50% 为偏紧（严格小于），其余为充足，与桌面额度仪表、桌面挂件和 Android 应用使用同一套阈值（用户决定 D4，T10.152）；充足使用主色蓝，桌面、小组件与 Android 应用一致（用户决定，T10.173 V-Q1，推翻 T10.131 的 Android 绿色；现行 Android 应用充足仍为绿）。error 由来源状态覆盖阈值色；stale 保留档位色并淡化显示，应用写琥珀色「历史数据 · 观测于…」，小组件写「待刷新」与观测日期（用户决定，T10.173 V-Q2）。现行应用把历史窗口的进度条整条压成灰色半透明，数值与状态标签为琥珀；现行小组件的历史圆环改用琥珀色、不按档位着色，文字写「历史」「历史数据」，「待刷新」字样由 A9 新增；两者都同时提供文字说明。V-Q1、V-Q2 随 T10.173 的视觉任务实施。Provider 按 Codex → Claude → Antigravity → 其他稳定排序。时效取当前 Provider 最新窗口的 `observedAt`，不得用云端投影 `generatedAt` 或其他 Provider 的 stale 状态污染当前来源；没有重置时间时不得输出“额度已刷新”等臆测文案。小组件的额度绝对量“剩 N”只用来源给的剩余量，缺失或非有限写“—”，不拿已用量顶替（R-71，T10.207）。

版面只能展示一个或两个窗口时，选择不得依赖 transport 数组顺序：先按 Provider 的稳定角色偏好选择，再在同角色内取已用比例最高、最先形成约束的窗口，平手以 `windowId` 确定性排序。偏好角色缺失而使用其他窗口时必须显示“替代”文字；仍有未展示窗口时显示 `+N`，并让读屏读取该文本，不能只用颜色或静默截断。完整额度页继续展示全部合法窗口。

### REQ-WIDGET-03 大数版面（P0）

有效 Token 必须稳定承载数百 M，主值采用最多一位小数的 compact 形式（例如 `987.6M`）。预估费用与 Android 主看板保持人民币口径，支持五至六位整数和千分位（例如 `¥128,640.34`），未知显示不可得（T10.207 起小组件金额走共用金额出口，读不到写“不可得”）。Token、变化率、费用使用独立布局轨道，任一数值变长不得推动另一轨道或造成截断；精确值仍可从应用内看板读取。

用户可在 Android 主看板与小组件切换隐藏费用，状态跨两者持久复用。隐藏费用只把金额显示为 `¥***.*`，不改变底层统计、缓存、同步或导出数据，也不得以“加密”“停止上传”等文案误导用户。

### REQ-WIDGET-04 每实例主题与状态（P1）

每个小组件实例可独立选择“跟随系统 / 明亮 / 黑暗”，默认跟随系统；该选择不改变应用主题和其他实例。正常、stale、error、需授权、未登录、无数据在深浅色下均须保持文本与图形双重编码，不依赖单一颜色。

### REQ-WIDGET-05 交互、无障碍与验收（P1）

可点击的数据区最小 48dp，并提供当前值、动作与方向明确的 TalkBack 描述；不得用字符箭头冒充刷新/切换图标。用户可通过 Launcher 的重新配置入口修改类型、来源、范围与主题。主机测试覆盖组件选择、可用额度换算、稳定排序、主题存储与大数格式；渲染证据覆盖三种类型、深浅色、正常/stale/error 和 200% 字体。真实 Launcher 添加、重新配置、缩放与 TalkBack 保持独立实机门禁。

旧通用 Provider 必须继续服务已存在实例但从新增选择器隐藏；三个公开 Provider 固定自身类型，配置页不得把环形额度实例静默改成其他用途。共享刷新任务只有在全部 Provider 都没有实例时才能取消，删除一种组件不能停止其他组件。

## 7. 桌面应用壳

### REQ-SHELL-01 macOS 聚焦窗口拖动（P0）

窗口聚焦或失焦时，侧栏顶部和标题空白区域都可拖动；按钮、筛选、输入、滚动区不触发拖动。不得同时依赖互相竞争的原生 drag region 与手动 `startDragging()`。

验收：聚焦/失焦各连续拖动 10 次；点击导航与顶栏控件不抖动；双击标题区行为符合平台；全屏和多显示器正常。

### REQ-SHELL-02 Windows 自由窗口（P1）

支持系统 Snap 和低至合理宽度的响应式布局；1200×800 不横向裁切主要内容，125%/150% 缩放不丢控件。

### REQ-SHELL-03 桌面挂件与托盘状态（P1）

主窗口之外提供一个无边框、置顶、不进任务栏的桌面挂件（窗口尺寸按当前板式变化，见本节 T10.124 段落与 T10.193）：今日/本周/本月的有效 Token 大数字与上一周期变化、预估费用、记录数、按同期对比序列绘制的迷你走势、最紧的一条订阅额度窗口（可用百分比、窗口名、重置时间与充足/偏紧/告急状态词；窗口名写「来源 · 分组 窗口」，分组与窗口名与看板相同，同一来源的同类窗口可以区分，T10.191；公司额度来源现行挂件仍多列看板不显示的「Key 日额度」窗口，由 T10.192 改为只列「今日」「本月」，R-52），以及最近刷新时间。挂件只读取本机数据，复用主看板的缓存统计与本机额度命令，并订阅调度器广播；不新增采集、不改变口径。挂件卡片为方向 B「账本圆环」（T10.192）：四种板式按 T10.190 方案 §6.4 的尺寸与内容排版；走势为单调三次曲线（今日实线、上期同进度虚线）；额度用圆环表示可用百分比，阈值 20 / 50，档位字充足 / 偏紧 / 告急，额度总览最多 6 个并写「+N」；「较昨日同期」胶囊与看板 KPI 同一份同期对比（`comparison.delta.tokens`）；公司额度来源只列「今日」「本月」，与看板同一筛选。额度整次读取失败与「没有来源」分属两个状态：失败时画虚线空槽并写「不可用」，不给授权入口；契约不合法仍按「没有来源」处理（T10.192 修复轮）。

鼠标在托盘/菜单栏图标上**停留**约 0.45 秒后在图标附近临时显示挂件，且不夺取当前应用的焦点；停留时长可在设置中调整（立即 / 0.25 / 0.45 / 0.9 秒，上限 2 秒），选择「立即」即恢复碰到就弹；停留未满就离开图标不得弹出——托盘图标只有十几像素宽，去点旁边的图标或滑向屏幕角落都会从它上面扫过，把「路过」当成「想看」会让一块窗口毫无预兆地盖住正在用的界面；指针离开图标与挂件后自动收起（默认开启，可在设置关闭）。单击图标把挂件钉住（再次单击、挂件内“隐藏”或托盘双击收起），Windows 双击与菜单“显示窗口”仍打开主窗口；挂件关闭只隐藏，用户拖动后的位置在本次运行内保留。挂件底栏提供“设置”入口，直接拉起主窗口并定位到“桌面挂件”分区。托盘悬停文案始终显示今日预估费用与有效 Token，写法与看板逐字相同：金额按汇总写法（`≈$`、千分位、两位小数，0 < v < 0.01 写 `<$0.01`，已知 0 写 `≈$0.00`），Token 按 DESIGN §4.4，TS 与 Rust 共用黄金用例（T10.191）；费用不可得时写「今日预估费用不可得」，macOS 菜单栏标题写「不可得」（T10.186），Token 读不到写「—」；macOS 菜单栏标题文字由独立开关控制，默认关闭。是否在启动时显示挂件是默认关闭的显式设置（ADR-015）。

T10.112：macOS 托盘弹层使用系统 Popover 材质、系统字体与连续分隔的指标结构，额度采用细进度条；其他平台保留不透明底色。统计先展示，额度慢来源独立读取并明确区分加载、可用与空态。范围变化时不得以旧范围快照冒充新范围；底栏「更新于」表示客户端读取时刻（T10.192 起由「读取于」改称，不是数据生成时刻），历史快照另行标注。Escape/隐藏/关闭必须统一清除钉住与悬停状态，使下一次悬停仍可自动收起。核心操作目标不小于 44px。

用户可在 Windows 与 macOS 上把同一挂件作为桌面小组件长驻：独立窗口位于其他窗口之下、壁纸之上，不进任务栏、不抢焦点，可拖动并跨重启记住位置；设置页“在桌面上常驻小组件”、托盘菜单勾选项“桌面小组件”、小组件内“从桌面移除”与直接关闭该窗口作用于同一个默认关闭的开关。Linux 托盘不产生悬停事件，只保留单击切换。托盘挂件、桌面小组件与 macOS 动态桌面将改用同一套「账本圆环」卡片（用户决定 U-12，方向 B）：桌面小组件窗口透明、卡片自带圆角，不出现方形底色；桌面上不常驻操作按钮，指针移入时出现刷新、打开主窗口、设置与从桌面移除，命中区 44px，键盘用户通过托盘菜单与设置页完成同样操作（U-18）。「Mac 的小组件」即这块桌面小组件，不做 macOS 原生 WidgetKit 小组件（U-17）。以上未实现，由 `design/desktop-widgets-wallpaper-visual-v1.md` §7 W2、W3、W5 实施。

T10.123 收口命名与入口：弹层一律称“托盘挂件”，长驻桌面那块一律称“桌面小组件”，托盘菜单、托盘 tooltip、设置页与挂件内文案不得混用；`widget_open_at_startup` 打开的是托盘挂件，其文案不得写成“桌面挂件”。两者的全部开关集中在设置页“桌面挂件”分区（`settings-widget`），目录可按“挂件”“小组件”检索到。主窗口侧栏不再提供打开挂件的按钮：它与单击托盘图标等价，而挂件的用途是主窗口未打开时扫一眼，从已打开的主窗口召唤它没有意义。

T10.124 内容配置：两块挂件各自持有一份「板式 / 主题 / 默认范围 / 额度来源」，对齐 Android 的每实例 `WidgetConfig`；托盘挂件与桌面小组件互不影响。板式四选一：用量详情（默认，大数字 + 走势 + 输入/输出/缓存 + 最紧额度）、额度与用量（额度横条在上、用量数字在下；放不下的窗口数与底栏「更新于」同一行，写作「· 另有 N 个窗口」，T10.191、T10.192）、额度总览（只看额度，按吃紧程度排列全部可读窗口）、单行消耗（只留有效 Token 与预估费用）。主题三选一（跟随系统 / 浅色 / 深色），显式选择压过系统深浅色与主窗口主题。默认范围决定每次打开先看哪一段，挂件顶部的范围按钮仍是本次会话的临时覆盖，不再写入持久化存储（旧实现两块挂件共用同一个键）。额度来源默认自动挑最吃紧的一条窗口，也可钉住某一个来源；钉住的来源读不到时必须直说读不到并给出换源入口，不得回退成显示其他来源的额度。所有取值是前后端共享的闭合集合，未知取值回落默认而不是渲染空白。四种板式各自定窗口尺寸（用户决定 U-13，T10.193 实施）：桌面小组件用量详情 364×388、额度与用量 364×172、额度总览 364×272、单行消耗 364×104，托盘挂件在此基础上加 26px 顶栏；切板式时保持离屏幕边缘最近的角不动、再夹回当前显示器工作区（多显示器按窗口所在显示器计算，覆盖负坐标原点的副屏），位置仍以物理像素持久化；托盘挂件在下次弹出时才采用新尺寸，已打开时不活改。托盘挂件顶部一条范围分段 + 刷新、打开主窗口、设置、收起四个图标（命中区 44×44）；桌面小组件平时不显示按钮，指针移入右上角淡入刷新、打开主窗口、设置、从桌面移除（「额度与用量」在右栏底部），减弱动效时直接出现，其余区域可拖动（T10.192，U-18）；设置页两张挂件卡各有一块按当前板式、主题与默认范围画的静态预览（示例数据，不可聚焦）。

验收：1280×860 主窗口隐藏时托盘单击可弹出挂件并再次单击收起；挂件内“打开主窗口”能从托盘驻留状态恢复主窗口；挂件在深浅主题下与主看板同一套颜色；范围切换后数字与主看板同范围一致；无额度来源时挂件给出去设置的入口而不是空白；键盘可到达全部按钮；四种板式在各自尺寸内不出现滚动或截断；两块挂件的内容配置互不串台；改设置后不必重开窗口即生效。

## 8. 周期总结与分享

### REQ-SHARE-01 周期总结图片分享（P0）

用户可把当前看板范围生成适合朋友圈或好友会话的 9:16 周期总结海报。海报不是看板截图，而是围绕“这段时间我如何与 AI 协作”的个人总结；桌面与 Android 均提供同一组五种布局：数据海报、协作手记、连续成就、协作结算单、极简信号。布局选择只改变信息编排和视觉语言，不改变统计口径。

验收：

1. `today/week/month/year/all` 分别使用“今日/本周/本月/今年/AI 协作里程碑”语义。桌面导出固定为 1080×1920 PNG；Android 以 1080×1920 为最低清晰度并优先使用设备显示面板的真实物理像素，按当前横竖屏方向输出、保持设备长宽比，以铺底留白容纳 9:16 设计内容，不裁切页脚或主值。分享页必须显示本次实际导出尺寸，不能用固定 1080×1920 文案掩盖动态结果。
2. 五种布局均只读取当前 `StatsData` 中可证明的字段。有效 Token 固定为输入 + 输出，缓存单列；无可靠上一周期时不显示百分比，`year/all` 不伪造同比；未知活跃日、峰值、缓存净节省或缓存读写拆分直接省略或标注不可得，不以 0 补齐；缓存净节省只在为正时作为海报事实，不画读取节省（毛值）或负值；海报首期不展示订阅回本倍数（用户决定，T10.154）。桌面海报由 T10.253 改画可信、无兜底单价的正缓存净节省；Android 海报已改画「缓存净节省」，只在净值为正、拆分可证明、未隐藏费用且不含兜底单价时出现，不足 ¥0.01 写「<¥0.01」（T10.184，用户决定 U-9）；云端 B 期上线前 Android 响应没有该对象，海报由其他事实补位（分期见 `design/cache-savings-net-v1.md`）。
3. 周期传播点由确定性规则生成，不调用生成式 AI：今日优先峰值小时/记录数，本周优先活跃日与峰值日，本月优先活跃日与日均（仅在有效分桶存在时），今年优先活跃日/连续记录/峰值周期，范围为「全部」时使用“AI 协作里程碑”而不是冒充年度总结。
4. 桌面支持复制 PNG 与保存 PNG；Android 使用系统 ShareSheet 分享 `image/png` 文件，以 `FileProvider` 受控 URI、`EXTRA_STREAM` 和临时只读授权交付。Android 不得再以 `text/plain` 作为主分享内容；可选说明文字不能替代图片。
5. 隐藏费用偏好同时作用于海报预览、导出和 Android 分享图；海报不得包含邮箱、账号、设备 ID、会话 ID、API 地址或其他身份信息。页脚可说明“数据来自本机账本/已同步账本”、生成时间及估算/stale 边界。
6. 布局与周期选择支持键盘和 TalkBack，选中状态不只靠颜色；生成失败保留选择并提供重试。桌面覆盖 1200×800、1280×860 与明暗主题；Android 主预览可进入全屏大图，支持双指缩放、双击快捷放大/复位、拖动、系统返回和显式关闭，并覆盖 320–430dp、390×844、字体 100%/150%/200%、明暗主题及系统 ShareSheet 图片缩略图。

### REQ-SHARE-02 离线 HTML 使用简报（P1）

导出单文件 HTML，沿用所选海报的五款封面风格，阅读区保持浅色纸面与清晰主次指标，不依赖外部网络字体、图片、图表或脚本，不做网页发布/托管。简报从分享弹窗导出，沿用同一「隐藏费用」开关（默认开启）；开启时金额、由金额算出的占比与同期变化显示「费用已隐藏」或省略，排序不按金额。有效 Token 为主指标，缓存与预估费用另列；工具表列出预估费用，登记订阅后另列 API 等值、预估支出与各订阅计费周期的回本倍数（B 期）；使用中性“缓存观察”，列出缓存读取节省、缓存写入溢价与缓存净节省（按价格表估算，非账单），不凭高低复用率评定用户效率。模型费用未知时显示不可得，核心统计畸形时拒绝导出。简报给出同期变化，云端无法证明上期基线时写“基线缺失”；响应带 `dailyCosts` 时另附每日预估费用表，只列有有效 Token 消耗的日期，超过 120 天时只列最近 120 天并注明。星期节奏要求每个星期几至少有 2 个观测日，否则只说明原因；峰值写作「单日最高」（用户决定，T10.156）。长名称允许换行，窄屏表格局部横向滚动；打印独立使用浅色前景背景。文件注明范围、来源、导出时间及估算/历史快照边界。

分享弹窗入口、隐藏费用、同期变化、工具费用列、每日预估费用表与星期节奏的观测日门槛由 T10.159、T10.163 实现。T10.253 简报缓存观察在契约提供时显示读取节省、写入溢价与净节省；仅有旧毛值时明确叫“缓存读取节省”，其余不可得，不反推净值。星期日均另标“星期节奏（日均）”，不冒充单日最高。订阅相关列仍待对应契约实施，本批不新增数据。

T10.112 海报布局补充：字号按宽高等比适配，避免水平拉伸或挤压字形；主数值应完整保留 compact 单位。无活跃日/连续日来源不得写成 1 天；小时桶与月桶不得当成每日签到记录。预览必须实际渲染后检查正文、趋势和页脚，区域元数据检查不能代替像素结果。

## 9. 非功能门禁

- `NFR-01 性能`：窗口可交互工作不在 Tauri 主线程；扫描增量化；统计 SQL 先过滤；重复请求 single-flight。大型来源 SQLite 必须使用索引可达的持久 keyset 游标，文件来源必须按版本化身份/大小/mtime 跳过未变化正文；记录、累计状态与游标在同一事务提交。默认自动扫描周期为 900 秒，旧版 60 秒默认值一次性迁移，用户可配置下限为 60 秒。用户触发一次扫描/同步只允许一个统计刷新链路；后台无新增时不得整表重写费用/同步状态，空闲云同步最多每 15 分钟重试一次，后台无变化时不广播刷新，隐藏窗口不轮询，图表数据更新复用实例而不是完整重建。
- `NFR-02 安全`：最小权限、RLS、secret 不进客户端/日志；第三方额度来源可审计。
- `NFR-01a 存储`：删除或清理只把页面放入 SQLite 空闲链表，文件不会自动变小。清理旧数据后若空闲页占比超过一成必须自动 `VACUUM`；设置页“数据库概览”显示可回收字节并提供显式回收动作；被同前缀带 `id` 索引覆盖的旧索引在初始化时幂等删除。回收不改变任何统计值，扫描或同步持锁时回收失败要原样提示稍后重试。
- `NFR-03 兼容`：旧数据库、旧 RPC、旧缓存和未知可选字段有明确策略。
- `NFR-04 可观测`：数据生成时间、云端刷新时间、stale、Provider 刷新和错误可见。
- `NFR-05 可重复构建`：开发门禁不修改版本；release 产物可从提交和锁文件重建。
- `NFR-06 发布完整性`：PR 门禁至少覆盖文档、前端、Rust、Android 与 Supabase SQL；受保护版本构建缺正式签名或生产公开配置时必须失败。正式产物清单记录版本、源码 SHA、同一构建启动时间、平台/架构、SHA-256、签名身份、Supabase 迁移头和验证证据；无签名、Debug、Preview 或本地临时包不得表述为公开 RC。

## 10. 模型接入与本地网关（ADR-017）

### REQ-GATEWAY-01 供应商、网关与路由（T10.263、T10.267、T10.266）

- 本地网关只监听 `127.0.0.1:3462`（避开 magpie 的 3425），使用本地随机 token；启用至少一个供应商后自动启动。
- 供应商 API key 只存系统钥匙串，前端只能设置或删除、不能读回；Agent 配置与接入示例中不出现供应商 key；页面不显示完整本地 token，只有用户在主窗口点击「复制 token」或「复制带 token 的完整示例」时才取出并写入剪贴板，不落日志、不进前端状态缓存（U-98）。
- 路由组 `group/<id>` 支持按顺序、轮流、固定一个、按权重四种分配方式；按权重时各成员权重 1–100（缺省 1），新会话按平滑加权轮询分配，失败时其余成员按权重从高到低切换；会话保持与规则命中的请求不占轮流或权重名额。成员可以是另一个路由组 `group/<id>`（最多嵌套 2 层，不得成环，被引用的组不能删除），子组按自己的分配方式与规则展开。连接失败、5xx、429 时在上游尚未返回 2xx 前切换下一个成员，流式开始后不切换；这样失败的成员冷却 30 秒（连续失败翻倍，最长 5 分钟，成功即解除），冷却期间排到其余成员之后。会话保持带时长，会话标识取自请求头，没有时取请求体的 `prompt_cache_key` 或 Anthropic `metadata.user_id` 中的会话（只用于路由，不入账）；确定性规则优先于会话保持，不做意图分类。
- 网关请求记录的主数字为有效 Token（输入 + 输出），缓存读写单列；与本地日志扫描的去重规则写入 `dashboard-stats-v2` 前不并入看板（U-95）。
- 网关提供 Anthropic Messages 接口（`/v1/messages`，流式与非流式）：上游为 Anthropic 协议的供应商时直通并保留缓存标记，上游为 Chat 时双向转换；只提供 Responses 的上游不能服务该接口。用量按输入、输出、缓存读、缓存写分列记账，不把缓存并入有效 Token（T10.289）。
- 模型接入是可选功能，设置里有总开关（U-112，T10.293）：关闭时侧栏不显示 Agent、供应商、网关、路由四个入口，网关不监听；新安装默认关闭，升级前已启用供应商或有 Agent 接入网关的用户保持开启。关闭前若仍有 Agent 指向网关，须提示并可一键恢复其原配置；开启不改任何 Agent 配置。

### REQ-GATEWAY-02 Agent 接入（T10.265、T10.266、T10.269）

- Agent 页为每个已支持的 Agent 提供：检查当前配置、选择 `供应商/模型` 或 `group/<id>`、预览 diff、确认后写入、从备份恢复。写入前备份、原子替换、保留其他内容与注释；文件在预览后被改动则拒绝写入，恢复时若接入后又被改过需显式强制。
- 接入范围对齐 magpie 支持的 Agent 并分批交付（U-94）；需要订阅登录或未公开接口的 Agent 排除（ADR-004）。尚未支持的 Agent 显示「即将支持」并写明原因。
- 已支持：Codex（T10.265）；OpenCode、Crush、Pi（T10.269 首批，JSON 配置）；Kimi CLI、Hermes、Goose、Oh My Pi、oh-my-opencode、Zed、MiniMax Code（T10.291～T10.298，逐个说明见 DESIGN §4.15）；Claude Code 与 Gemini CLI 见下两条。只写网关地址与本地 token，不写供应商 key；配置文件含注释、尾逗号、是符号链接或超过 256KB 时拒绝改动；JSON 写入保留原有键顺序，新增键追加在所在对象末尾（U-97，T10.270）。
- Claude Code（T10.289）：经网关使用用户自有供应商 key。只写用户级 `settings.json` 里网关拥有的 `env.ANTHROPIC_*` 键（地址不带 `/v1`、本地 token、模型及别名），不覆盖 `statusLine` 等其他键；恢复只还原这些键并保留其他键的当前值，这些键接入后被改过时需确认强制。
- Gemini CLI（T10.290）：网关提供 Gemini `generateContent` / `streamGenerateContent` 接口并转发到 Chat 协议供应商；Gemini CLI 以 API key 模式接入，写 `settings.json` 与同目录 `.env`（逐行合并、保留注释），不复用 Google 账号登录凭据。`.env` 只在 Gemini CLI 受信任的文件夹里生效，项目 `.env` 与 shell 已导出的变量优先，界面须提示这一局限。
- 设置页不再提供「API 配置」分区，模型与 Agent 接入只在模型接入四页完成；旧书签或挂件跳转到该分区时进入 Agent 页。旧分区留在本机的数据文件不删除、不再读取（U-99，T10.272）。

### REQ-GATEWAY-03 失败重试、恢复与接入界面约束（T10.300）

网关失败重试保留可审计的尝试身份；零Token诊断不参与计费去重，重试后成功只计一次，失败但有上游用量的尝试仍计入。协议无法表达的内容不得静默删除，发起上游前拒绝或选择原生成员。HTTP读取、响应、SSE、并发与转换累计必须有界，流式使用空闲超时。Gemini每次提交完整供应商/模型，不沿用其他客户端选择。
Agent多文件接入、普通/强制恢复在故障或进程中断后须可安全对账，未完成事务遇外部变更不能覆盖；预览/错误不得泄漏配置凭据。旧API配置退役保留只恢复入口和显式迁移步骤。
关闭检查失败保持开启，部分恢复逐项说明；弹层具备键盘模态行为，非敏感编辑草稿跨页可恢复，密钥不保留。模型接入与侧栏命中盒44px；长身份、双向记录表与按需自定义日期保持可读可达。
验收以本机夹具、故障注入、匿名浏览走查分开取证；真实原生IPC、Agent运行、Android/Windows设备与外部服务未验时保持平台/外部待验，不提升既有发布状态。
