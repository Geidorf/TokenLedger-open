## 1. 项目是什么

TokenLedger 是跨平台 AI 工具 Token 消耗账本：桌面端扫描本地工具日志，统一输入、输出、缓存、请求与成本口径，保存到 SQLite，并可选同步到 Supabase；Android 端以只读方式展示云端聚合数据。产品目标不是复刻供应商账单，而是为用户提供可解释、可下钻、可跨设备对比的个人使用洞察。

### 1.1 当前产品面

| 表面 | 责任 | 不负责 |
|---|---|---|
| Tauri 桌面端 | 本地扫描、SQLite、统计、云同步、设置、托盘、挂件、壁纸 | 代替供应商官方计费结算 |
| 本地模型网关 | 127.0.0.1 上的 OpenAI 兼容入口，按 `供应商/模型` 转发并记用量账本（ADR-017） | 把供应商 key 暴露给智能体 |
| React 看板 | 指标、趋势、明细筛选、模型/工具下钻、额度展示 | 直接持有第三方 secret |
| Supabase | 认证、跨设备日志与聚合 RPC | 绕过 RLS 的公共明细访问 |
| Android | 登录后只读云端看板、移动洞察、摆件模式 | 扫描手机上的桌面工具日志 |

## 3. 编号与状态

### 3.1 编号

- `GLB-NN`：全局体验与质量要求。
- `REQ-DETAIL-NN`：消耗明细与筛选。
- `REQ-COMP-NN`：同期趋势比较。
- `REQ-DRILL-NN`：模型/工具专属看板。
- `REQ-QUOTA-NN`：额度 Provider 与展示。
- `REQ-ANDROID-NN`：Android 产品体验。
- `REQ-SHELL-NN`：桌面窗口/应用壳。
- `REQ-WIDGET-NN`：Android 桌面小组件与全屏摆件。
- `REQ-SHARE-NN`：周期总结海报、隐私与跨端图片分享。
- `NFR-NN`：非功能门禁。
- `ADR-NNN`：架构决策。
- `T<M>.<N>`：任务编号；并行子任务追加小写字母，例如 `T4.2a`、`T4.2b`，每个子任务仍需独立认领。
- `TOKE-NN`：已停用的 Multica Issue 编号，只存在于存量任务。当时 Issue 进入本仓库实现时直接作为 TASKS 任务 ID（例如 `TOKE-14`），与 `T<M>.<N>` 并列，沿用同一套状态轴；不另造镜像编号。

### 3.2 状态

```text
[ ] 未开始  [~] 进行中  [r] 待复核/待合入
[v] 已合入、待平台/外部验收  [x] 已合入且验收完成
[!] 受阻  [?] 待产品决策
```

总状态只表达任务整体进度，不能替代两条结构化状态轴。两轴取值是**封闭枚举**，由 `npm run check:docs` 强制校验；需要新语义时先改本节，不得在台账里就地发明取值。

#### integration（代码到达了哪里）

| 取值 | 含义 |
|---|---|
| `not-started` | 尚未开始实现 |
| `uncommitted` | 有工作区改动但未提交 |
| `committed` | 已提交到任务分支，未合入目标分支 |
| `review` | 已提交并请求协调员复核 |
| `partial` | 已有子能力合入目标分支，但任务仍有明确实现缺口 |
| `merged-local` | 已合入本地 `main`，尚未推送远端 |
| `merged-remote` | 已合入且已推送到 `origin/main`，其他机器可 fetch |
| `blocked` | 被依赖、凭据或环境阻断 |

`merged-local` 与 `merged-remote` 必须区分："合到本地主干"与"其他机器拿得到"是两个完全不同的交接前提，不能用同一个词表达。`partial` 不得用平台待验收掩盖未实现代码。

> 迁移说明（2026-07-25）：旧取值 `merged` 与 `pushed-main` 已废弃，分别并入 `merged-local` 与 `merged-remote`。门禁自本次修订起拒绝旧取值。

#### validation（在什么条件下验过）

| 取值 | 含义 | 强弱 |
|---|---|---|
| `not-run` | 一项门禁都没跑 | 最弱 |
| `platform-pending` | 逻辑已验，真实平台矩阵未覆盖 | |
| `local-passed` | 本机自动化门禁通过（编译、单测、lint、截图回归） | |
| `target-device-passed` | 已在目标真机/真实平台验过，但 §6 平台矩阵尚未闭合 | |
| `external-pending` | 依赖真实外部服务或凭据，尚未验证 | |
| `blocked` | 验证被环境或凭据阻断 | |
| `complete` | §6 适用矩阵逐项有证据 | 最强 |

`target-device-passed` **弱于** `complete`：它表示"这台设备上是对的"，不表示"矩阵覆盖完了"。禁止复合取值（例如 `remote-passed / windows-ui-pending`）——状态列只写一个词，缺口写进"当前缺口 / 下一动作"列。

> 迁移说明（2026-07-25）：旧取值 `local-complete` 语义等同 `local-passed`，`remote-passed` 语义等同 `target-device-passed`，均已废弃。

#### 总状态与两轴的对应

`[r]` 只用于尚未合入目标分支的复核阶段。代码已合入但缺真实平台或外部服务验收时必须用 `[v]`。`[x]` 的充分必要条件是 `integration ∈ {merged-local, merged-remote}` **且** `validation = complete`——这条由 `npm run check:docs` 机器校验，人工判断不作数。

## 4. 协作与执行（Claude + Codex，2026-10-17 起；本地验证 U-86，2026-10-03）

仓库由 Claude 与 Codex 两类智能体推进维护，用户做产品取舍并在本机验收。本节取代此前的 TEAM-v1 岗位链与 Multica 单通道流水线（两者均于 2026-10-17 经用户确认废止，材料在 `docs/archive/`）；§3 状态真实性、§4.3 单写、§5 完成条件与 §6 适用验收不变。历史任务的证据与决定保留，不回写。各小节编号沿用原含义，旧引用仍可查。

### 4.1 角色

- **协调者**：开单、写派单、读 diff 复核、合入、在本机跑全量门禁、单写 §4.3 所列文件、向维护者汇报。
- **执行者**（可以是命令行编码智能体，也可以是人）：只在派单给定的分支与路径内实现，提交、写日志、回报后结束。
- **独立评审**：只给 §4.10 所列高风险任务派，由不是该任务实现者的一方做（Codex 写的交 Claude 评，反之亦然）；只读，结论写进一份短日志。
- 同一时刻一个任务只有一个实现者。两边都可以当协调者，但同一轮只有一个，由用户在开轮时指定。

### 4.2 工作流

1. **登记**：协调者登记一行（ID、目标、级别、依赖），并记录分支、基线 SHA 与路径所有权。登记前按 §4.12 先扫规格与口径；有冲突则不登记、不派单。
2. **派单**：派单写进 `docs/task-logs/<任务ID>/brief.md`（约 20 行：目标、范围、可改路径、要跑的检查、预算、回报格式），规则引用文件路径，不贴长简报。所有执行方读同一份派单，交接不依赖任何一方的对话上下文。
3. **实现**：执行者在派单给定的分支、独立 worktree 中实现（不在共享检出里切分支），只跑与改动相关的测试；长命令前台跑到结束；按独立逻辑单元中文提交。
4. **日志**：每个任务一份，front matter 保留 `status`、`validation`、`verification`（如实写跑了什么、没跑什么和原因），正文不超过 20 行。执行者在日志里写实现 SHA 与未完成项，即为回报。
5. **复核**：协调者读 diff；高风险任务按 §4.1 交另一方独立评审；发现按 §4.11 处理。
6. **合入与推送**：协调者按批合入，合入 `main` 前在本机对最终树跑一次全量门禁（§4.13）；事实源与待办在同一个文档提交里更新；全绿即推送，事后汇报。归档脚本把已闭合的行移入归档文件，归档行只能是已完成行或只差平台验收的行，同一 ID 不得同时出现在两处。
7. **收尾清理**：PR 合并或关闭后，负责该 PR 的一方按顺序清理：先 `git worktree remove` 移除为它开的 worktree（分支仍被 worktree 检出时删不掉），再删除本地分支与远端分支，最后 `git worktree prune`。分支上若还有未合入的独有提交（PR 关闭未合并时常见），先打并推送标签 `archive/<分支名>` 保住这些提交，在任务日志记下标签与 SHA，再删分支；只记 SHA 不够，提交失去引用后会被垃圾回收。
8. **真实平台**：代码合入后只缺真机的任务标 `[v]` 与 `platform-pending`，清单写在任务日志，由用户在对应机器上执行。云端可跑与本机专属按 §4.12 拆开记，不捆成一次通过或失败。

### 4.3 路径所有权与单写

以下默认由协调者单写：

- 本文件、`docs/REQUIREMENTS.md` 与 `docs/DESIGN.md`；
- `docs/contracts/**`，以及额度能力矩阵等跨任务集成事实；
- `supabase/migrations/` 的编号（`supabase/schema.sql` 是禁止执行的历史快照，不再随迁移更新）；
- `package-lock.json`、`src-tauri/Cargo.lock`；
- `package.json`、Tauri/Android 版本文件；
- 根级发布说明、可分发产物清单与最终证据索引。

执行者若确需修改，必须在派单与认领记录里获得显式、限时的唯一所有权。

### 4.4 多机器约定

- 跨机器继续前优先推送；推送受阻时只交接已提交引用的 Git bundle，记录 SHA-256 与验证命令，接收方核验前 `handoffReady` 为 `false`；不复制脏工作区。
- 本地机密只放 `.env`、Android `local.properties` 与系统钥匙串，不进 Git、不进日志。
- 每台机器使用自己的构建目录、端口、模拟器与临时数据库；不停止别人的进程。
- 平台专属验证在对应机器完成：macOS 负责窗口、菜单与动态壁纸，Windows 负责 Snap、WebView2 与锁屏，Android 负责真机或模拟器矩阵。

### 4.5 Git 规则

- 分支名：Codex 用 `codex/<任务ID>-<slug>`，例如 `codex/T3.2-quota-provider`；Claude 用运行环境分配的 `claude/<slug>` 分支，并在认领行写明。从 T6.1 起，新提交（含合并提交）的主题必须包含中文，例如 `统计：增加上一周期曲线（REQ-COMP-01，T1.2）`；技术名、任务 ID 与路径可保留原文。
- 每个 worktree 执行 `git config core.hooksPath .githooks` 启用提交钩子；交接前可运行 `node scripts/check-commit-message.mjs --range <基线>..HEAD`。历史 SHA 已被任务日志和多机交接引用，不得仅为统一语言而改写。
- 独立 worktree，基于已记录的目标分支 SHA；依赖只有在合入目标分支后才视为满足。
- 禁止 `git add .`、`git add -A`、强制清理、覆盖他人文件和把无关改动顺带提交。
- 重构/废弃后用 `rg` 清扫旧符号、路由、文案、测试、样式、文档与配置；兼容层必须登记退出条件。

### 4.6 版本日期与构建时间

- 所有平台、安装包、界面、更新说明和任务证据中输出的“版本日期”“构建日期”或“构建时间”，统一取该次实际构建启动时捕获的同一个日期时间，并保留时分秒与时区；不得再维护或计算另一套独立版本日期。
- 禁止从语义版本号、Git 提交日期、更新日志日期、文件修改时间、任务完成时间或自增计数推导构建日期。同一次构建产生的多个产物复用同一时间戳；重新构建则使用新的实际构建时间。
- 该规则不改变 SemVer、Android `versionCode`、Tauri/Android 版本一致性或显式发布升版流程；版本号与构建日期时间是两个来源明确、互不推导的字段。

### 4.7 派单、交接与证据

- 派单即交接：`brief.md` 写明任务 ID、目标、范围、准确基线、验收与回报格式；执行者的日志即回报，协调者核对后回填台账。用户可直接指挥；产品目标、重大范围、预算、权限或验收底线变更由用户决定。
- 证据与风险成正比：开发中只跑相关测试，全量门禁由协调者在合入前跑一次；故障注入与 SHA-256 记录只用于用户数据、安全与发布阻断规则；截图只在界面改动且用户要看时做，截图本身不进 Git（见 `docs/task-logs/README.md`）；Android 参考图只在合并时于集成分支重出一次。
- 安装包、跨机器 bundle 等可移交产物仍记录完整 SHA-256、来源提交与环境；临时构建路径不能作为唯一证据。

### 4.8 清理

- 删除前核对：准确路径没越出本项目；没有在用的任务、进程或服务；未提交与未合入的独有成果已交付；保留与恢复需要已处理。
- 用 Git 或平台支持的方式移除，不直接递归删除平台内部目录；内容不明就保留并写明查证者。对话归档、远端分支、业务数据与全局配置不随目录清理自动获准。

### 4.9 复盘与用量

- 每轮收尾复盘一次：用量（执行者数、工具调用，可得时附 token）、返工与等待；无可靠数据写未知。
- 出现任一报警信号先停下复盘再派单：任务超出 §4.10 预算；执行者改第一行代码前已调用 50 次以上；评审发现又变成新任务；文档与日志新增行数超过产品代码。
- 真实平台验收连续两次在业务用例启动前失败时，暂停同类重试，先查共同前置（零进展熔断）。

### 4.10 分级与预算

| 级别 | 条件 | 预算 |
|---|---|---|
| 小 | 改动集中（产品代码约 300 行以内），不触及高风险面 | 约 100 次工具调用 |
| 中 | 跨模块或规模更大，但不触及高风险面 | 约 300 次 |
| 高风险 | 本机账本、设置与价格文件等用户数据的读写与迁移；云端权限、RLS 与 RPC；数据库迁移；跨端统计口径；发布前置；凭据与安全 | 单独估算，另派独立评审 |

- 同一区域的小、中任务合成一个包交给一个执行者，提交主题带各自任务 ID。
- 执行者超出预算先停下报告，协调者决定是否继续。
- 每轮开工前写明收尾线；轮内不追加任务，预计超出时先问用户。

### 4.11 评审与待办（用户决定 U-22）

- 小、中任务由协调者读差异并抽查关键规则，再以集成全量门禁把关，全绿即可合入；高风险任务另派独立评审，评审通过且门禁全绿才合入。
- P0、P1 合入前必须修复；P2 在同一修复轮内能低成本修复就修，否则记入待办；P3 一律记入待办清单，不登记新任务。
- 协调者在每轮收尾时把待办交维护者挑选，选中的项才登记。转入待办的已登记任务保留 `[ ]`，备注写明用户决定与去向，并释放认领。
- 需要用户拍板的取舍按 §4.12 停泊：未登记的只写入待办，已登记的标 `[?]` 并释放认领。不空转，不靠猜另开实现。

### 4.12 开单、验收拆分、停泊与防重复

- **开单前先扫规格与口径**。新开任何任务前，先扫 `REQUIREMENTS`、`DESIGN`、`contracts`、`TASKS` 相关行和近期已合入任务。口径冲突时不建任务、不实现，把冲突交给协调者或用户。例：旧 PR #14 要「缓存合计」，与 T10.207「缓存复用率」冲突。
- **验收拆成云端可跑与本机专属**。同一 PR、同一任务里把两类条目分开列，不捆成一次通过或失败。云端能跑过的条目在 PR 与任务日志里单独勾完；本机专属（如 Android 模拟器 390×844 截图）保持 `platform-pending`，写明由用户在本机跟进。任务级 `validation` 仍只写 §3.2 的一个词：本机专属未验不得标 `complete` 或 `[x]`。
- **需用户拍板则停泊等待**。产品取舍、口径或验收底线要用户决定时，停泊等决定，再派工。未登记的写入待办清单；已登记的总状态用 `[?]`，备注写明在等哪一个决定，并释放认领。不空转过夜，不靠猜消耗 token。
- **不重复实现**。派单前先查当前认领与开放 PR；已有认领或开放 PR 覆盖同一任务时，改去核验或补验收，不另开第二套实现。每个执行方开工前都按这条自查。
- **派编码前先登记**。写代码之前，任务行、认领与 `brief.md` 必须已经写好；未登记不得开工。

### 4.13 本地验证（用户决定 U-86，2026-10-03）

- 验收与合入只认本机实际运行的门禁：开发中跑与改动相关的检查，合入 `main` 前由协调者在本机对集成结果跑一次 `npm run check`（Android、Supabase 只在改动涉及时追加）。GitHub Actions 工作流文件保留，但其结果不作为验收依据，也不作为合入前置。
- 任务日志的 `verification` 写本机实际跑的命令与结果；未在本机运行的平台项仍按 §4.12 保持 `platform-pending`，不因远端 CI 未运行或失败而改变结论。
- 本条不改变 §3.2 状态枚举与 `npm run check:docs` 的机器校验；推送仍按 §4.2 第 6 步，推送与否由用户决定。

## 5. Definition of Done

一个任务只有同时满足以下条件才能完成：

1. 需求验收标准逐条有证据；错误、空态、加载、取消和旧版本兼容不缺失。云端可跑与本机专属分开列证，本机未验不得并成同一次通过（§4.12）。
2. 统计或接口变化已同步 TypeScript、Rust、SQL、Kotlin 中适用的消费者，并更新契约。
3. 自动化测试、静态检查、构建和 `git diff --check` 通过；只声明实际运行的门禁。
4. 用户可感知 UI 已在目标尺寸和主题视觉走查；平台专属行为有对应实机证据。
5. 安全检查覆盖凭据、RLS、权限、日志脱敏与第三方 API 边界。
6. 任务日志带 YAML front matter，`status`、`validation`、`verification` 必填且如实，正文不超过 20 行；最终实现与合入 SHA 由协调者在合入时回填。
7. 安装包、跨机器 bundle 等可移交产物记录完整 SHA-256、来源提交与环境；临时 `dist`、`target`、`build/outputs`、`/tmp` 或可变 `release/` 路径不能作为唯一完成证据；截图与故障注入按 §4.7 配比。
8. TASKS 中 `integration ∈ {merged-local, merged-remote}` 且 `validation=complete`；需要跨机器继续时还需 `integration=merged-remote`（或已交接可验证 bundle）与 `handoffReady=true`。
9. 文档/更新说明已同步，或任务日志说明为什么无需更新。

## 7. 架构决策（ADR，只追加）

### ADR-001 保留 Tauri + React + Rust + SQLite + Supabase + 原生 Compose（2026-07-14）

现有技术栈符合常驻型跨平台日志账本。当前性能问题来自全量扫描、全表聚合、重复刷新与高频重绘，不以框架重写解决。优化优先落在增量扫描、查询下推、缓存、状态与渲染预算。

### ADR-002 统计采用单一跨端契约与有效 Token 主口径（2026-07-14）

`StatsData` 是 React、Rust、Supabase、Android 的共同契约。主口径固定为输入 + 输出，缓存读写、成本和请求数单列。v2 以可选字段扩展并兼容旧 RPC，禁止单端先行改变语义。

### ADR-003 多智能体使用独立 worktree、路径所有权与共享文件单写（2026-07-14）

并行工作的正确边界是任务 + 路径 + worktree，不是共享一个脏工作区。TASKS、ADR、契约、迁移、锁文件和版本由协调员单写，减少跨机器冲突与不可追溯合并。

### ADR-004 额度能力采用可审计 Provider，不逆向消费者产品私有接口（2026-07-14）

额度卡区分“消费者订阅窗口”和“API 组织用量/费用”。只接入官方公开 API、官方本地工具明确暴露的授权信息或用户手工配置；无官方接口时显示“不支持自动读取”，不得保存网页 Cookie、抓内部端点或伪造百分比。

### ADR-005 Android 采用 Material 3 壳层与可取消状态流（2026-07-14）

Android 保留 TokenLedger 数据品牌，但交互使用原生 Material 3、edge-to-edge 与无障碍语义。网络、会话、筛选和页面状态移入 ViewModel，以请求键和 latest-wins 防竞态；Compose 页面不直接启动脱离生命周期的请求。

### ADR-006 开发构建可重复，版本提升只在显式发布步骤发生（2026-07-14）

类型检查、单测、静态前端构建和调试构建不得自动修改源码版本。发布协调员显式提升版本，同步根版本、lockfile、Tauri、Android 和发布说明，再执行 release 门禁。

### ADR-007 Android 固定主路径采用主机截图回归，真实设备矩阵独立验收（2026-07-15）

390×844 Ledger Snapshot 使用官方 Compose Preview Screenshot Testing 保存仓库 golden，并在 Android 门禁中做像素回归。golden 只能在设计源与实现同画布复核、确认变化有意后更新。Layoutlib 主机渲染用于防止布局/绘制漂移，不替代 edge-to-edge、触控、TalkBack、字体缩放、导航模式、主题和 GPU 性能的真机验收。由于字体栅格化会随主机 OS 漂移，golden 的生成与验证固定在 macOS runner；Ubuntu Android job 只负责单测、lint、Debug/R8 构建，禁止把跨主机像素差异当作产品回归或静默放宽像素阈值。

补充（2026-09-25，用户决定 V-Q7，T10.173）：Android 视觉焕新批次（T10.173 规范的 A0–A10）开发期间，参考图在 Windows 开发机上生成，只作 fixture 证据，不作为权威 golden；整批合入本地主干后、推送前，由用户在 macOS 上执行一条命令统一重出全部参考图并校验一次，通过后才推送。原因：A0 更换色板会使全部 242 张参考图变化，逐个任务在 macOS 上重出不现实，而字体栅格化随主机 OS 不同。本补充不改变上文：macOS 仍是权威 golden 的生成与验证主机，跨主机像素差异不得当作产品回归，也不得放宽像素阈值。

### ADR-008 协作状态采用双轴、结构化认领与可验证远端交接（2026-07-15）

任务“已合入”与“已验收”是不同事实，统一用 integration/validation 双轴记录；认领是带机器、基线、路径和共享资源的显式租约。跨机器交接以可 fetch 的远端提交为主，远端受阻时仅允许内容可验证的已提交 Git bundle。任务证据使用 YAML 元数据、完整哈希与 fixture/真实平台标签，历史日志可被后续事实 supersede，但正文不可静默改写。

### ADR-009 消费者额度按风险分级并允许用户授权外部桥接（2026-07-16）

本决策在产品策略上取代 ADR-004 的“只要不是官方来源就一律拒绝”，但不降低凭据与数据最小化要求。额度来源分为：官方公开/本地协议（稳定）、受控本地观察（计划相关或实验）、用户自行安装并授权的外部增强桥接（高风险实验）。第三类必须逐来源默认关闭，设置页披露它可能使用钥匙串、浏览器会话、OAuth 或供应商 CLI；TokenLedger 只启动受控绝对路径、固定参数、固定超时和输出上限，只接收并校验标准化额度窗口，不直接读取、保存、上传或记录外部桥接持有的凭据/原始响应。关闭最后一个同 Provider 来源后清除快照并停止同步；真实账户能力仍须单独实机验收。

### ADR-010 消费者额度允许显式授权的内置本地增强（2026-07-17）

本决策扩展并部分取代 ADR-009 对“增强来源只能是外部桥接”的限制。自用型客户端可以参考可审计的成熟开源实现，在不复制其运行时依赖的前提下内置受控本地 Provider。Claude 增强来源参考 CodexBar 的 CLI PTY 探测思路，但由 TokenLedger 依次尝试 Claude Desktop 自带的本地代理与已安装的 Claude Code；任一候选失败后先尝试其他候选，对可恢复失败再做一次全新 PTY 会话重试。探测目录固定禁用 Claude 深链注册，失败结果不进入短时成功缓存；不安装或启动 CodexBar，不读取 Claude 钥匙串、Cookie、OAuth Token，也不直接调用消费者产品的未公开网络接口。来源默认关闭；子进程必须使用规范化绝对路径、固定无工具参数、隔离工作目录、PTY、总时限/单次时限/输出/窗口白名单，并只保留正规化百分比与重置时间。关闭最后一个来源后清理 LKG 与同步资格；Claude Desktop 网页额度可用不代表 CLI `/usage` 通道可用，CLI/计划不返回数值时须准确显示通道不可用，不以本地活动量估算额度。

### ADR-011 Claude 额度优先使用用户授权的 CodexBar 标准化桥接（2026-07-17）

本决策扩展 ADR-009 并取代 ADR-010 中“生产路径不启动 CodexBar”的限制。实机证据表明 Claude Desktop 额度页正常时，Claude CLI `/usage` 仍可同时加载失败；同机 CodexBar 则可通过用户已授权的 web 来源返回标准化消费者额度。因此用户单独开启 Claude 增强来源后，TokenLedger 优先以规范化绝对路径、固定参数、固定工作目录、输出上限、进程树超时和来源白名单执行 CodexBar CLI，只接收其标准化 Claude JSON；TokenLedger 本身不读取或保存钥匙串、Cookie、OAuth Token、账户身份或网页原始响应，并拒绝 API 组织 scope 伪装成消费者额度。桥接不存在或失败时继续使用 ADR-010 的内置 PTY 回退，整条恢复链仍有界；关闭授权时同时停止桥接与 PTY，并按既有规则清理 LKG 和同步资格。

### ADR-012 消费者额度统一采用内置主路径与可选桥接兜底（2026-07-18）

本决策取代 ADR-011 的 Claude 桥接优先顺序，并将同一策略扩展到 Antigravity。跨平台客户端不能把 macOS 专用 CodexBar 作为主要运行依赖：Codex 继续使用官方 app-server + 受限 JSONL；Claude 使用 status line 或 TokenLedger 内置 `/usage` PTY，失败后才尝试用户另行安装的 CodexBar；Antigravity 由 TokenLedger 内置发现同用户 App/IDE/agy 进程，或以短生命周期 PTY 启动规范化绝对路径 `agy`，只请求 `127.0.0.1` 的三个额度/状态 RPC。Antigravity 的自签名证书放宽仅属于专用 loopback client，TUI 只排空不解析，进程结束时只回收 TokenLedger 自己启动的 child。可选 CodexBar 兜底固定为 Antigravity local/CLI 来源并拒绝 OAuth。所有路径逐 Provider 默认关闭，只持久化去身份的正规化窗口；Windows 无 CodexBar 时仍具完整内置主路径，真实 Windows 运行行为保留为独立平台验收。

### ADR-013 跨设备额度采用按 Provider 持久 latest-wins（2026-07-18）

本决策取代 v1 的整集合替换、24/25 小时 TTL 和“停用即远端清空”。云端按 `auth user + providerId + scope` 持久保存最后一个可用 envelope，直到账号或用户显式删除；普通上传缺少某个 Provider 不表达删除。冲突以窗口最大 `observedAt` 为主时钟，相等时以服务端 `receivedAt` 决胜，错误/鉴权失败/unsupported 不覆盖 LKG。桌面同步严格区分本机生产值与云端展示缓存，先 get 代际再只上传本机可用观测；桌面和 Android 对任意年龄的快照继续按原始观测时间显示 stale。关闭某台设备、退出登录或撤销本机 Provider 只停止该设备，不删除其他设备可读的云端历史。单 Provider 删除使用 generation 墓碑，全局删除提升 epoch 并推进现有 Provider generation，阻止迟到旧写；旧 v1 读保持可用，旧 replace 降级为 additive latest-wins。

### ADR-014 Android 桌面小组件采用类型显式、每实例主题的 Ledger Rings 家族（2026-07-19）

Android 桌面小组件不再由 Launcher 尺寸暗中决定内容，而由每实例持久配置选择环形额度、单行消耗或组合卡；尺寸只负责响应式编排和诚实降级。百分比统一表达可用额度，复用 Android Provider 稳定排序与来源观测时效；大数使用 `987.6M` 与人民币千分位固定轨道。主题按实例选择跟随系统、明亮或黑暗，不改变应用外观。Glance 继续负责原生文本、语义和点击区；仅环形进度以无动画位图绘制，以兼容 RemoteViews 的确定性静态更新和低功耗要求。

### ADR-015 公开 RC 采用安全迁移、身份隔离与分阶段证据门槛（2026-07-28）

系统级副作用必须先取得可持久验证的用户授权：新安装的桌面/锁屏/动态壁纸全部关闭；旧设置缺少授权版本且仍启用壁纸时，调度器暂停执行，直到用户明确保留或关闭。Android Debug 使用独立 applicationId，生产包保持稳定身份与正式证书；旧 Debug 包不能冒充可升级的正式发行。

公开 RC 分为内部功能候选、同证书私有签名演练与公开签名 RC。代码、自动化和无签名压缩构建可以在缺少外部凭据时完成，但 Developer ID/公证、Authenticode、Android 正式 keystore、生产 Supabase、目标设备与屏幕阅读器证据是公开发布硬门槛。每个正式产物必须绑定唯一版本、源码 SHA、构建时间、SHA-256、签名身份、迁移头和验证证据；缺一项不得把内部包表述为公开 RC。

### ADR-016 本机项目维度采用显式授权、只存项目名与本机专属存储（2026-09-24）

用户决定 D5②：项目/工作目录维度默认关闭，由用户主动开启；不同步云端；设置中说明读取与不读取的内容。2026-09-24 用户逐条确认：只存末级目录名，不存哈希（D5② 原允许二选一），仓库自身的文件夹名即视为末级名称；暂不做 git 探测；设置入口放在「数据与帮助」；首版提供「隐藏项目名」显示开关；接受额外读取三类扫描器不打开的元数据文件（Gemini CLI 的 `.project_root`、Kimi Code 与 Kimi Desktop 的会话与工作区元数据、DeepSeek GUI 的 `metadata.jsonl`），并在设置中如实列出。

存储采用可读的项目名，不采用加盐哈希：项目名取工作目录末级名称；worktree 目录与来源记录的仓库根取仓库文件夹名。理由有三点：这个维度要回答可读的问题；数据不出本机；本机数据库本来就为增量扫描保存了来源文件路径，哈希的额外隐私收益有限。同名文件夹合并作为已知限制向用户说明。主目录（及其上级、与账户名同名的文件夹）、磁盘根目录、临时目录与托管目录只记固定分组，避免用户名与随机名入库。

开关、授权版本与代次存在本机库的状态行，不放 `AppSettings`：开启、关闭与清除要在同一个数据库事务里原子完成，通用设置保存也不能误开这个开关。授权版本沿用壁纸授权代次模式：读取范围扩大时提升版本，旧授权暂停采集。项目索引与扫描器解耦，不改 `token_logs` 与去重键；开启后按会话只读文件头或单个字段回填历史，此后每次启动只做增量维护；关闭时清除项目行并截断 WAL，截断受阻时记下不含名称的待办标记，下一次扫描重试。git 探测由单一常量控制，用户决定关闭，开启须另行决定并提升授权版本。项目数据只进入本机行为契约 v1.2 的项目字段（T10.182 已写入 `docs/contracts/behavior-analysis-local-v1.md`，行为聚合只读索引），不进入 Stats v2、云同步、Android、分享与导出。

### ADR-017 模型供应商接入以本地网关为主路径（2026-10-03）

决策 U-87、U-88：桌面端以「供应商」「Agent」两个对象组织模型配置。供应商 key 由 TokenLedger 存入系统凭据库并只在本进程内读取；本地网关监听 `127.0.0.1`、使用本地随机 token，向外转发请求并承担协议转换；Agent 配置只写指向网关的一张 provider 表与模型选择键，不再让 Agent 直接持有供应商 key。T10.256 系列（PR #36）中的 Codex 直连、`credential-helper` 取 key 与一次性网络授权链路冻结，配置文件局部编辑、安装探测与工作区导航拆件回收。远端地址策略：域名解析全部落在 `198.18.0.0/15`（代理 fake-ip）时，若为 HTTPS 且主机名与证书校验通过则放行并提示，其余保留段与内网仍拒绝。网关逐请求用量进入看板前，必须先在 `dashboard-stats-v2` 定义与本地日志扫描的去重规则，有效 Token 口径不变。不吸纳 magpie 的订阅登录共享与消费者额度查询（ADR-004）。用户决定 U-89～U-92（2026-10-04）：桌面「总览看板」「行为分析」合并为「用量」入口（子标签概览、记录、会话），主数字仍为有效 Token；网关增加路由组（多供应商模型合成一个虚拟模型，故障切换、会话保持与确定性规则，不做调用模型的意图分类）；侧栏把 Agent、供应商、网关、路由提升为一级入口。上述以 T10.262 原型为准，实现前改写 DESIGN 与 analytics-ia 方案。用户决定 U-93～U-95（2026-10-04）：T10.262 原型 v2 定为实现依据；Agent 接入范围按已确认的支持列表分批交付（需订阅登录或私有接口的排除）；网关记录与日志扫描重复时以网关记录为准，规则写入 `dashboard-stats-v2` 后才并入看板。用户决定 U-96～U-99（2026-10-04）：网关记录的去重窗口与跨设备同步先做独立调研，确认 Supabase 可承载后开迁移，让云端与 Android 口径一致；Agent 配置写入保留原 JSON 键顺序；网关页提供「复制本地 token」（只在主窗口、用户点击时返回）；设置页旧「API 配置」分区下线，由模型接入四页取代。用户决定 U-100（2026-10-04）：用量页子标签「会话」改名「行为分析」，侧栏「用量」下展开概览、记录、行为分析三个二级入口。用户决定 U-103（2026-10-04）：设置页提供壁纸效果预览（缩略图），不应用到桌面。用户决定 U-104（2026-10-04）：设置页同样遵循少文字、多留白（U-102），说明性长文默认折叠，操作按性质分组。用户决定 U-112（2026-10-04）：模型接入（供应商、Agent、网关、路由）是可选功能，设置页提供总开关；关闭时侧栏不显示这四个入口、网关不监听，避免与同类工具争用 Agent 配置。新安装默认关闭，已启用过供应商或已有 Agent 指向网关的老用户升级后保持开启；关闭前若仍有 Agent 指向网关，提示并可一键恢复其原配置。

### ADR-018 额度来源：受控写入 Claude 配置，接入用户自有 API key 的供应商额度（2026-10-04）

依据 T10.280 调研（`docs/design/quota-source-compliance.md`）与用户决定 U-105～U-111。本决策扩展 ADR-009～012，并取代其中「TokenLedger 不改写 `~/.claude/settings.json`」的对外承诺；ADR-004 的禁止项不变。

- U-105（D1）：设置页可一键写入 Claude Code 用户级 `settings.json`，只改顶层 `statusLine` 一项，保留其他键与原键顺序。写入前展示改动预览并需确认；写入带版本检查、原子替换、备份清单，并支持一键恢复。写入方式复用网关 Agent 配置写入器（`src-tauri/src/gateway/agent_config.rs`）的约束。
- U-106（D2）：用户原有的 status line 必须保留。原命令保存在 TokenLedger 本机配置中，不再留在 Claude 配置里；`--claude-statusline` 先按既有白名单记录额度快照，再把同一份 stdin 交给原命令执行，并把原命令的 stdout 原样输出。原命令失败或超时，不影响额度记录，也不回显 stderr。恢复时把原命令写回。
- U-107（D3）：两个 Claude 开关合并为一个「读取 Claude 额度」开关。来源按 `quota-provider-v1` §3 的既有仲裁顺序自动选择；实验性的内置 `/usage` PTY 和 CodexBar 兜底放进「高级」，默认不参与。
- U-108（D4）：新增供应商官方余额来源（Moonshot、DeepSeek、OpenRouter、SiliconFlow、用户自配的中转余额地址）。`quota-provider-v1` 增加货币单位，按契约 §7 的门控规则保证旧桌面、旧云端与旧 Android 不会收到新单位。
- U-109（D5）：接入智谱 GLM、MiniMax、Kimi Code 的套餐用量，标为实验性、默认关闭，开启前展示风险提示；凭据只存系统钥匙串。
- U-110（D6）：只做本机额度告警（REQ-QUOTA-07），不做额度历史曲线。
- U-111（D7）：铁律不变。不复用订阅登录的 OAuth/会话凭据，不调用消费者产品的私有接口。

**ADR-004 的界线（U-109 与 U-111 的分界）**：允许的是**用户自己的 API key 发往该供应商自家的固定域名**（或用户为中转站显式配置的同源余额地址）。即便该接口没有公开文档，也只能标为 `experimental`，并且默认关闭、逐来源告知风险。禁止的是：复用 ChatGPT/Codex、Claude、Copilot、Cursor、Gemini/Antigravity 等消费者产品的订阅登录凭据（OAuth Token、refresh token、钥匙串条目、浏览器 Cookie），调用 `chatgpt.com/backend-api`、`copilot_internal`、`v1internal` 等消费者私有端点，以及任何「预热窗口」「花费重置次数」之类的代用户自动消费。API key 只能发往其所属供应商的允许列表域名，不得跨供应商、跨中转站转发。

## 8. 违反即返工

- 改了统计语义但没有更新契约和四端消费者。
- 在客户端、APK、日志或 Git 中写入 service role、API secret、访问 Cookie。
- 未经逐来源显式授权直接使用消费者私有来源，或把不可验证结果伪装成精确额度。
- 在共享脏工作区覆盖他人文件、泛化暂存或破坏性清理。
- 并行写同一仓库却未登记 Active Claim 就开工，或把脏工作区/未校验 bundle 交给另一台机器继续。
- 没有真实平台证据却宣称 macOS/Windows/Android 已验收。
- 口径冲突仍开单或实现；把云端可跑与本机专属验收捆成一次成败；该等用户拍板时通宵空转或靠猜实现。
- 未获用户当次点名就另开流水线外的云端编码会话，或已有开放 PR 仍另开第二套实现。
- 构建脚本隐式升版，或只因一个小提交机械创建新版本。
